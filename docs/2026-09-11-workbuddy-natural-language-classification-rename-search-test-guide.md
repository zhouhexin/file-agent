# WorkBuddy 自然语言测试手册：文件分类、重命名与检索问答

日期：2026-09-11
适用范围：使用 WorkBuddy 通过 File Agent MCP 测试文件导入自动分类、已入库文件检索/问答、显式重命名和分类落位。
目标读者：不需要手写 MCP 参数的新手测试人员。

> 本文测试的是“用户自然说一句话后，WorkBuddy 能否选择 File Agent 连接器并完成受控操作”。
> 不要求、也不建议在聊天里手写 `document_id`、`working_copy_id`、路径、JSON、工具名或确认参数。

## 1. 本次能测什么，不能测什么

### 1.1 可以通过自然语言测试的能力

| 测试目标 | 预期连接器能力 | 是否会改动文件 |
|---|---|---:|
| 导入一个已授权目录并自动分类 | `file_batch_ingest` | 会创建受管工作副本、分类、索引；原件不改动 |
| 导入本轮会话附件并自动分类 | `workbuddy_attachment_ingest` | 同上 |
| 查找已入库文件 | `file_search` | 否 |
| 读取/总结已找到的文件 | `file_read` | 否 |
| 根据已入库文件回答问题并给依据 | `evidence_answer` | 仅产生受控问答/审计记录，不改文件 |
| 修改已入库文件的主分类或受管落位 | `file_set_primary_category` / `file_move` | 会改工作副本的分类/位置；原件不改动 |
| 明确重命名已入库文件 | `file_rename` + OperationPlan 确认 | 会改工作副本名称；原件不改动 |

### 1.2 不属于本次自然语言测试承诺的能力

- 不把 WorkBuddy 上传附件自动映射到 File Agent，除非宿主实际已把本轮附件交给 `workbuddy_attachment_ingest`。
- 不支持把任意电脑路径、USB 盘路径或聊天中猜测的目录交给后端读取。
- 不支持绕过确认直接重命名、删除、覆盖或导出文件。
- 不支持凭文件名就认定文件内容、分类或事实结论；正文解析/索引完成前，检索和问答可能提示等待。
- 不支持把模型回答当作证据；问答结果应有文件名、页码、工作表或原文片段等依据。

## 2. 测试前准备

### 2.1 服务和 WorkBuddy

开始前确认：

1. File Agent API、数据库和处理 worker 已启动。
2. WorkBuddy 已重连 File Agent MCP，工具列表至少能看到 `file_batch_ingest`、`file_search`、`file_read`、`evidence_answer`、`file_rename`。
3. MCP 运行环境已配置 `FILE_AGENT_LOCAL_ROOTS`。示例：逻辑根 `local-materials` 对应一个实际测试目录。
4. 本次使用一个全新的 WorkBuddy 对话；整个测试过程尽量不要切换对话。
5. 不要使用生产敏感文件。测试文件中不要放身份证号、账号、真实学生信息或密码。

### 2.2 推荐测试目录和文件

在已配置的逻辑根下创建一个新测试目录，例如：

```text
WB自然语言测试/
├─ 2025年奖学金申请通知.txt
├─ 2025年奖学金申请表.docx
├─ 2025年活动经费明细.xlsx
├─ 2025年迎新工作总结.pdf
├─ 说明不完整材料.txt
└─ 同名目录/
   └─ 2025年奖学金申请通知.txt
```

建议内容：

| 文件 | 最少应包含的正文 | 用途 |
|---|---|---|
| `2025年奖学金申请通知.txt` | “奖学金”“申请条件”“2025年”“提交截止日期” | 分类、检索、问答、重复测试 |
| `2025年奖学金申请表.docx` | “申请人”“学院”“国家励志奖学金” | Word 解析、分类、重命名 |
| `2025年活动经费明细.xlsx` | 工作表含“项目、金额、日期、负责人” | Excel 解析、问答 |
| `2025年迎新工作总结.pdf` | “迎新”“工作总结”“参与人数” | PDF 解析、检索 |
| `说明不完整材料.txt` | 仅少量无业务含义文本 | 验证会落入“其他”或需要人工判断，而不是编造分类 |

记录每个文件的原始名称。后续检查时，原始文件应仍在原目录且名称不变。

### 2.3 自然语言测试规则

1. 每一轮只发一条清晰、完整的任务句子，等待回复完成再进行下一轮。
2. 首轮导入时可写目录名称，但不要写 `source_root_ref`、绝对路径、JSON 或工具参数。
3. 如果 WorkBuddy 展示“正在使用 File Agent”或工具调用记录，截图保存；这证明它确实选择了连接器。
4. 如果 WorkBuddy 追问目录、文件或确认范围，按实际情况回答，不要让它猜测。
5. 重命名和分类调整时，必须先让它找出目标文件；不要在第一句话要求“把所有文件随便改名”。

## 3. 测试一：自然语言导入并自动分类

### 3.1 测试话术

在新对话发送：

> 请读取并自动分类已授权测试目录“WB自然语言测试”中的全部文件。请保留原件，只整理工作副本，并逐个告诉我分类、命名和处理状态。

### 3.2 预期行为

1. WorkBuddy 应选择 File Agent，而不是只给出文字建议。
2. File Agent 应创建批量导入并依次处理文件；处理可能是异步的。
3. 回执应逐文件显示处理状态，而不是只显示“已完成 6 个文件”。
4. 每个已成功解析的文件应有分类、分类依据或提示、当前名称/命名结果，以及索引状态。
5. `说明不完整材料.txt` 不应被编造成高置信度业务类；合理结果是“其他”或明确需要人工判断。
6. 本地原始目录的文件名和文件内容不应变化。

### 3.3 需要记录

- WorkBuddy 是否显示调用 File Agent。
- 批次 ID、文件总数、成功/失败/等待确认数量。
- 每个文件的分类结果和异常原因。
- 是否出现重复文件确认；若出现，先不要随意决定，按第 7 节处理。

### 3.4 合格判定

以下全部满足才算通过：

- WorkBuddy 实际调用了连接器。
- 文件没有被漏掉或被静默失败。
- 已知内容的文件分类与内容大体一致。
- 原件未改名、未移动、未覆盖。
- 无法判断的文件没有伪造业务分类。

## 4. 测试二：自然语言检索文件

在导入完成后、保持同一个 WorkBuddy 对话，发送：

> 找出 2025 年奖学金申请相关的文件，分别说明文件名、文件类型和你找到它的依据。

### 4.1 预期行为

- WorkBuddy 应使用 File Agent 的只读检索，而不是把“奖学金”解释成重命名或移动操作。
- 结果应包含奖学金通知和申请表；不相关的经费明细不应作为主要结果。
- 如果存在歧义，系统可以提出澄清问题；这是正常的安全行为。
- 检索返回的稳定文件身份由系统保存，后续读取、问答、改名应基于该结果继续，不应让用户手写 ID。

### 4.2 追加检索话术

> 找出包含“负责人”和“金额”的 Excel 文件。

预期：主要命中 `2025年活动经费明细.xlsx`。

### 4.3 不合格情况

- 返回不存在的文件或编造文件名。
- 搜索请求触发改名、移动、删除等写操作。
- 把文件名相近但正文无关的材料当作确定匹配，且无提示。

## 5. 测试三：自然语言读取与证据问答

先发送：

> 请阅读刚才找到的奖学金申请通知，告诉我申请截止日期和需要提交的材料；每项都说明来自哪个文件以及对应原文依据。

再发送：

> 根据已入库文件回答：活动经费明细中有哪些项目，金额分别是多少？请按工作表或单元格依据回答。

### 5.1 预期行为

- WorkBuddy 应使用 File Agent 的 `file_read` 或 `evidence_answer` 能力。
- 答案应来源于已入库正文；不应仅根据文件名猜测。
- 找不到截止日期、材料或金额时，应明确说“未找到”，而不是编造。
- 对 PDF/Word 应显示页码或可定位片段；对 Excel 应显示工作表名和相关内容。

### 5.2 合格判定

- 问答结论能在测试文件正文中核对到。
- 引用指向正确文件。
- 如果问题跨文件，回答会区分不同来源，而不是混在一起。

## 6. 测试四：自然语言调整分类或移动

先找到目标文件，再在同一对话发送：

> 把刚才找到的“2025年奖学金申请通知”主分类调整为奖助学金相关材料；只调整这一个文件，并告诉我最终分类和落位状态。

如果系统要求你选择候选分类，选择与“奖助学金”对应的真实选项，不要输入自由分类路径。

### 6.1 预期行为

- WorkBuddy 应先复用已搜索到的受控文件身份，再调用分类落位能力。
- 如果文件、分类目标或当前版本不明确，应要求澄清，而不是猜测。
- 成功后应返回操作状态；必要时可继续询问“现在这个分类调整完成了吗？”
- 该操作只影响工作副本的分类和受管位置，不改原始文件。

### 6.2 反向测试话术

> 把所有文件都移动到“其他”。

预期：系统应追问范围或拒绝过宽、含糊的目标，而不是不加区分地批量移动。

## 7. 测试五：自然语言重命名与确认

先用自然语言找文件：

> 找到“2025年奖学金申请表.docx”。

确认搜索结果正确后发送：

> 把刚才找到的“2025年奖学金申请表.docx”重命名为“2025年国家励志奖学金申请表.docx”。先只生成计划和风险说明，不要执行。

### 7.1 第一阶段预期

- 应生成重命名计划，而不是立刻改名。
- 回执应显示原名称、目标名称、文件范围、冲突/风险检查结果和计划状态。
- 如果名称冲突、文件已变化或找到了多个同名文件，应要求用户选择或修正，不得擅自选一个。
- 原件和当前工作副本此时都不应变化。

### 7.2 明确确认话术

只有在计划中原名、目标名和数量都正确时，发送：

> 我确认执行刚才这个重命名计划，只重命名计划中列出的这一个文件。

### 7.3 第二阶段预期

- WorkBuddy 应使用既有确认链路，而不是重新创造一条直接写文件的路径。
- 执行完成后应返回最终状态和当前文件名。
- 再发送：

> 再查找“2025年国家励志奖学金申请表”。

预期：应能找到新名称；旧名称作为导入快照/审计信息可能仍会出现在历史字段中，但当前检索应以新名称为准。

### 7.4 必须判为失败的情况

- 未经用户明确确认就完成了独立重命名。
- 重命名影响原件。
- 计划显示一个文件，实际改了多个文件。
- 文件冲突或版本变化后仍强行执行。

## 8. 重复文件出现时的测试处理

如果导入时出现重复候选，发送：

> 请告诉我这两个重复候选的文件名、重复原因，以及我应该如何查看对比后再决定。

如返回浏览器链接，打开链接，在 File Agent 登录后分别预览或下载两侧文件。页面只用于查看，不负责决定。

查看后回到 WorkBuddy，再自然说：

> 我已经查看过重复文件，请保留已有文件，不再导入这份重复文件。

或：

> 我已经查看过重复文件，两份都需要保留，请继续导入这份文件。

预期：WorkBuddy 应基于当前 review/candidate 修订提交既有重复决定；如果候选已变化或过期，应要求重新查看，而不能把旧决定套到新文件。

## 9. 自然语言未调用连接器时如何判断

这不一定代表后端功能失败。按下面顺序判断：

1. 查看 WorkBuddy 是否显示 File Agent 工具调用；没有调用时，先记录原始话术和回复。
2. 把话术改得更具体，例如把“整理一下”改为“读取并自动分类已授权测试目录中的全部文件”。
3. 确认 WorkBuddy 当前对话已启用 File Agent 连接器，并重连 MCP 后再试。
4. 确认目录已经在 `FILE_AGENT_LOCAL_ROOTS` 中授权；自然语言不能替代这个部署配置。
5. 如果自然语言已经明确表达文件任务、范围和期望结果，WorkBuddy 仍只文字回答且没有调用连接器，则记录为“宿主工具选择/提示词问题”，不要通过手写路径或伪造参数绕过。

## 11. 最小通过标准

本轮自然语言验收通过，至少应满足：

1. 导入分类、检索问答、分类调整和重命名计划四类任务都至少有一次实际 File Agent 工具调用。
2. 检索和问答结果能用测试文件正文复核。
3. 重命名在确认前不执行，确认后仅影响指定工作副本。
4. 原始测试文件从开始到结束都未被修改。
5. 对不清晰范围、无证据内容、重复候选变化和名称冲突，系统会追问或拒绝，而不是猜测执行。

## 12. 测试完成后的清理

- 保留测试记录、批次 ID、计划 ID 和脱敏截图，便于排查。
- 不要为了清理测试结果直接删除服务器文件或数据库记录。
- 如果需要清理受管工作副本，应另行创建并确认受控操作计划；原始测试目录可由测试人员按本地文件管理规则自行保留或移走。
