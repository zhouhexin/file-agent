# WorkBuddy 职称汇总表 B–AA 同轮识别与低成本执行方案

日期：2026-09-30

状态：方案，尚未开发。首期适用于上传目标 Excel 与扫描 PDF 的首次填表，以及向已发布的 `申报人员业绩汇总-教学科研型教授.xlsx` 按文件名追加新 PDF 人员行。Word 来源须在能提供等价原始印章图像、位置和审批范围后单独扩展，纯 Word 文字不能充当盖章证据。现有 A–I 定向技能继续服务用户**明确只要求 A–I** 的任务；完整填表任务使用新的 B–AA 同轮契约，不能先运行 A–I 技能发布一版，再补 J–AA。本轮用户明确要求按印章判断业务列，因此须同时遵守 [`file-agent-sealed-item-extraction`](../integrations/workbuddy/file-agent-plugin/skills/file-agent-sealed-item-extraction/SKILL.md) 及其 [A–AA 列来源路由](../integrations/workbuddy/file-agent-plugin/skills/file-agent-sealed-item-extraction/references/column-source-map.md)。

## 1. 目标与样本事实

对每份新 PDF，在**同一次任务中识别 B–I 身份任职信息和 J–AA 业绩、意见、备注**，由模板规则处理 A 列序号，形成一条完整的人员行。首次上传目标 Excel 时以上传表为准；只上传来源 PDF 并指定已发布的完整 `.xlsx` 文件名时，向该表追加一行。多份来源在同轮分别生成一行，整轮只发布一次新 `DocumentVersion`，并验证可见同名文件与不可变版本 SHA 一致。“同时填写”表示同轮完成所有列的**一次识别、判断和写入**；OCR 不准的格子直接标记待核对并继续，不为追求每格准确而重复读取 PDF。不适用、无来源内容和 OCR 未识别须分别标注，不能凭空填值。

对历史上已仅填写 A–I 的人员行，若用户**明确要求修补同一记录**，可用稳定 `record_id` 走同行更正兼容路径，保留人工回传的非空值并报告冲突；这不是新来源的默认执行方式，也不能成为完整填表的前置步骤。

当前模板的 J–AA 物理列为：J 辅导员/班主任等经历，K 国际合作和公共服务，L 考核优秀，M 师德评价，N–P 课程、指导和教学工作量，Q–S 教育教学成果，T–Y 论文、项目、经费、转化、奖励和专利，Z 资格审查意见，AA 备注。Q–Y 的标题包含复杂资格条件，不能把 OCR 到一个关键词等同于满足整列条件。

本轮“根据印章判断”按既有专用 Skill 执行：B–I 与 J–AA **同轮读取和写入**；B–I 是有原文证据即可填写的身份列，不借此放宽 J–Y；J/K/M/O/P 保留专用模板的逐片段无章事实例外。若用户明确改为“所有列一律只写盖章属实内容”，则该例外关闭，不能写 `SOURCE_ONLY`。

`2026职称评审表-教授-石程.pdf` 是 25 页纯扫描文件，所有页面直接文本提取长度均为 0。已验证样本的 B–I 候选区域位于物理第 1、3 页；已有 Skill 的来源路由把 L 列人事考核方章指向物理第 25 页，把其余 J–Y 分散指向第 5–24 页的相关栏目及可能的续页。页码仅是**该样本的候选索引**，不是其他 PDF 的固定页码、盖章已通过的证明或可直接提交的证据。完整 B–AA 任务可能涉及大部分页面，无法承诺保持 A–I 两页 OCR 的成本。

## 2. 推荐执行链

```text
本轮上传的 Excel 或已发布同名 Excel + 本轮 PDF 来源
→ 冻结目标模板、来源版本、全部 B–AA 列和每份来源的行分配
→ 复用同一 PDF 已保存证据并识别版式；生成 B–I、J–AA 区域并集
→ 同轮 OCR 身份区、业绩项目区及对应印章/审批区，每块只读取一次
→ 对每份来源记录 B–I 八列识别结果或待核对状态，并按来源版本定位人员行
→ 服务端逐项核对印章、声明、审批覆盖范围和项目原文
→ 对完整列及跨列条件使用版本化规则计算；疑难项才交模型复核
→ 服务端组装每份来源的 A–AA 整行并校验写入边界
→ 所有来源准备完成后一次发布新版本并核对可见文件
```

### 2.1 先冻结目标与来源，避免重复工作

- 首次上传目标时冻结本轮上传 Excel 的 `document_id/version_id/extraction_run_id`、真实 sheet 和布局，转换 `.xls` 后仍以本轮上传表为准；后续只上传来源时按用户指定的完整 `.xlsx` 文件名解析唯一活动目标，冻结 dataset、WorkingCopy、DocumentVersion、revision 和当前行范围。每份本轮 PDF 归档为不可变来源版本并记录 SHA；若同一版本已有正式提取结果直接复用，不重复上传或识别。
- 先核对目标可见文件 SHA 与当前版本记录，再分配新人员行。新增任务不按姓名回查历史行，不覆盖已有人员；重复来源按稳定来源 ID/版本与既有记录关系校验，避免重复追加。历史同行更正才读取 `record_id` 与现有单元格作为冲突基线。**人工写入的值不构成 PDF 原文或盖章证据**；已有可复用证据仍须绑定同一来源版本。
- 模板 A–AA 的真实多层标题、合并区和数据区按目标版本校验一次。长标题的资格规则编译为受版本约束的结构化规则快照；后续每个人只传列键和规则 ID，避免每次把长标题送入模型。

### 2.2 两级定位与按需 OCR

- 已验证的 25 页/22 页版式使用**版本化页图**：每个栏目配置候选页、表格区域、预期标题和适用列。服务端先做容器和版式校验；低分辨率页眉/表格线指纹仅用于定位，不当作内容证据。未知版式先对页眉窄条或缩略索引做一次受控定位；无法确定时返回待定位，不静默 OCR 全篇。
- 对全部 B–AA 列一次性求候选区域并集：B–I 覆盖身份任职原文，J–AA 覆盖适用的**项目原文、审批声明、真实印章区域及必要续页**，不能只裁表格正文。先检查对应审批区域是否有可核验印章和声明：Q–Y 缺任一项则停止该栏资格通过判定，但仍须读取足以逐项列出排除/待复核事项的原文；J、K、M、O、P 可继续读取可定位的无章来源事实。同一页服务多个列的图像只渲染和 OCR 一次；空白或无关区域可跳过，但不能把“未读”推断成“无业绩”或“无章”。B–I 可先在内存中用于人员绑定，不能先单独写表或发布。
- PDF 有可靠原生文字层时可先按页/区域取项目文字，但**印章图形仍须用原页图像核验**。本样本没有文字层，须由 WorkBuddy 已安装、授权且能返回真实印章信号和页内坐标的 Provider 处理服务器裁剪出的区域图像；仅有普通文字 OCR 时不能生成 `SEALED_CONFIRMED`。按版式为普通表格和章图预选一次合适的裁剪范围与分辨率，识别不清即标记，不因低置信度再升级分辨率或重调 OCR。区域裁剪可使用 PyMuPDF `Page.get_pixmap(clip=...)`；其 `get_textpage_ocr()` 本身不提供区域裁剪。[PyMuPDF 页面 API](https://pymupdf.readthedocs.io/en/latest/page.html)、[局部渲染示例](https://pymupdf.readthedocs.io/en/latest/recipes-images.html)。
- 宿主若只有整篇识别接口，则同一固定来源最多识别一次并缓存全部页面，再只把需要的区段送入后续判断；回执必须如实说明本次没有节省 OCR 页数。不能为了宣称低费用而跳过必要的印章/续页，也不能把纯文字结果当印章图像证据。
- OCR/印章检测缓存键至少包含来源版本 SHA、版式版本、页码、区域坐标、图像 SHA、Provider 名称/版本和识别参数；印章区块的 bbox、页号、可辨识文字和栏目绑定另行留痕。任务中断按原租约恢复；**成功、低置信度和未识别的区域结果都作为本轮终态保存**，不重新读取同一区域。缓存只代表对应局部内容，不冒充 PDF 全文，也不把旧 OCR 文字自动升级为印章证据。

#### 已读内容复用账本

启动新 OCR 前，服务端按不可变来源 `DocumentVersion` 和文件 SHA 汇总该 PDF 的所有正式提取结果，包括历史 A–I 定向运行（若存在）、WorkBuddy 已有页面 OCR、整页 OCR、局部 OCR、印章检测及已核验审批关系；这些只作为**读取缓存**，不要求先有 A–I 发布版本。先调用 `structured_dataset_source(mode="INDEX", content_origin="WORKBUDDY")` 建立候选页索引；仅对确实需要的 `unit_orders` 批量调用一次 `FULL`，续页缺失时才补第二次。不能将 25 页全文反复送进模型上下文。已有第 1、3 页文字可用于 B–I 身份字段，但其裁剪范围之外的 J–AA 区域仍属未读；同轮新识别的第 1、3 页结果也立即供全列任务复用。

账本以“来源版本、物理页、原始 bbox、证据类型”记录覆盖状态：`TEXT`（项目/表格 OCR 文字）、`APPROVAL_TEXT`（审批声明）、`SEAL_IMAGE`（真实章图和 bbox）、`BINDING`（声明覆盖的项目范围），并记录 `CONFIDENT / OCR_UNCERTAIN / OCR_UNREADABLE`。同一区域的整页结果可覆盖局部结果；局部结果只能覆盖其真实裁剪范围。复用时仍校验位置、人员与栏目归属、声明及印章的同栏绑定；已有文字不能代替章图，已有章图也不能代替声明。对同一不可变 PDF 版本，**低置信度或未识别也命中缓存**，直接沿用待核对状态；只有从未处理的必要区域才发起一次识别，不因 Provider 升级或旧结果不清而自动重读。

持久化缓存分两层：图像/识别层按来源 SHA、页码、bbox、裁剪图 SHA、预处理参数、Provider 和模型版本去重；结构化事实层按来源版本、OCR 证据 ID、栏目路由版本、印章绑定规则版本和模板资格规则版本计算。规则更新只重算受影响的事实和资格，不重新 OCR 未变化的图像；换 PDF 版本或裁剪范围则不能误命中旧缓存。每个区域的**一次处理结果**立即落库并记录幂等任务键；任务恢复与多人并发不得对同一区域重复收费。Provider 调用本身失败时保留失败状态和错误码，不做自动付费重试，由回执说明未处理范围。

### 2.3 印章属实、来源事实和资格判定三层分离

每个拟认定为“盖章属实”的项目都必须形成不可拆分的证据链：**真实印章图形及 PDF 页内位置 → 同一可解释审批区域的可辨识声明 → 声明能唯一绑定的项目/栏目范围 → 该项目完整原文、页号和位置**。红色图形、OCR 出“章”字、本人承诺、签字、编号前勾选或同页其他栏印章都不能单独证明属实。签字不是必需条件。

声明到项目的绑定顺序沿用旧 Skill：明确项号/范围 → 唯一完整项目或整栏 `WHOLE_SECTION` → 编号前可定位勾选 → 同栏跨页行序 → 受限 `LAST_ITEM_FALLBACK`。每一步都要求同栏、同审批区域和可确定阅读顺序；不能唯一绑定则进入 `review_items`，不把整页内容默认归入印章。跨页续表必须同时读取起始栏和审批续页。每个项目分别标 `SEALED_CONFIRMED`、允许的 `SOURCE_ONLY` 或 `UNRESOLVED`；同一格不同片段可有不同状态。

| 列 | 来源与印章规则 | Excel 展示和资格规则 |
| --- | --- | --- |
| A | 由目标模板和既有序号确定，不取 PDF 文字 | 首次保留模板预置序号；后续新行按前一序号续排，不由模型生成 |
| B–I | 与业绩区在同轮各读取一次，绑定本份 PDF 版本和页/区域；清晰结果保存 OCR 引文，不清晰结果保存 OCR 原样文本、候选值及低置信度标记；按原 Skill 不要求盖章 | 清晰值正常写入；有候选但不确定时写 `〔OCR 待核对：候选值〕`，完全无法识别时写 `〔OCR 未识别，待核对〕`。这些格不阻止同轮发布，且不得从文件名、旧表或其他人员补猜 |
| J、K、M、O、P | 逐片段取事实并找本栏对应章和审批声明。仅本专用模板这些列允许清楚、可定位且属于同一申报人的无章原文进入 `SOURCE_ONLY` | 无章片段由服务端逐段附 `〔PDF 原文，未见对应印章〕`；有章片段按实际范围核验。P 的工作量与教学效果、O 的不同指导事实分别判断，不借相邻章。来源事实不等于整列资格通过 |
| L | 仅从“任现职以来的考核情况”取经人事部门真实方形/长方形印章核验的“年度考核优秀”年份，参考样本候选物理第 25 页 | 来源运行必须有同页 `SEAL` 区块及真实 bbox；`approval_kind=HR_ANNUAL_EXCELLENCE`，声明与印章引用同一段章内优秀结论。手写“合格”、空白推荐意见或无章年份不写 |
| N | “系统主讲两门课”等属于派生条件，课程表事实和适用审批范围分别取证 | 不用无章 `SOURCE_ONLY` 冒充通过；完整条件及依赖事实核验后才给资格标记，否则说明未确定 |
| Q–Y | 每个业务项目必须在本栏可验证盖章及审批声明的覆盖范围内；无章、范围外、仅本人承诺和含糊项目进入排除/复核，不写业务事实 | 已审批事实即使不满足资格也可写具体内容，但不加 `√`；数量、等级、排名、到账金额等再按完整标题计算。Q–S 的“3 选 1”和 T–Y 的跨列必选/任选条件必须单独核验，当前逐列 evaluator 无法表达的组合保持未确定，不强行加勾 |
| Z、AA | Z 须有与资格审查意见**本栏对应**的独立正式原文和审批证据；第 25 页系所推荐意见不等同 Z。AA 仅收明确授权的备注 | 不从 L 或 Q–Y 的章推断 Z 已通过；缺证据则保留空白。AA 不擅自生成说明 |

模型只接收一次 OCR 得到的相关短片段，用于栏目归属、字形候选和证据匹配；普通数字汇总、日期范围、排名、数量阈值由确定性代码计算。模型不能为了消除不确定性要求重新 OCR。每条事实分别保存源版本、物理页、OCR 字符范围、项目 bbox、声明和印章 bbox、绑定方法及 Provider；`raw_text` 保留 OCR 原样，置信度与展示标记单独保存。只有完整标题条件成立、依赖事实清晰且均在合法审批范围内，服务端才在整个人员数据格末尾加一次 `√`；不确定的候选文字、印章或声明不参与资格计算，也不生成 `SEALED_CONFIRMED`。

默认 `DIRECT_SAVE` 在同一整行中写入清晰的 B–I 值、J–AA 的 `verified_items` 与允许的 J/K/M/O/P `source_fact_items`，同时把 OCR 不清的候选以**明确的待核对展示文字**写入对应格，并在回执逐格列出页/区域、原始 OCR 文本及不确定原因。J–AA 的待核对文字单独标为 `OCR_UNCERTAIN`，只是候选，不能算已盖章属实、不能进入数量/经费汇总，也不能加 `√`；完全无法识别时写 `〔OCR 未识别，待核对〕`。无章或审批范围不明但 OCR 清晰的项目仍按既有印章规则处理，不把它伪装成 OCR 问题。用户明确要求先复核才使用 `REVIEW_REQUIRED`。未读到、无匹配、无章、已读但不满足、审批范围不明和用户人工已填分别记录，不能混为“没有业绩”。

### 2.4 整行组装与一次发布

领取 OCR 前先探测服务端 `sealed-item-template-v1` 及其 `source_fact_column_range=J:P`、`source_only_fragments`、`hr_annual_excellence_seal_block` 能力。新定向契约还必须明确支持 B–I 证据、真实印章区域、声明、项目范围、`OCR_UNCERTAIN / OCR_UNREADABLE` 逐格状态与展示标记、整行追加和单次发布；缺任何必要能力则在 OCR 前停止，不花钱做无法保存的识别。新增独立的 `SCOPED_FULL_EXCEL_ROW` 任务契约，不能直接放宽现有固定 B–I、两块区域的 `workbuddy-scoped-pdf-v1`。新契约固定 `requested_columns=B:AA`、A 列序号规则、源版本、栏目及审批区域、Provider、目标版本和业务模式；B–I 记录清晰原文引文或 OCR 待核对候选，J–AA 分别记录 `SEALED_CONFIRMED / SOURCE_ONLY / OCR_UNCERTAIN / OCR_UNREADABLE / UNRESOLVED` 及资格 `VERIFIED / NOT_MET / UNRESOLVED`。待核对候选是**展示数据**，不得进入 `verified_items`、`source_fact_items` 或资格计算；服务端必须保留独立状态，不能让现有 Skill 将候选当成通过项。即使某列按证据规则留空，也须给出已读、无匹配、证据不足或不适用的明确状态；新来源默认不得把 J–AA 标成 `NOT_REQUESTED`。

复用已有 `StructuredDatasetTask`、来源运行/页面证据、`excel_writeback_checkout/apply/publish` 的整行追加边界和发布协调器，并扩展为同一来源运行内携带 B–I OCR 结果及 J–AA 的 `SEAL` 区块、声明和作用范围；不能把人工修订任务或 A–I 局部文字运行当成自动盖章证据。服务端在内部预览中逐列校验 B–I 的清晰值或待核对标记，逐片段校验 `approval.scope` 只覆盖本栏已确认事实，`source_only_fragments` 只对应 J/K/M/O/P 原文。每份 PDF 先组装 A–AA 单行，所有本轮来源均完成一次识别或明确标记后调用**一次** `apply` 和**一次** `publish`；不为 B–I 单独创建 Excel 版本。识别不清本身不阻止 `DIRECT_SAVE`；来源缺失、目标版本冲突、文件损坏或无法建立人员来源绑定仍须停止。写入前比较工作簿与冻结基线，只追加本轮人员行，保护原有人员、表头、公式、样式、合并区和人工补充值。发布后校验最新隐藏版本、数据库当前版本及同名可见文件三方 SHA。历史 A–I 行的明确更正请求才用 `excel_writeback_correction_checkout/apply/publish`，并固定 `record_id`。预计可沿用现有 JSON 审计列和版本表；实施前仍需核对唯一约束及来源运行关联，若不足则补迁移，不以缺审计换速度。

## 3. 成本和速度控制

### 3.1 每次只购买缺失证据

1. **先查缓存，再估预算，再调用 Provider**：完成目标能力探测、来源/目标版本冻结、整行列范围、版式匹配和上述复用账本后，才计算缺口。实际 OCR 队列只包含 B–I 身份区与 J–AA 项目区、审批声明区、印章区、续页中尚无可用证据的区域。已有 Excel 值不算证据。
2. **同页同区严格一次**：按区域并集去重，而非按列发起 OCR；同一裁剪图只做一次识别，低置信度、错字或无法识别都直接记为 `OCR_UNCERTAIN / OCR_UNREADABLE` 并显示待核对标记，**不放大重试、不换 Provider 重读、不重复传给模型猜字**。仅有整篇识别能力的 Provider 对同一不可变来源最多发起一次整篇 OCR，随后复用页面结果；回执明确实际计费页数。
3. **先读审批，仍保留项目清单**：Q–Y 优先核验本栏及续页的真实章图和声明；无章或范围不明时跳过该栏资格模型推理，但仍读取足以列出排除/待复核项目的原文。J/K/M/O/P 继续按 Skill 的无章来源事实例外处理，L 必须查人事方章。不得用成本理由缩小印章或声明的必要裁剪范围。
4. **计算优先于模型**：同一 PDF 的 OCR 文本只解析一次，同时建立 B–I 身份字段和可跨 J–AA 列复用的课程、项目、论文、奖励等事实索引；同页重叠区域不因不同列重复渲染或付费识别。规则树处理数量、年份、排名、经费及跨列资格；模型只接收无法用确定性规则解决的短候选，按栏目批量处理，不逐行逐列重复输入 PDF 全文。已验证结构化事实可在目标表规则更新时重算，不重复 OCR。

### 3.2 强制预算门禁与断点续跑

每轮配置并记录 `max_paid_ocr_regions`、`max_ocr_pixels`、`max_model_calls`、`max_model_input_tokens`、`max_elapsed_seconds`；Provider 提供可靠计价时再配置 `max_provider_spend`，并按其实际计费单位估算。金额单价未知时不能虚构人民币预算，仍以区域、像素、调用和 token 硬限额约束。预算以**缓存命中后的缺口**计算，而不是按 PDF 总页数估算。每次付费调用前原子预留预计用量、核对剩余额度和截止时间；并发任务按同一来源/区域幂等领取，防止超额及重复收费。并发 OCR 数量由 Provider 限流和实测耗时配置，避免靠无限并发缩短表面时长。

预计缺口超过任何硬上限时，在首次超额调用前停止调度，返回已完成覆盖、未处理区域及预计追加计费单位；用户可调整整轮预算或另开明确的限列任务，但**本次完整填表不能自动缩小为先写 B–I**。运行中达到上限也停止新调用，保留已经落库的 OCR、印章和事实检查点；不取消已计费的在途请求。预算中断与 OCR 已处理但不清晰必须区分：前者有**未读区域**，不发布半行；后者已有一次读取结果，标记待核对并照常完成同轮发布。后续恢复只读取从未处理的必要区域，不重读低置信度区域。默认每份来源的 B–AA 均完成一次处理或已有正式缓存后，才对同轮全部来源进行一次 checkout/apply/publish；已判定的排除与 `UNRESOLVED` 按既有 Skill 明示，不冒充通过项。

回执和日志按阶段记录缓存命中区域数、实际 OCR 页/区域/像素、章图检测次数、模型调用/token、Provider 计费单位与可得的实际金额、各阶段及总耗时、Excel 发布时间，并列出每个 `OCR_UNCERTAIN / OCR_UNREADABLE` 格子的原始 OCR、候选值、页/区域和 Excel 展示标记。验收同时做冷缓存和热缓存对比：同一来源版本、模板和请求范围的热重跑目标是 **0 次新增 OCR 和 0 次新增模型调用**；缺少章图证据时只处理从未处理的章图区域一次，已有低置信度结果不重读。不同来源版本、版式或证据不足时如实记录必要开销，不能承诺固定的省时或省钱百分比。

完整 B–AA 识别必然比已验收的 A–I 两页模式耗时和花费更多。节省幅度应与“整篇 25 页 OCR + 全文交模型逐列判断”及“先发布 A–I、再读取同一 PDF 补 J–AA”比较。样本的候选事实跨越多数页面，OCR 页数未必显著减少；更确定的收益是同一 PDF 只建一次来源与事实索引、区域面积和重复调用下降、模型 token 减少，以及每轮只发布一次。实际金额取决于 WorkBuddy 使用的 OCR/模型 Provider 计费方式，不预设百分比。

## 4. 开发顺序与验收

1. 先做能力探测与只读页图：对 25 页和 22 页版式同时校准**B–I 身份区 + J–AA 项目区 + 审批声明区 + 印章区 + 续页**，记录每份 PDF 的候选页、渲染面积、OCR/印章检测调用、缓存、耗时和费用；不改 Excel。用无章、仅签字、同页他栏章、整栏属实、编号区间和跨页续表样本验证定位。
2. 实现同一来源运行的 B–I 字段识别与 J–P 事实、盖章状态，先保存在内部结果中，**不单独发布 B–I 或 J–P**。重点验证 B–I 清晰值和待核对标记均有页/区域与 OCR 原样文本，J/K/M/O/P 逐段 `SOURCE_ONLY`，L 同页人事 `SEAL` 区块与“年度考核优秀”，N 条件不明时不加勾，P 两个子事实不借章。
3. 在同一整行契约中接入 Q–Y 逐项印章/声明/范围索引、跨列组合条件树，以及 Z/AA 的独立正式原文与审批证据要求。用论文、项目经费、专利、奖励的真章、假阳性章、范围外项、满足/不满足/证据不足样本验证：只有已审批事实可写，只有完整标题和跨列组条件可确认时才加一次 `√`。实现阶段可以分模块开发，但完整 B–AA 功能齐备前不开放完整填表发布。
4. 实现每份来源 A–AA 整行组装、多来源同轮追加与单次发布；同轮多 PDF/Word 支持时先绑定每条事实的独立来源版本，拒绝跨人混用。默认直写清晰的 B–I 值、通过项、允许的来源事实及独立标记的 OCR 待核对候选；其他格按无匹配、不适用或审批未确认等真实状态留空并逐项报告。另以独立兼容测试验证历史 A–I 行在用户明确指定 `record_id` 时可更正，不把该路径放在新来源主流程中。

验收对比采用同一机器、同一 Provider、相同来源和冷/热缓存分别测试：总耗时 p50/p95，OCR 页/区域及像素量、印章检测调用、Provider 计费、模型 token、Excel 发布耗时、逐项印章范围准确率、误写入率、误加勾率和待核对率。必须看到**同一 PDF 在同一任务中产生 B–I 与 J–AA 的一次读取结果，A–AA 整行只写入一次且只生成一个新版本**；多 PDF 各占一行，已发布其他人员行不变，当前可见同名文件与版本文件 SHA 相同。用 B–I 模糊字、项目金额模糊字、章内文字不清和完全未识别样本验证：格内有明确待核对标记，回执有源位置，OCR 调用不重复，整行仍发布；不确定项目不算盖章属实、不加 `√`。未知版式、来源缺失、缺 SEAL 坐标、声明残缺、章与项目范围不一致、超预算和条件不足均返回明确状态；尤其不得在 J–AA 未处理时先发布 A–I，也不得以省时为由跳过盖章核验。
