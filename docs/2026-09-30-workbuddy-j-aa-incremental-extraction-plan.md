# WorkBuddy 职称汇总表 J–AA 增量识别与低成本执行方案

日期：2026-09-30

状态：方案，尚未开发。首期适用于已发布的 `申报人员业绩汇总-教学科研型教授.xlsx` 及其对应扫描 PDF 来源；Word 来源须在能提供等价原始印章图像、位置和审批范围后单独扩展，纯 Word 文字不能充当盖章证据。当前 A–I 定向流程保持有效。本轮用户明确要求按印章判断业务列，因此须同时遵守 [`file-agent-sealed-item-extraction`](../integrations/workbuddy/file-agent-plugin/skills/file-agent-sealed-item-extraction/SKILL.md) 及其 [A–AA 列来源路由](../integrations/workbuddy/file-agent-plugin/skills/file-agent-sealed-item-extraction/references/column-source-map.md)。

## 1. 目标与样本事实

在同一张已发布 Excel 的**同一人员行**补充 J–AA，不重复追加人员。优先识别缺失格，保留人工回传的现有值；有冲突时生成差异供复核。最终只发布一次新 `DocumentVersion`，并验证可见同名文件与不可变版本 SHA 一致。

当前模板的 J–AA 物理列为：J 辅导员/班主任等经历，K 国际合作和公共服务，L 考核优秀，M 师德评价，N–P 课程、指导和教学工作量，Q–S 教育教学成果，T–Y 论文、项目、经费、转化、奖励和专利，Z 资格审查意见，AA 备注。Q–Y 的标题包含复杂资格条件，不能把 OCR 到一个关键词等同于满足整列条件。

本轮“根据印章判断”按既有专用 Skill 执行：B–I 仍是有原文证据即可填写的身份列，不借此放宽 J–Y；J/K/M/O/P 保留专用模板的逐片段无章事实例外。若用户明确改为“所有列一律只写盖章属实内容”，则该例外关闭，不能写 `SOURCE_ONLY`。

`2026职称评审表-教授-石程.pdf` 是 25 页纯扫描文件，所有页面直接文本提取长度均为 0。已有 Skill 的来源路由把 L 列人事考核方章指向物理第 25 页，把其余 J–Y 分散指向第 5–24 页的相关栏目及可能的续页。页码仅是**该样本的候选索引**，不是其他 PDF 的固定页码、盖章已通过的证明或可直接提交的证据。若要求覆盖所有 J–Y，可能涉及大部分页面，无法承诺保持 A–I 的两页 OCR 成本。

## 2. 推荐执行链

```text
当前 Excel 版本 + 已归档来源版本
→ 只读确定缺失列、已有人工值与目标人员行
→ 复用 A–I 运行及已有 OCR；识别 PDF 版式
→ 根据版式页图和栏目索引生成 J–Y 候选区域
→ 先定位对应栏的印章与审批声明，再对可写项目区域每块只 OCR 一次
→ 服务端逐项核对印章、声明、审批覆盖范围和项目原文
→ 对完整列及跨列条件使用版本化规则计算；疑难项才交模型复核
→ 服务端校验同一行的非覆盖式差异
→ 一次发布新版本并核对可见文件
```

### 2.1 先冻结目标与来源，避免重复工作

- 按完整 `.xlsx` 文件名解析唯一活动目标，冻结 dataset、WorkingCopy、DocumentVersion、revision、行号和 `record_id`。从已归档来源成员查找原 PDF/Word 的不可变版本及 SHA；同一来源无需再次上传、归档或提取 B–I。
- 先核对可见文件 SHA 与当前版本记录，再读取该行实际值。非空格不自动覆盖；但**人工写入的值不构成 PDF 原文或盖章证据**。用户要求校验这些格的印章时仍需处理对应来源，只有同一来源版本已保存完整盖章证据的区域才可直接复用。若新证据与人工值不同，给出冲突，不覆盖。对多份同名或同人记录先确定稳定行，不按姓名猜测。
- 模板 A–AA 的真实多层标题、合并区和数据区按目标版本校验一次。长标题的资格规则编译为受版本约束的结构化规则快照；后续每个人只传列键和规则 ID，避免每次把长标题送入模型。

### 2.2 两级定位与按需 OCR

- 已验证的 25 页/22 页版式使用**版本化页图**：每个栏目配置候选页、表格区域、预期标题和适用列。服务端先做容器和版式校验；低分辨率页眉/表格线指纹仅用于定位，不当作内容证据。未知版式先对页眉窄条或缩略索引做一次受控定位；无法确定时返回待定位，不静默 OCR 全篇。
- 按待判列求候选区域并集；每个栏目同时覆盖**项目原文、审批声明、真实印章区域及必要续页**，不能只裁表格正文。先检查对应审批区域是否有可核验印章和声明：Q–Y 缺任一项则停止该栏资格通过判定，但被请求列仍须读取足以逐项列出排除/待复核事项的原文；J、K、M、O、P 可继续读取可定位的无章来源事实。同一页服务多个列的图像只渲染和 OCR 一次；空白或无关区域可跳过，但不能把“未读”推断成“无业绩”或“无章”。
- PDF 有可靠原生文字层时可先按页/区域取项目文字，但**印章图形仍须用原页图像核验**。本样本没有文字层，须由 WorkBuddy 已安装、授权且能返回真实印章信号和页内坐标的 Provider 处理服务器裁剪出的区域图像；仅有普通文字 OCR 时不能生成 `SEALED_CONFIRMED`。常规表格与章图分开选择分辨率，失败时只升级该区域。区域裁剪可使用 PyMuPDF `Page.get_pixmap(clip=...)`；其 `get_textpage_ocr()` 本身不提供区域裁剪。[PyMuPDF 页面 API](https://pymupdf.readthedocs.io/en/latest/page.html)、[局部渲染示例](https://pymupdf.readthedocs.io/en/latest/recipes-images.html)。
- 宿主若只有整篇识别接口，则同一固定来源最多识别一次并缓存全部页面，再只把需要的区段送入后续判断；回执必须如实说明本次没有节省 OCR 页数。不能为了宣称低费用而跳过必要的印章/续页，也不能把纯文字结果当印章图像证据。
- OCR/印章检测缓存键至少包含来源版本 SHA、版式版本、页码、区域坐标、图像 SHA、Provider 名称/版本和识别参数；印章区块的 bbox、页号、可辨识文字和栏目绑定另行留痕。任务中断按原租约恢复；成功区域不重新识别。缓存只代表对应局部内容，不冒充 PDF 全文，也不把旧 OCR 文字自动升级为印章证据。

#### 已读内容复用账本

启动新 OCR 前，服务端按不可变来源 `DocumentVersion` 和文件 SHA 汇总本次 PDF 的所有正式提取结果，包括此前 A–I 定向运行、WorkBuddy 已有页面 OCR、整页 OCR、局部 OCR、印章检测及已核验审批关系。先调用 `structured_dataset_source(mode="INDEX", content_origin="WORKBUDDY")` 建立候选页索引；仅对确实需要的 `unit_orders` 批量调用一次 `FULL`，续页缺失时才补第二次。不能将 25 页全文反复送进模型上下文。A–I 既有第 1、3 页文字可用于复核身份，但其裁剪范围之外的 J–Y 区域仍属未读。

账本以“来源版本、物理页、原始 bbox、证据类型”记录覆盖状态：`TEXT`（项目/表格原文）、`APPROVAL_TEXT`（审批声明）、`SEAL_IMAGE`（真实章图和 bbox）、`BINDING`（声明覆盖的项目范围）。同一区域的整页结果可覆盖局部结果；局部结果只能覆盖其真实裁剪范围。复用时仍校验原文定位、人员与栏目归属、声明及印章的同栏绑定；已有文字不能代替章图，已有章图也不能代替声明。若复用证据完整且仍对应同一不可变 PDF 版本，即使 Provider 现已升级，也不因版本变化强制重新付费识别；只对缺失或不可靠的证据重新识别。

持久化缓存分两层：图像/识别层按来源 SHA、页码、bbox、裁剪图 SHA、预处理参数、Provider 和模型版本去重；结构化事实层按来源版本、OCR 证据 ID、栏目路由版本、印章绑定规则版本和模板资格规则版本计算。规则更新只重算受影响的事实和资格，不重新 OCR 未变化的图像；换 PDF 版本或裁剪范围则不能误命中旧缓存。每个成功区域立即落库并记录幂等任务键，重试、任务恢复与多人并发不得对同一区域重复收费。

### 2.3 印章属实、来源事实和资格判定三层分离

每个拟认定为“盖章属实”的项目都必须形成不可拆分的证据链：**真实印章图形及 PDF 页内位置 → 同一可解释审批区域的可辨识声明 → 声明能唯一绑定的项目/栏目范围 → 该项目完整原文、页号和位置**。红色图形、OCR 出“章”字、本人承诺、签字、编号前勾选或同页其他栏印章都不能单独证明属实。签字不是必需条件。

声明到项目的绑定顺序沿用旧 Skill：明确项号/范围 → 唯一完整项目或整栏 `WHOLE_SECTION` → 编号前可定位勾选 → 同栏跨页行序 → 受限 `LAST_ITEM_FALLBACK`。每一步都要求同栏、同审批区域和可确定阅读顺序；不能唯一绑定则进入 `review_items`，不把整页内容默认归入印章。跨页续表必须同时读取起始栏和审批续页。每个项目分别标 `SEALED_CONFIRMED`、允许的 `SOURCE_ONLY` 或 `UNRESOLVED`；同一格不同片段可有不同状态。

| 列 | 来源与印章规则 | Excel 展示和资格规则 |
| --- | --- | --- |
| J、K、M、O、P | 逐片段取事实并找本栏对应章和审批声明。仅本专用模板这些列允许清楚、可定位且属于同一申报人的无章原文进入 `SOURCE_ONLY` | 无章片段由服务端逐段附 `〔PDF 原文，未见对应印章〕`；有章片段按实际范围核验。P 的工作量与教学效果、O 的不同指导事实分别判断，不借相邻章。来源事实不等于整列资格通过 |
| L | 仅从“任现职以来的考核情况”取经人事部门真实方形/长方形印章核验的“年度考核优秀”年份，参考样本候选物理第 25 页 | 来源运行必须有同页 `SEAL` 区块及真实 bbox；`approval_kind=HR_ANNUAL_EXCELLENCE`，声明与印章引用同一段章内优秀结论。手写“合格”、空白推荐意见或无章年份不写 |
| N | “系统主讲两门课”等属于派生条件，课程表事实和适用审批范围分别取证 | 不用无章 `SOURCE_ONLY` 冒充通过；完整条件及依赖事实核验后才给资格标记，否则说明未确定 |
| Q–Y | 每个业务项目必须在本栏可验证盖章及审批声明的覆盖范围内；无章、范围外、仅本人承诺和含糊项目进入排除/复核，不写业务事实 | 已审批事实即使不满足资格也可写具体内容，但不加 `√`；数量、等级、排名、到账金额等再按完整标题计算。Q–S 的“3 选 1”和 T–Y 的跨列必选/任选条件必须单独核验，当前逐列 evaluator 无法表达的组合保持未确定，不强行加勾 |
| Z、AA | Z 须有与资格审查意见**本栏对应**的独立正式原文和审批证据；第 25 页系所推荐意见不等同 Z。AA 仅收明确授权的备注 | 不从 L 或 Q–Y 的章推断 Z 已通过；缺证据则保留空白。AA 不擅自生成说明 |

模型只接收经 OCR 得到的相关短片段，用于栏目归属、字形候选和证据匹配；普通数字汇总、日期范围、排名、数量阈值由确定性代码计算。每条事实分别保存源版本、物理页、原文字符范围、项目 bbox、声明和印章 bbox、绑定方法及 Provider。原文引文、`raw_text` 和片段不附加“无章”说明或 `√`；这些只能由服务端展示层生成。只有完整标题条件成立且其所依赖事实均在合法审批范围内，服务端才在整个人员数据格末尾加一次 `√`，不在小项逐个加勾。

默认 `DIRECT_SAVE` 只发布 `verified_items` 与允许的 J/K/M/O/P `source_fact_items`；`review_items` 自动排除并逐项报告。用户明确要求先复核才使用 `REVIEW_REQUIRED`。未读到、无匹配、无章、已读但不满足、审批范围不明和用户人工已填分别记录，不能混为“没有业绩”。

### 2.4 同行增量发布

领取 OCR 前先探测服务端 `sealed-item-template-v1` 及其 `source_fact_column_range=J:P`、`source_only_fragments`、`hr_annual_excellence_seal_block` 能力。新定向契约还必须明确支持真实印章区域、声明、项目范围和已发布行更正；缺任何必要能力则在 OCR 前停止，不花钱做无法保存的识别。新增独立的 `SCOPED_PERFORMANCE_ENRICHMENT` 任务契约，不能直接放宽现有固定 B–I、两块区域的 `workbuddy-scoped-pdf-v1`。新契约冻结 `requested_columns`、源版本、栏目及审批区域、Provider、目标行和业务模式 `sealed_only=true`，分别记录 `SEALED_CONFIRMED / SOURCE_ONLY / UNRESOLVED / NOT_REQUESTED` 及资格 `VERIFIED / NOT_MET / UNRESOLVED`，不能用“已 OCR”替代盖章或资格完成。

复用已有 `StructuredDatasetTask`、来源运行/页面证据、`excel_writeback_correction_checkout/apply/publish` 的同行更正边界和发布协调器。现有更正链默认绑定完整 WorkBuddy 来源，须扩展为接受**同一来源的定向业绩运行**以及 `SEAL` 区块、声明和作用范围；不能把人工修订任务或 A–I 局部文字运行当成自动盖章证据。服务端在内部预览中逐片段校验 `approval.scope` 只覆盖本栏已确认事实，`source_only_fragments` 只对应 J/K/M/O/P 原文。默认 `DIRECT_SAVE` 校验通过后直接发布；仅用户明确要求先看结果时才等待确认。写入前比较工作簿实际格值与冻结基线，默认只改目标行的本轮列，保护其余行、表头、公式、样式、合并区和人工补充值。发布后校验最新隐藏版本、数据库当前版本及同名可见文件三方 SHA。预计可沿用现有 JSON 审计列和版本表；实施前仍需核对唯一约束及来源运行关联，若不足则补迁移，不以缺审计换速度。

## 3. 成本和速度控制

### 3.1 每次只购买缺失证据

1. **先查缓存，再估预算，再调用 Provider**：完成目标能力探测、来源/目标版本冻结、行定位、版式匹配和上述复用账本后，才计算缺口。实际 OCR 队列只包含请求列所需的、尚无可用证据的项目区、审批声明区、印章区和续页。已有 Excel 值不算证据。
2. **同页同区一次处理**：按区域并集去重，而非按列发起 OCR；同一裁剪图在本轮只做一次标准识别。需更高分辨率时，最多针对失败区域额外做一次升级识别，并先检查剩余预算。两个尝试仍不足则记为 `UNRESOLVED`，不循环重试。仅有整篇识别能力的 Provider 对同一不可变来源最多发起一次整篇 OCR，随后复用页面结果；回执明确其实际计费页数。
3. **先读审批，仍保留项目清单**：Q–Y 优先核验本栏及续页的真实章图和声明；无章或范围不明时跳过该栏资格模型推理，但仍读取足以列出排除/待复核项目的原文。J/K/M/O/P 继续按 Skill 的无章来源事实例外处理，L 必须查人事方章。不得用成本理由缩小印章或声明的必要裁剪范围。
4. **计算优先于模型**：同一栏目 OCR 文本只解析一次，生成可跨列复用的课程、项目、论文、奖励等事实索引。规则树处理数量、年份、排名、经费及跨列资格；模型只接收无法用确定性规则解决的短候选，按栏目批量处理，不逐行逐列重复输入 PDF 全文。已验证结构化事实可在目标表规则更新时重算，不重复 OCR。

### 3.2 强制预算门禁与断点续跑

每轮配置并记录 `max_paid_ocr_regions`、`max_ocr_pixels`、`max_model_calls`、`max_model_input_tokens`、`max_elapsed_seconds`；Provider 提供可靠计价时再配置 `max_provider_spend`，并按其实际计费单位估算。金额单价未知时不能虚构人民币预算，仍以区域、像素、调用和 token 硬限额约束。预算以**缓存命中后的缺口**计算，而不是按 PDF 总页数估算。每次付费调用前原子预留预计用量、核对剩余额度和截止时间；并发任务按同一来源/区域幂等领取，防止超额及重复收费。并发 OCR 数量由 Provider 限流和实测耗时配置，避免靠无限并发缩短表面时长。

预计缺口超过任何硬上限时，在首次超额调用前停止调度，返回已完成覆盖、未处理区域、预计追加计费单位和可缩小的列范围。运行中达到上限也停止新调用，保留已经落库的 OCR、印章和事实检查点，下一轮只处理剩余缺口；不取消已计费的在途请求。预算中断时不把未读列写成“无业绩”，也不把未完成请求范围当成一次完整发布。默认同一人员行只在本轮请求范围全部得到可判定结果后进行一次 checkout/apply/publish；已判定的排除与 `UNRESOLVED` 按既有 Skill 明示，不冒充通过项。

回执和日志按阶段记录缓存命中区域数、实际 OCR 页/区域/像素、章图检测次数、模型调用/token、Provider 计费单位与可得的实际金额、各阶段及总耗时、Excel 发布时间。验收同时做冷缓存和热缓存对比：同一来源版本、模板和请求范围的热重跑目标是 **0 次新增 OCR 和 0 次新增模型调用**；仅缺章图时只补章图证据。不同来源版本、版式或证据不足时如实记录必要开销，不能承诺固定的省时或省钱百分比。

新增识别必然比已验收的 A–I 两页模式耗时和花费更多。节省幅度应与“整篇 25 页 OCR + 全文交模型逐列判断”比较，不能与 A–I 模式直接比较。若用户要求所有 J–Y，本样本的候选事实跨越多数页面，OCR 页数未必显著减少；更确定的收益是区域面积、重复调用、模型 token 和多次发布次数下降。实际金额取决于 WorkBuddy 使用的 OCR/模型 Provider 计费方式，不预设百分比。

## 4. 开发顺序与验收

1. 先做能力探测与只读页图：对 25 页和 22 页版式校准**项目区 + 审批声明区 + 印章区 + 续页**，记录每份 PDF 的候选页、渲染面积、OCR/印章检测调用、缓存、耗时和费用；不改 Excel。用无章、仅签字、同页他栏章、整栏属实、编号区间和跨页续表样本验证定位。
2. 落地 J–P 同行事实补全和盖章状态；当前人工 J–P 值只作为冲突基线，不能省略 PDF 校验。重点验证 J/K/M/O/P 逐段 `SOURCE_ONLY`，L 同页人事 `SEAL` 区块与“年度考核优秀”，N 条件不明时不加勾，P 两个子事实不借章，以及一次发布。
3. 落地 Q–Y 逐项印章/声明/范围索引、跨列组合条件树。用论文、项目经费、专利、奖励的真章、假阳性章、范围外项、满足/不满足/证据不足样本验证：只有已审批事实可写，只有完整标题和跨列组条件可确认时才加一次 `√`。
4. 接入 Z/AA 的独立正式原文与审批证据要求；同轮多 PDF/Word 支持时先绑定稳定人员行和每条事实的独立来源版本，拒绝跨人混用。默认直写仅发布通过项与允许的来源事实，逐项报告排除/待复核项。

验收对比采用同一机器、同一 Provider、相同来源和冷/热缓存分别测试：总耗时 p50/p95，OCR 页/区域及像素量、印章检测调用、Provider 计费、模型 token、Excel 发布耗时、逐项印章范围准确率、误写入率、误加勾率和待复核率。必须看到已发布旧行只被增量更新、A–I 与其他人员行不变、当前可见同名文件与版本文件 SHA 相同；未知版式、缺 SEAL 坐标、声明残缺、章与项目范围不一致、超预算和条件不足均返回明确状态，绝不以省时为由跳过盖章核验。
