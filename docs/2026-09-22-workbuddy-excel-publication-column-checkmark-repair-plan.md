# WorkBuddy Excel 发布、缺列与符合条件标记修复方案

WorkBuddy 调用记录、服务日志、只读数据库查询以及最终 XLSX 单元格检查制定。

正文确认响应明确包含 `content_saved=true`、`excel_published=false` 和
`next_action=structured_dataset_source`。宿主没有继续调用数据集注册、追加和导出工具，
而是通过本地 Office 工具在 Documents 另存了 XLSX。因此本轮产物没有进入服务器累计表发布链路。

最终表第一工作表数据行 J–P 列为空。宿主将提示词中的“只提取该编号范围”解释为必须有显式项号，
排除了没有显式编号的“本栏情况属实”等声明。部分原文已被识别，缺失发生在筛选和字段映射阶段。
其他空列必须逐列检查，不能因为为空就认定应该填入。

两个工作表均未发现新增对勾。宿主未形成逐字段条件判定与标记写入；当前 Skill 又把标记描述为
`title_source_text + √`，无法清晰表达“满足该列标题要求后，在该人员该格的整段内容末尾加 √”。
当前 MCP `DatasetValue` 和 API `FieldCandidate` 只有原文、位置、证据和置信度，没有这类判定契约。

## 2. 修复目标与保留边界

1. 用户本轮上传的 Excel 优先成为目标；没有新表时按明确文件名解析，否则按提示词新建。
2. WorkBuddy 负责真实读取与 OCR；不固定 Provider。服务端负责证据校验、受控格式提升和 Excel 发布。
3. 盖章、审批声明和可定位的项目映射是通过依据；签字不是必需条件，不恢复签字门槛。
4. 保留按提示词选择复核后保存、明确授权直接保存的两条路径；纯归档不触发表格生成。
5. 工作副本真实 basename、文件列表名、下载名一致；同一 Document/WorkingCopy 持续产生版本。
6. 原件保持不变；同名冲突、目标版本变化和权限校验沿用受控边界。
7. 用户没有明确选择额外明细工作表时，不自动新增工作表或更改模板结构。

## 3. 服务器保存：持久任务与统一执行入口

### 3.1 建立可恢复的表格任务

新增受控表格任务记录，绑定来源版本、提取任务/运行、目标选择快照、字段布局、确认指纹、
幂等键、追加 revision 和最终导出版本。任务状态必须区别：

`WAITING_CONFIRMATION -> SAVING_CONTENT -> PREPARING_TARGET -> VALIDATING_RECORDS -> APPENDING -> PUBLISHING -> COMPLETED`

各阶段允许记录 `WAITING_DEPENDENCY`、`NEEDS_REVIEW` 或 `FAILED`，保存准确阻塞原因和恢复位置。
跨轮确认、会话压缩和 MCP 重启后，用任务 ID 恢复；不能只依靠模型记住后续步骤。

确认前继续遵守现有边界：服务器只保存有界任务元数据、目标快照和结果指纹，正文与完整候选值保留在
已有受控宿主草稿缓存中，不提前持久化到服务器正文/数据集/Excel。用户确认后才提交固定草稿。
目标原本已入库的只读信息不受此限制。

### 3.2 统一提交与恢复工具

拟新增 `structured_dataset_commit` 和只读 `structured_dataset_task_get`，属于待实现接口，
不能在实现前写进可调用白名单。前者接受任务 ID、已确认草稿指纹及有界候选，不接收任意路径或脚本。

服务端通过既有受控 service/handler 完成目标准备、证据校验、追加、非空检查和导出。
每个阶段保持 ToolInvocation、ChangeSet 和版本审计；MCP 不直接操作服务器数据库或文件。
导入尚未形成 ACTIVE 工作副本、XLS 转换未完成时，记录固定依赖任务并等待完成，不能猜测 Document ID。
格式提升复用现有 STRUCTURED_EXTRACTION 异步任务，不另建客户端转换通道。

必须分别表达正文保存完成和 Excel 发布完成。旧 confirm 工具保持原有语义，不让纯归档调用隐式生成表格。
Excel 流程的 Skill 在确认后调用统一任务入口；已有细粒度工具继续兼容。

复核路径的指纹覆盖来源、目标文件名/版本、工作表、字段及布局、候选内容、留空原因和标记决策。
仅确认 OCR 全文不等于确认任何后来重新生成的字段值。正式 source_unit_id 在提交后产生时，使用
受控映射绑定原始 unit ID、原文和位置，不通过替换正文绕过原确认。
直接保存路径复用同一任务入口，依据冻结的明确直接保存授权执行，不额外要求一次无意义确认。

### 3.3 幂等、并发和失败恢复

- 锁定目标版本，注册/追加/导出各阶段保存幂等结果。
- 数据库事务和磁盘写入不能假装是同一个原子事务；采用现有安全 writer、暂存校验、原子发布及可恢复状态。
- append 成功而 export 失败时记录未发布 revision；恢复只重试导出，不再次追加。
- 同一请求响应丢失时复用原任务与结果，不重复生成行、工作副本或文档版本。
- 目标被其他任务改动时返回版本冲突，重新解析；需要用户确认的内容发生变化时重新预览。
- 旧接口兼容请求不得用于绕过新任务中已经冻结的确认与目标绑定。

### 3.4 完成判据

完成回执必须绑定本轮任务与本轮 revision，验证当前文件存在、内容哈希正确、DocumentVersion 和工作副本
一致、文件列表接口可查且下载字节一致。不能用旧版本中的累计记录数大于零证明本轮已经写入。
区分本轮新增、幂等复用、排除、待复核和实际写入单元格数；没有可写数据时返回无可写记录，不能称为已生成。

服务器当前文件保存位置继续采用：

`WORKING_COPY_STORAGE_ROOT/structured-datasets/{dataset_id}/{用户可见文件名}.xlsx`

下载失败与服务器发布失败分别报告；发布成功而宿主下载失败不重复导出或追加。
宿主自由生成的回复仍无法仅靠后端完全约束，但本系统不得签发没有发布事实的完成状态或交付链接。

## 4. 缺列：完整字段清单与逐列判定

读取真实模板的全部工作表候选、多层表头、合并区域、实际列位置和填写区域，建立稳定字段清单。
相同叶标题用实际列位置消歧；不采用模型手写的部分列号列表作为完整 schema。

每个选定字段都必须有结果，允许的结果包括：有证据可写、无来源内容、超出授权范围、证据不足、
声明映射不明确、待复核、模板保留字段。不出现未解释的缺列。序号、公式、资格审查意见等不能凭空填值。

明确项号不是填写前提。项号只是定位审批范围的一种方式，不是必填字段或审批通过门槛。
盖章、审批声明和对应内容范围能够确定，且可以映射到目标 Excel 字段时，即使原文没有任何显式项号，
也允许按冻结的复核/直接保存策略填写。不得仅以“没有第几项”或“没有编号范围”为由留空。
用于内部定位的行序不得伪装成原文已有项号，也不能要求用户给原文补编号。

定位范围时继续按以下优先级判定：

1. 显式编号或范围。
2. 声明与盖章区域唯一绑定的完整项目/栏目。
3. 编号前真实勾选。
4. 从同栏首条数据开始的行序及必要的跨页连续计数。
5. 同一可定位审批区域内受控候选集合的末项兜底。

“本栏情况属实”只有在栏位和盖章覆盖能够唯一绑定时才能适用整栏/整项规则；不把同页所有内容都视为通过。
例如“指导情况属实”“教学工作量属实”能够明确对应已盖章的相关栏目时，允许提取该范围内的指导情况或
教学工作量并填写对应列，无需声明中出现项号。是否加 √ 仍另按该列标题条件判定。
声明残缺只保留可确认的内容，审批事实本身不能确认时不能通过。

优先级仍是本轮明确指令高于 Skill 默认规则。用户明确要求“仅限显式编号，不含整栏声明”时必须排除无项号项。
本次用户已明确“不一定要有明确项号才能填写”，此澄清覆盖此前提示词中“编号范围”引起的歧义；
不得沿用此前的严格项号过滤，也不再仅因缺少项号重复询问。后续只有用户另外明确排除无编号内容时才收窄范围。
审批范围本身仍无法确定时，在预览中展示具体映射问题并按既定规则处理，不能将其笼统归因为没有项号。

确认前预览必须逐列列出：字段/列、拟写内容、来源位置、审批绑定、标题条件结论、是否加勾、留空原因。
没有显示的新增内容不能借旧的“确认无误并保存”写入。

## 5. 对勾：数据单元格展示派生值

### 5.1 明确位置与语义

对每个人的每个业务字段，以该列标题的实际要求判断；通过后只在该数据单元格整段文字末尾加一个 `√`。
不修改表头文字，不在每条论文、项目、子选项之后分别打勾，不自动给姓名、日期、金额等基础字段加勾。

例如一列要求“以第一发明人授权专利不少于 5 项”，证据确认的合格数量达到要求时，展示为：

`以第一发明人授权专利 9 项…… √`

真实性认证与资格条件是否满足分开判断：有盖章属实不自动代表数量、排名、级别或年限条件全部满足。
证据不足时不给勾；明确不满足时也不给勾，已经核实且在范围内的事实可按已确认的字段策略写入。

### 5.2 条件表达

标题中的 AND、OR、数量门槛、排名、年限、学科分支必须保留真实条件。
“3 选 1”采用至少满足一个分支，“5 选 2且指定必选项”采用数量门槛与必选约束组合，
不能把所有备选项都设为必须通过。组标题与叶列条件分别计算；组结论没有独立目标格时只在回执展示，
不修改合并表头，也不把组结论任意写进某个叶列。

LLM 只从模板和证据提出有界条件与候选事实，服务端校验引用并运行白名单比较/组合规则。
条件本身或事实含义不能可靠确定时返回待复核，不接受模型直接传一个 `true` 就加勾。

### 5.3 数据契约与导出

在当前 MCP/API 字段契约中新增可选且有界的条件判定元数据，正式名称实施时同步 API 文档。
至少区分原文证据、提取后的字段内容、条件引用、判断依据、判定结果和展示标记。

- `quote`、source unit 和 OCR 原文保持原样；生成的 √ 不进入原文证据。
- 服务端依据校验后的判断生成展示值，而非要求模型把 √ 混进 raw_text。
- query 同时返回字段内容、判定与展示值，export 使用同一个展示值生成逻辑。
- 同一字段重试最多一个末尾生成标记；不要通过全局删除 √ 损坏原文本身已有的勾选证据。
- 新判定信息必须持久化并绑定数据集 revision，供后续导出重试和历史版本回溯。
- 明确区分允许留空的可选字段与必须阻塞整行的关键字段；不能用一个可选空列无解释地隐藏整条人员记录。

## 6. Skill 与宿主衔接

同步更新盖章提取、累计表格及附件桥接三个 Skill 的调用入口、完成判据和例子。
移除把“标题级通过”理解为修改标题文字的歧义；统一为“列条件判断 + 人员数据格末尾标记”。
确认后的短流程以任务 ID 恢复状态并提交，避免会话压缩后转向本地 Office 编辑。
本地 Office 能力可作为真实表格读取 Provider，但本业务的最终写入由服务器受控接口执行。

保留非 Excel 的归档、搜索、读取、重命名及旧数据集流程。新字段采用兼容默认值；
旧记录不因升级自动被判定为通过或补上 √。

## 7. 实施顺序

1. 实现任务状态、固定候选/确认绑定、统一 commit/status 契约及必要迁移。
2. 接通现有导入完成、XLS 格式提升、数据集 append/export 和阶段恢复，建立服务器完成判据。
3. 实现完整字段覆盖、受控条件判定、展示值和 writer/query 一致性。
4. 同步 Skill、API 文档、运行说明和插件版本，执行相关自动回归。
5. 校验迁移状态、后端与 worker 运行版本；部署后重新连接 MCP，并完成真实 WorkBuddy 验收。

每一阶段记录实际完成状态，不以插件重新打包替代服务端实现或真实流程验证。

使用脱敏或合成测试材料记录验收，文档不复制个人材料正文、租约、令牌或配置密钥。

## 9. 已失败任务的恢复范围

本轮已有本地 XLSX 保留作为诊断样本，不能直接把它上传当成已正确修复的累计表。
先核实服务器现有来源版本、已确认正文和草稿可复用性，避免重复 OCR/上传。
按真实模板重新形成完整逐列候选与标记预览；补入此前排除的内容或改变判定属于实质变化，
复核路径需要用户确认新预览。确认后经统一任务发布服务器当前表，再验收文件列表与下载。
不自动删除旧文件，不覆盖原件，不静默创建带附加后缀的同名替代文件。

## 10. 本次实现与验证记录

- 新增 structured_dataset_preview/confirm/commit/task_get；服务端只保存未确认候选指纹与目标元数据，
  MCP 缓存完整草稿，确认后固定内容进入持久任务。来源文档确认与表格确认合并编排。
- 阶段为 WAITING_CONFIRMATION、READY、WAITING_DEPENDENCY/PREPARING_TARGET、APPENDING、PUBLISHING、COMPLETED。
  服务端每次推进一个阶段，MCP 有界循环。等待归档/转换时返回，后续同 task_id 继续，不自动后台轮询。
- 设计收敛：等齐所有来源后，同一事务追加本批所有来源，避免后续来源失败留下半批记录。
  导出失败保留已追加阶段；重试只发布。未追加前失败释放目标占用；发布完成释放占用。
- 新增迁移 20260922_0002：structured_dataset_tasks、字段 presentation_json、目标 active_task_id。
  旧记录默认不补勾；旧 append/export 被同目标活动任务占用时拒绝交叉写入。
- FieldCandidate 增加 fragments、blank_reason、approval、assessment。审批范围支持 WHOLE_SECTION，
  无编号可填写。所有模板列必须有事实或空白原因，片段逐字引用；否定声明及范围外引文拒绝。
- ALL/ANY/AT_LEAST + 必选组通过白名单比较生成数据格末尾 √，不改表头和源文。
  数字不可截取或反转阈值方向。复杂自然语言条件仍由宿主依据真实模板解读，不能可靠表达时不加勾。
- 新统一任务对缺失评分不伪造置信度；逐字证据和类型校验仍强制，缺失评分对外为 null，明确低分仍按原规则复核。
