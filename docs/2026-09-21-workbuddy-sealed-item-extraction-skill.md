# WorkBuddy 盖章项目属实范围提取 Skill 规范

日期：2026-09-21

状态：历史方案。2026-10-09 应用户只保留 B–I/L 定向填表的要求，当前 WorkBuddy 插件已移除本 Skill 及其列来源表；下文不再代表可调用能力。服务端相关契约本次未删除。

## 1. 需求

当用户上传 PDF，并明确要求只把盖章区域中“第几项至第几项属实”覆盖的项目写入 Excel 时，
系统必须排除未被审批证据覆盖的其他项目，同时兼容 `①②③` 等带圈序号、未限定子选项的整项审批，
以及审批文字无法区分具体项时编号前勾选标记的辅助判定。

该能力不改造 OCR Provider，而是新增 WorkBuddy 业务编排 Skill：

```text
WorkBuddy 宿主 PDF/OCR/版面识别
-> 签章区域 + 属实声明 + 编号范围
-> PDF 编号项目映射
-> verified_items / review_items
-> 用户预览确认
-> 仅 verified_items 写入目标 Excel
```

## 2. 能力边界

- OCR、页面渲染、文字坐标与签章区域识别在 WorkBuddy 宿主侧完成。
- Skill 不固定 `tencent-docs`、`ocr.extract` 或任何 `provider_name`；实际 Provider 必须随结果记录。
- File Agent 不得为 WorkBuddy 图片/扫描页启用内部 OCR 降级。
- 只有 OCR 全文而没有可定位签章证据时，不能自动声称项目已盖章。
- 是否需要用户内容复核由本轮提示词冻结：明确要求直接生成/保存且无需确认时可跳过 preview/confirm；
  未明确时默认先预览确认。无论哪条路径，文档 submit 成功前都不创建/追加数据集记录或导出 Excel。

## 3. 证据契约

每个可写入项目的最小证据集：

- 独立的签字页码与区域。
- 独立的盖章页码与区域；签字和盖章缺一不可。
- 属实声明原文、页码与区域。
- 规范化后的起止编号、完整编号项或编号前已勾选项；带圈序号同时保留原始字符。
- 被命中项目的编号、完整原文、页码与区域。

缺少任意一项都只能列入 `review_items`。`review_items` 必须向用户展示，但不能进入 Excel 拟写入数据。

## 4. 范围与 Excel 映射

- 闭区间包含起止编号。
- 阿拉伯数字、中文数字和带圈数字 `①②③…⑳` 规范化到统一编号，原始编号样式保留为证据；模糊字形不猜测。
- 多个独立范围取并集后去重，不自动填补范围之间的项目。
- 声明没有提到具体子选项，但能由签章和版面唯一绑定某个编号项时，该编号项含全部子选项整体通过。
- 声明区域有多个编号项且文字无法区分时，可使用紧邻编号前、与编号位于同一行或同一选项框的真实
  `✓/√/☑/手写勾` 辅助确定；仅勾选项通过。勾选不能替代签章或审批声明，位置不清或冲突时待复核。
- 声明残缺时只使用可确定片段，不补字；无法确认审批事实时整组待复核。
- 无可见序号时从同一栏第一条真实数据行开始跨页连续计数；当前页是续页时向前查找该栏起始行。
- 明确范围、整项、勾选和跨页行序后仍有多个候选时，仅在同一栏、同一签字盖章审批区域且顺序确定的范围内
  选择最后一项，并记录 `LAST_ITEM_FALLBACK`。无法确定栏、审批区域或顺序时仍待复核。
- 项号重复、缺号、越界、顺序颠倒或无法确定“以上”的起点时转待复核。
- 行式目标 Excel 只新增已验证项的行。
- 列式目标 Excel 只填充已验证项对应字段，范围外字段留空。
- 每个写入值保留项目原文 evidence ref，并可追溯到属实声明和签章区域。
- `√` 是标题级通过标记：先把标题及其全部必需小项组成一组，只有组内全部小项均已验证且不存在待复核项时，
  才在标题末尾追加一个 `√`，例如 `政治表现√`。小项 `政治表现良好` 始终保持原样，不得写成
  `政治表现良好√`；部分小项通过时标题也不加勾。原始 OCR、quote 和 evidence ref 不增加该字符，重复执行
  不能产生 `√√`。

## 5. 复核与直接保存路径

- `REVIEW_REQUIRED`：提示词明确要求先预览、先复核、确认后保存，或没有明确说明时使用。完整展示标题分组、
  全部必需小项、标题是否满足全部要求、拟写入的标题级 `√` 和待复核项，用户后续确认后才 submit、append 和 export。
- `DIRECT_SAVE`：仅当本轮提示词明确要求无需复核/确认或直接生成并保存/写入时使用。跳过 preview/confirm，
  但必须先完成相同证据判定；只写 verified 项，review 项自动排除并在最终回执逐项说明。
- 两类表达冲突时先请用户澄清。跳过复核不授权选择歧义目标、忽略同名/版本冲突或写入证据不足内容。
- 导入前冻结路径：复核路径使用 `CONFIRM_BEFORE_SAVE`，直接路径使用 `DIRECT_ARCHIVE`。后者仍继续结构化数据
  写入与 Excel 导出，不能误解成只归档文件。

## 6. 验收用例

1. 单范围：“第 3 项至第 7 项属实”，只预览和写入 3–7。
2. 单项：“第四项属实”，只预览和写入第 4 项。
3. 多范围：1–3 与 7–8 分别有可验证签章声明，写入 1、2、3、7、8，不写入 4–6。
4. 有“属实”文字但无签章区域：列入待复核，不写入。
5. 有印章但范围 OCR 不清：展示冲突与页码，不写入。
6. 项号在不同篇章重复：缺少唯一篇章证据时不自行选择。
7. 用户更正范围：必须重新 preview 并展示新的全部拟写入项后再等待确认。
8. 宿主不存在可靠的签章/版面识别能力：明确报告阻塞，不降级 File Agent 内部 OCR。
9. 带圈序号：声明“①至③属实”，规范化并写入 ①、②、③，同时保留原始序号。
10. 整项审批：声明只写“属实”且签章区域唯一绑定 ②，②及其全部子选项作为一个完整项目进入预览。
11. 勾选辅助：声明覆盖 ①、②、③ 但未写具体项，仅 ①、③ 编号前有可定位勾选，只预览 ①、③；
    勾选位置不清时转待复核。
12. 标题级对勾：标题 `政治表现` 下全部必需小项均 verified 时写为 `政治表现√`；小项
    `政治表现良好` 仍按原文写入。任一小项未通过或待复核时标题不加勾，evidence quote 始终为原文。
13. 复核路径：提示词“先给我看，确认后保存”必须 preview 并等待后续确认。
14. 直接路径：提示词“无需复核，直接生成 Excel”跳过 preview/confirm，只写 verified 项并在回执列出排除项。
15. 模糊提示词只说“生成 Excel”但没有明确跳过复核时，默认 `REVIEW_REQUIRED`。
16. 只有签字没有盖章：即使声明清楚也不写入；只有盖章没有签字同样不写入。
17. 残缺声明：只保留可确定原文；“属实/审批通过”本身不可确认时不得使用末项兜底。
18. 无编号单页：从本栏第一条真实数据行按 1 开始计数，标题、空行、说明和续行不计数。
19. 无编号跨页：当前页没有可见编号时向前页定位同栏第一行，跨页连续计数，不在当前页重置。
20. 末项兜底：同一栏、同一审批区域内候选为 A/B/C 且仍无法唯一绑定时选 C，并在预览/回执展示全部候选；
    候选跨栏或跨审批区域时不得选择整份文件末项，必须待复核。

## 7. 2026-09-23 人工样表核对后的专用规则修订

本节记录当前专用 Skill 的有效口径；前文关于“签字和盖章缺一不可”以及“在标题末尾加 √”的旧表述
不再适用。签字不是必需条件；只有真实盖章、同一审批区域的可辨识核验结论和可定位项目内容才可写入。
`√` 仅在完整列标题条件满足时加在数据格的具体文字末尾，不改表头，也不逐个小项加勾。

- 有效印章不限圆形。方形、长方形印章可作为证据，但须有真实图像区域和页码，不能以“方章”OCR
  字样、打印方框或其他栏印章代替。
- 本模板 B–I 为身份列；L 列“考核优秀情况”可从来源 PDF“任现职以来的考核情况”栏中人事部门
  方形/长方形印章内或与该章唯一关联的年度与“年度考核优秀”结论提取。该明确核验结论在 L 列
  不另要求出现“属实”字样；“合格”年份和空白推荐意见不得转写为优秀。
- Z 列“资格审查意见”必须有独立的对应审批证据，不得从 L 列、人事印章或人工填写样表推断“通过”。
- Q–S、T–Y 的合并表头条件须按整组判断；服务端现有逐列 assessment 无法表达的跨列组合不得
  强行加勾或宣称通过。计数汇总须保留逐项来源和可复核依据。
- 当前服务端 `approval` 校验仍要求声明引用包含“属实/通过”等字样，且印章引用包含“章/印”。
  因而仅修改 Skill 不能保证上述 L 列方章案例可成功提交；不得伪造引用绕过校验，服务端契约
  兼容前须如实报告该列的校验阻塞。

## 8. 2026-09-23 J–P 无章来源事实的专用模板例外

本节覆盖前文“只有盖章项目可写入”的笼统表述，但不改变 Q–Y 的盖章项目范围规则。
人工 Excel 只决定目标列及填写结构，不能用其已有值或 `√` 代替 PDF 原文证据。

- B–I 仍是身份列。J–P 不是身份列，而是按事实分级：有完整印章、核验结论和范围关联的
  `SEALED_CONFIRMED`；PDF 原文清楚且人物、栏目唯一对应，但无相应印章的 `SOURCE_ONLY`；
  原文或定位不确定的 `UNRESOLVED`。仅 J–P 的 `SOURCE_ONLY` 可注明状态后写入，不能因此
  推断“审批通过”或加资格 `√`；若用户本轮明确要求所有列一律只写盖章内容，则不启用
  `SOURCE_ONLY` 例外。
- J、K、O 的经历按事实逐项取证；M 的师德评价无章时可写原文但须标为来源事实；L 的
  “考核优秀”仍须人事方章和对应年份。N 的“正常申报业绩”是派生资格结论，不能照搬人工
  表中单独的 `√`。P 的工作量和教学效果分别核对；工作量有章不自动覆盖教学效果。
- 同一单元格混合盖章与无章内容时逐片段标状态。无章文字在 Excel 中须可见标为
  `〔PDF 原文，未见对应印章〕`；标记只属于展示层，不能拼进原始 `raw_text`、`quote` 或
  `fragments`。仍按本轮提示词选择复核或直接保存，不因无章而静默换路由。
- 当前 `TaskManifest` 的免审批范围固定为 `B:I`，`sealed_only=true` 会拒绝 J–P 无章内容，
  且当前字段契约不支持独立状态及展示标记。因此本次只细化 Skill，不能宣称已经具备
  端到端写入能力。不得关闭 `sealed_only`、扩大身份列或伪造审批引用；服务端加入受控
  逐字段/逐片段证据状态与 Excel 展示标记后，方可完成这些来源事实的保存和验收。

## 9. 2026-09-23 固定模板按列来源路由

专用 Skill 当时新增 A–AA 列来源路由；该文件已随 Skill 从当前插件移除，
覆盖“教学科研教授”工作表每个物理列、这份 25 页教授评审表的候选 PDF 页与栏目、跨页条件和无 PDF
来源的序号/资格审查/备注。该文件是每轮使用此模板前必须读取的候选定位表，不是事实或审批证据。

WorkBuddy 应先核对实际上传模板和 PDF 栏目，再优先复用同一 DocumentVersion 已有的页面结果；
宿主支持页码/区域识别时合并所需候选页做一次定向识别。版式或页数不同、审核意见跨页、目标栏缺失
时按栏目标题及相邻页扩大查找，不得把没扫描到当作没有内容。若用户要求填写 A–AA 几乎所有列，
候选页仍可能覆盖大部分 PDF；宿主只有整份提取接口时也无法仅凭 Skill 避免首次全文识别。

## 10. 2026-09-23 服务端受控写入契约

OCR 前由 MCP 只读 `structured_dataset_capabilities` 探测真实 API 是否支持
`sealed-item-template-v1`。专用任务同时冻结 `sealed_only=true`、物理 B:I 身份列与 J:P 来源事实
范围；真正可无章写入的列仅 J、K、M、O、P，L 和 N 不享受例外。
`source_only_fragments` 必须逐项引用 `fragments` 原文；同格混合状态的审批范围只覆盖盖章片段。
服务端逐字校验正式来源，在导出展示层给对应片段加
`〔PDF 原文，未见对应印章〕`，不修改原文、表头或其他列的盖章判定。

L 列年度考核方章使用 `approval_kind=HR_ANNUAL_EXCELLENCE`：来源 PDF/图片页面必须提交
带真实 bbox 与章内文字的 `SEAL` 区块，服务端核对同页“年度考核优秀”结论；只有文字没有可
定位印迹时安全失败。单元测试不能代替真实宿主和原页图像验收。
