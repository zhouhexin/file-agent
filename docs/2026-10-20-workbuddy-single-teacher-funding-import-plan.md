# 上传单人科研成果资助表，追加到教师成果明细汇总表

## 目标与样本

用户在 WorkBuddy 上传一份单人 `.xlsx`，按第 1 张“论文”和第 3 张“会议”工作表提取成果，把尚未登记的记录追加到已发布的《教师成果明细汇总表》同名 Excel。更新该教师的个人页及“汇总”页，保留目标原件、旧版本和其他教师的数据。成果明细正式发布后，默认继续用它的新版本刷新已发布的使用登记余额表；用户明确只更新成果明细时才跳过。现有完整成果表刷新余额表、图片使用登记追加与人工回传入口不改变。

样本《科研成果资助汇总表-温营坤.xlsx》有两条论文，当前目标个人页均已存在；会议页有一条 2020 年、1000 元记录，申请人、会议名称、地点为空。缺姓名时仅在本工作簿其他行唯一申请人且文件名中的姓名相同的情况下提出关联，预览明确标识，调用方须显式确认后才能发布；缺会议名称等字段保持空白，备注标待核对。样本确认后仅增该会议一行，个人页及“汇总”页总额从 21000 变为 22000 元。

## 服务端流程

1. 请求仅接受本轮已归档、当前版本且哈希相符的来源 `.xlsx` 快照，和目标完整 `.xlsx` 文件名；目标须在共享工作区唯一、处于活动状态。预览绑定目标当前版本 ID 与哈希，发布前重新核对，避免覆盖并发修改。使用现有认证、审计、版本及同名文件发布协调器，不接受客户端本地路径或自算金额。
2. 只读取来源第 1、3 张工作表；标题由固定列名校验。论文读取申请人、期刊、论文名、类型、发表时间、资助类型/类别、金额；会议读取申请人、会议名、地点、召开时间、是否 CCF、资助类别、金额。金额必须是有限、非负、最多两位小数且不超过十亿元；年份只能从明确的日期取得。无法确认姓名、金额、年份或目标人员时，该行仅列为待核对，不能改目标。
3. 按姓名定位目标“汇总”页与同名个人页。已有论文按成果名称识别：同名且其他主要字段一致则跳过，名称相同但金额/日期冲突时待核对。无会议名的会议按日期、金额、地点和资助类别判重；相同或有歧义时跳过/待核对，不重复计费。预览逐行返回新增、重复、冲突、待确认和金额变化。
4. 发布需要相同请求、预览指纹和显式的缺姓名关联确认。只插入可接受的新行，保留既有行与样式，重算该教师个人页“合计”、其“汇总”行的论文数、会议数、成果条数、各年度数量和资助总额，以及“汇总”页末尾的全体总计行。成果明细这一步不改其他教师或余额表；余额表在下一步单独受控发布。公式目标先拒绝，以免重存破坏公式缓存。
   来源文本及文本型序号写入前沿用现有表格防公式处理：以公式符号开头的内容加文本前缀，保存后仍须是普通字符串单元格。
5. 写入新的不可变 DocumentVersion，使用已有 StructuredDatasetExport 与发布协调器同步同名可见文件。稳定请求键幂等；重复上传内容由成果去重拦截。回执提供新增、跳过、待核对行数以及新版本与下载链接。没有可新增行时不发布空版本。

## 连续更新余额表（2026-10-21 调整）

WorkBuddy 在单人表追加成功后，从**已完成发布的成果明细表回执**取得文档 ID、新版本 ID 和哈希，把它当作余额表刷新来源。不能把上传的单人表直接当作完整成果表。余额表按用户给出的完整文件名定位；没给时先只读查找唯一已发布目标，不能猜。找不到或存在多个候选时，成果明细的成功结果保留，余额表明确报告未更新。

先冻结余额表当前版本，再调用现有资助总额刷新预览。只允许本次教师的预期资助额变化；待核对金额、其他教师变化或目标版本冲突时停止第二次发布。预览显示无金额变化时，不生成余额表空版本。核对通过后用独立请求键发布余额表：已有使用登记决定总支出，其他资助金额保持原值，首页和已有个人页都重新计算。两张表分别给出版本、下载链接和发布状态；若余额表失败，后续只重试余额表，不重新追加来源成果。用户明确说只更新成果明细汇总表时跳过本段。

这一调整只修改 WorkBuddy 技能编排和提示词，不新增 API 或数据库迁移。单人导入与余额表刷新仍是两次独立发布，不能宣称跨表原子成功。插件升至 `0.1.86`，重新构建的市场包为 `integrations/workbuddy/file-agent-marketplace-0.1.86.zip`，84001 字节，SHA-256 为 `520192e2a8c8d7e71f3c9e30d44b2af7d498959208812d3fae406ee59627bc65`；客户端 MCP 保持 `0.1.1`。

## 实现与验收

新增受控 API 与 MCP 预览/发布工具，扩展现有 `file-agent-research-funding-usage-balance` 技能路由；不改原有工具参数和行为。测试覆盖样本论文去重、缺姓名会议显式关联、个人页和汇总页合计、重复发布、目标版本变化、无效金额及原有来源同步流程。

## 实现记录与部署边界

- 新接口为 `/api/funding-usage/source-entries/preview`、`/api/funding-usage/source-entries/publish`；对应 MCP 工具为 `funding_source_entries_preview`、`funding_source_entries_publish`。来源和目标由服务端核验，预览本身不改文件；发布走现有版本与同名可见文件协调器，无数据库迁移。
- WorkBuddy 插件版本为 `0.1.85`，客户端 MCP 包版本为 `0.1.1`。市场包 `integrations/workbuddy/file-agent-marketplace-0.1.85.zip` 为 83197 字节，SHA-256：`1df8411c3fbe9cc07200c60e38cbda1db8a7b50456c97a5d6b3652996d036265`。服务器须部署本轮 API，用户电脑须更新 MCP 和 WorkBuddy 插件后才能实际调用。
- 用本机样本只读演算：论文两条为 `DUPLICATE`；未确认时会议为 `OWNER_CONFIRMATION_REQUIRED`；确认后会议为 `ADDED_REVIEW`，新合计 22000 元。保存到临时副本并重新打开后，个人页与“汇总”页该教师金额均为 22000 元，全体总计从 477500 元变为 478500 元，原样本未改动。
