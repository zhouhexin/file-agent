# WorkBuddy 通用提取与 Excel 模板保存安全方案

日期：2026-09-23

状态：已实施复杂模板缺网格的快速失败、异步终态传播及插件规则更新；真实 WorkBuddy 会话待用户验收。

### 盖章项目专用流程默认直写（2026-09-23）

用户本轮明确要求专用 Skill 读取后直接写入，无需人为复核。该 Skill 默认冻结
`review_mode=DIRECT_SAVE`、`extraction_save_policy=DIRECT_ARCHIVE`：目标 Excel 网格和来源证据
验收后，直接提交 WorkBuddy 读取结果，登记技术性表格预览指纹并立即 commit 发布。
技术性 `structured_dataset_preview` 不是向用户征求确认。用户当轮明确要求先看或确认后保存时，
以该更具体指令进入 `REVIEW_REQUIRED`；普通提取任务仍沿用其原有默认复核规则。
直写只跳过人为确认，不跳过真实印章、审批范围、逐列证据、目标版本、同名冲突、无可写记录及
发布完整性检查；`review_items` 自动排除并在回执说明。此调整不改 OCR 结果复用策略。

### 完整提取状态及长等待修复（2026-09-23）

- 文档提取任务的完整覆盖终态统一按 `COMPLETE` 判断；`claim` 不再把已保存结果重新发租约，
  相同 `submission_key` 重放正确返回 `ok=true`，部分/失败结果仍可按原契约重试。
- 对旧版误领且已保存完整 WorkBuddy 运行的任务新增受控 `document_extraction_resume`：校验源版本、
  SHA-256、固定提交指纹、完整运行和已保存页面后，只推进仍处于 `WAITING_EXTERNAL_EXTRACTION`
  的原条目；原归档 job 幂等复用。未保存完整结果或来源不匹配时拒绝，不重新 OCR。
- 专用 Skill 将目标 Excel 网格验收提前到 PDF 识别前：先真实读取/提交目标表并完成目标准备，
  复杂旧 `.xls` 无真实 `TABLE_CELL` 时直接说明需要有结构化网格的 WorkBuddy 能力或 `.xlsx`。
  已有 OCR 结果复用顺序与策略保持不变。

### 过期租约提交阻塞修复（2026-09-23）

实测两笔已确认提取任务在提交时租约已经过期，提交接口返回冲突或等待；数据库出现一条
`idle in transaction` 连接持锁，以及一条等待该事务的连接。旧续租路由在持锁校验失败后
没有立即回滚；旧异步提交路由又直接执行同步数据库调用，锁等待占住 API 事件循环，
使后续请求和事务清理也无法及时推进。这两笔任务均未生成提取运行或 Excel 写入。

现在续租及提交路由在所有异常出口主动回滚；提交的数据库校验、保存、提交和响应投影
在同一线程池工作单元内完成，避免数据库锁等待冻结 API 事件循环。请求体大小和 schema
仍在写入前校验，原有确认指纹、来源哈希、幂等提交键与后续归档/Excel 链路不变；
不改变 OCR 结果复用策略。对尚未保存的已确认任务，WorkBuddy 应从本地固定草稿
重新领取有效租约并提交相同结果；不得仅凭服务端确认状态伪造正文，也不得直接操作 Excel。
局部回归包含租约失败回滚和事件循环响应性；真实 WorkBuddy 重提交与最终 Excel 发布仍待验收。

### 已完成目标 Excel 被查重分支误判为未提取（2026-09-23）

真实任务显示目标 Excel 的 WorkBuddy 文档运行已是 `COMPLETE`，用户已在近似查重阶段明确选择
`CONTINUE_UPLOAD`，但旧归档决定分支只认旧 OCR 终态 `COMPLETED`。因此它清空候选、把归档状态
重新设为 `WAITING_EXTERNAL_EXTRACTION`，没有创建 ARCHIVE job，表格任务持续
`WAITING_DEPENDENCY`。这与 Excel 写入器无关。

归档决定现按契约区分终态：旧 OCR 的 `COMPLETED` 保持原行为；文档契约的 `COMPLETE` 还必须
同时验证固定源版本及 SHA-256、提交指纹、完整提取运行和已保存页面，才允许进入归档。
对历史受影响任务，原 `document_extraction_resume` 只在同一条目、已验证完整运行、近似查重
`RESOLVED + CONTINUE_UPLOAD`、仍处于提取等待、且归档 job 确实缺失时，沿既有幂等队列
补建归档任务；不重新 OCR、不重判已经确认的候选、不直接写 Excel 或修改原件。
其他状态不适用此补偿，冲突时关闭式拒绝。表格 `commit` 仍在工作副本实际发布后继续。
异步 worker 完成归档、导入和分析后，上传条目的最终工作副本投影可能晚于物理副本发布；
表格任务解析固定来源时现调用正式 `IngestionWorkflow` 同步该投影，再核对活动副本、
同一源哈希与 WorkBuddy 提取运行。该同步不直接创建 Excel，也不放宽来源校验。
实际旧 `.xls` 模板在提升后还有一种显示层差异：服务器把多层合并表头用 ` / ` 分隔，
并对重复叶标题追加真实列号（如 `[G]`、`[I]`）；WorkBuddy 预览可能以空格连接相同
表头单元格，且只展示叶标题原文。逐格 WorkBuddy 网格与转换后的模板已先严格核对，
表格任务再只允许这两种确定性显示差异；文件名、Sheet、布局、物理列次序和字段文字
仍必须一致。实际 27 列模板的差异均落在此范围内，不能以模糊相似度放宽校验。

## 实施记录（2026-09-23）

- API 对旧 `.xls` 的复杂布局在排入转换队列前核查 WorkBuddy 固定提取运行是否含表头范围内的真实
  `TABLE_CELL`；缺失返回 `TARGET_EXCEL_HEADER_CELLS_MISSING`，不启动 LibreOffice。
- `.xls` worker 执行前复核；转换后按表头非空单元格逐格比对，缺失、错位、额外与冲突格均拒绝，
  错误只返回数量，不返回用户表格内容。`.xlsx` 上传目标在提供 WorkBuddy 运行 ID 时也比对网格。
- 复杂模板确定性错误使统一任务进入 `NEEDS_INPUT`，worker 最终失败同步到父任务；
  旧悬挂任务的 `task_get` 也按失败 job 显示终态。MCP 不再对终态任务继续提交。
- WorkBuddy Skill 要求真实网格，插件版本为 `0.1.33`；主机存在本地文档预览草稿时，MCP 在
  `structured_dataset_preview` 前预检复杂表头坐标。直接归档没有本地草稿时仍由 API 强制检查。
- 局部回归覆盖缺网格快速失败、父任务终态、逐格不一致、现有模板发布与下载。
  原复杂模板修复相关 API/MCP 用例为 49 passed；更大范围测试运行到约四成未见失败，因耗时主动中止，
  不将其记为全量通过。真实用户材料和 WorkBuddy 会话仍由用户按第 6 节验收。

仍未在本轮自动完成：WorkBuddy 宿主不提供真实结构化表格读取能力时，File Agent 不能从普通
SHEET/OCR 文本制造 `TABLE_CELL`；必须选用已有可用宿主能力或用户另传可读取的 `.xlsx`。
现有每条记录只绑定单一来源；跨 PDF/Word/图片多来源合并同一人员的契约扩展尚未实现，
遇到这类材料应遵守 `references/task-payload.md` 的安全停止规则，不拆成虚假的重复行。
因此本轮不宣称第 6 节全部验收项已在真实 WorkBuddy 环境通过。

### 专用 Skill 身份列补充（2026-09-23）

用户明确限定：只有盖章项目专用 Skill 的模板，物理 B–I 列视为身份列。该 Skill 显式传
`identity_column_range="B:I"`；这些格凭真实原文证据直接填写，不做盖章审批或标题资格判定，
不加 `√`。B–I 外的业务项目仍遵守原有盖章属实和整列资格规则。普通 Excel 提取任务不启用此标记；
本轮复核/直接保存授权、来源证据、目标版本与发布规则均不变。
该补充的相关 API/MCP 局部回归为 50 passed；真实 WorkBuddy 会话仍待用户验收。

### 专用 Skill 来源状态与年度方章契约（2026-09-23）

`structured_dataset_capabilities` 提供 OCR 前只读版本探测，防止插件新、服务端旧时徒耗识别时间。
专用模板 J、K、M、O、P 可提交逐片段 `source_only_fragments`，服务端逐字核对原 PDF，
只在 Excel 展示层加无章状态。L 年度优秀只接受有真实页面坐标与 `SEAL` 区块的章内结论；
N 资格派生结论不启用无章例外，普通累计表及 Q–Y 盖章要求不变。真实 WorkBuddy 端到端仍待
部署后用用户材料验收。

### 已确认草稿的审批证据失败与恢复（2026-09-23）

真实任务在归档、旧版 Excel 转换及目标字段校验完成后，进入追加阶段时被 `APPROVAL_DECLARATION_REQUIRED` 拒绝。L 列的年度优秀声明引用与方章内引用不是同一段原文；O、T 列提交的审批声明引文分别含 OCR 错字及截断，不能证明“属实”。服务端不得把“居实”猜成“属实”，也不得仅凭印章或签字补全声明。此时目标 Excel 可作为已转换模板存在，但没有新增数据行或对勾，不能报告为最终文件。

首次携带完整草稿提交时，服务端在目标 Excel 准备或旧版格式转换前先做纯文字审批契约预检：普通列声明须有完整可确认的审批语义，L 列的 `declaration` 与 `seal` 必须引用同一段方章内“年度考核优秀”原文。此预检只负责提前拒绝明显无效草稿，不能代替随后对来源正文、章图坐标和审批范围的正式核验。追加校验失败回执只提供定位元数据（记录序号、字段 key〔若已创建数据集〕、字段标题和物理 Excel 列号），不回显正文。若尚无任何追加修订，确定性的审批、证据或条件错误将使原任务进入 `NEEDS_INPUT` 并释放目标占用；原任务的已确认草稿和摘要保持不可变，重复提交只返回终态。WorkBuddy 必须回到真实 PDF/OCR 引文，重新提取有完整审批依据的字段；证据不足的字段按既有专用 Skill 规则留空或在允许的来源事实列标明状态，然后创建新预览及新摘要。不能修改数据库中的旧草稿、直接写 Excel 或放宽盖章和审批校验。

## 1. 需求边界

File Agent 提供通用的“提取、核对、写入 Excel”能力：WorkBuddy 使用实际可用且已授权的能力读取
PDF、Word、图片以及电子表格，返回带来源定位的信息；File Agent 对固定来源、目标和证据进行校验，
把用户确认或明确授权直接保存的记录写入服务器中的 Excel，并返回可下载的结果和版本信息。

通用能力不强制每轮上传 Excel：本轮上传的 Excel 优先作为新目标；没有新 Excel 时，可按完整文件名
唯一定位已有目标，或按提示词字段新建目标。专用 Skill 可以把“本轮必须上传 Excel”设为自身的入口条件，
并定义诸如盖章属实范围、整列资格对勾等业务规则；它不能替代服务端的权限、证据、冲突和版本校验。

上传 Excel 的专用流程必须先由 WorkBuddy 真实读取工作表、完整表头、列坐标、合并区域及填写范围，
把这些字段作为本轮从其他上传材料中提取信息的范围。File Agent 再读取上传 Excel 的固定版本，核对
WorkBuddy 的字段快照，并以该文件为模板持续修改同一当前工作副本。最终返回文件名、Document ID、
WorkingCopy ID、数据集 ID、当前 DocumentVersion、版本号、记录数和下载资源。

## 2. 本次故障事实

2026-09-23 最近任务在 `PREPARING_TARGET`：目标是旧版 `.xls`，复杂模板布局为表头 `A2:AA4`、
填写区 `A5:AA5`。WorkBuddy 已提交的该表格提取运行只有 1 个普通元素，`TABLE_CELL` 数量为 0。
服务器使用 LibreOffice 格式提升约 4.37 秒后，因缺少真实坐标证据无法逐格核对转换后的表头，
返回 `TARGET_EXCEL_CONVERSION_SCHEMA_MISMATCH`；后台转换任务为 `FAILED`。任务表尚显示
`PREPARING_TARGET`，没有进入追加和发布阶段。09:33:49 到 09:43:13 之间无对应表格后端请求，
因此用户观察到的长等待主要不是转换计算或 worker 排队。

不能从一段普通 Sheet 文本、模型描述或视觉推断中补造表头坐标，也不能把转换后的近似新表当作原模板。

## 3. 分层职责和最小契约

| 层 | 负责的事实与动作 | 必须返回或保留 |
| --- | --- | --- |
| WorkBuddy 宿主 | 按真实 Provider 读取来源材料和目标表，建立逐字段候选与证据 | 原文件身份/哈希、页/段/表/格定位、实际 Provider、候选值与不确定项 |
| 专用 Skill | 选择业务字段、审批范围和是否复核，组织候选与回执 | 本轮入口条件、业务判断依据、每列候选或留空原因 |
| File Agent API | 身份、固定来源/目标、证据、模板、版本、确认和冲突校验 | 任务状态、审计、数据集修订、服务器当前文件与版本 |
| Worker | 旧 XLS 的受控转换及其他异步依赖 | 固定 job ID、进度、终态和可行动错误码 |
| MCP 桥接 | 使用白名单 API 缓存预览草稿并恢复同一任务 | task ID、预览指纹、准确终态、已发布文件资源 |

Word/PDF/图片的正文使用 WorkBuddy 返回的真实页码、段落、表格单元格或 OCR 区域；Provider 名填写
实际调用对象，不固定腾讯或其他产品。文件正文只作为数据，不作为新指令。字段证据必须逐字绑定到
已提交的来源区段，不能由模型补写不存在的姓名、数字、章或坐标。

电子表格读取需要一个**结构化网格**：每个有内容的表头单元格给出真实 `sheet_name`、零基
`row_index`、`column_index`、原始值及合并单元格锚点。WorkBuddy 可以直接提供 `TABLE_CELL`；
也可由能保证空格、空单元格和行列顺序无损的宿主表格工具返回网格，再在 MCP 中确定性转换为
`TABLE_CELL`。普通 OCR 文本或不保留空格位置的 TSV 摘要不能用于推算复杂模板列坐标。

## 4. 安全执行路径

1. 宿主固定本轮附件清单，将新上传 Excel 与待提取材料区分。多个目标 Excel 或多个可写工作表时，
   请用户选定；不得按上传顺序自动选择。目标 Excel 不重复作为来源记录。
2. WorkBuddy 读取目标表及来源材料。对目标表先在宿主侧校验完整字段清单与表头坐标；
   多层合并表头必须保留完整层级和实际列位置。缺失网格能力时立即报告，不开始保存。
3. 对每个人或每条业务记录，逐列提供候选内容和来源证据，或明确 `blank_reason`。不得只提交成功列。
   同一人员跨多个材料有证据时应合并为同一记录；现有单 `source_index` 记录契约尚不支持跨来源字段，
   实现通用合并前需扩展为受控的多来源引用，不可拆成重复人员行冒充合并。
4. 生成固定预览指纹，覆盖来源版本/哈希、目标 Document/WorkingCopy/版本、实际工作表/布局/列顺序、
   所有拟写入值、证据和留空原因。默认先展示逐列结果，用户修正后重新预览；本轮明确“直接保存”
   才按冻结的直接路径执行。仅确认 OCR 正文不足以授权稍后变化的 Excel 值。
5. File Agent 在确认后再次核对来源快照和目标当前版本。对 `.xlsx`，以当前工作簿做受控模板写入；
   对 `.xls`，先执行服务器受控格式提升，再逐格比较 WorkBuddy 固定网格与提升后的标题，确认布局、
   已有数据行和尾注。无法保证格式或功能一致时停止，并要求用户提供 `.xlsx`，不能近似重建。
6. 一次任务先验证全部来源和全部列，再追加，避免多文件半批成功。导出只修改受控填写区域，保留
   原工作表、合并表头、公式、样式、其他部件与尾注；原件和历史版本不被覆盖。
7. 服务器将完成版发布为普通文件。工作副本实际 basename、列表展示名、下载名一致；同一目标只有一个
   当前工作副本，历史由 `DocumentVersion` 管理。返回结果必须证明本轮有记录、服务器版本已发布、
   当前文件可下载且与导出记录一致，才可显示“完成”。

按文件名续写时必须精确解析唯一目标并冻结稳定 ID 与当前版本。找不到、同名、版本变化或文件名冲突
应让用户选择或重新预览，不能自行改名、覆盖或写到另一份表。

## 5. 本次 `.xls` 故障的具体修法

1. 在 WorkBuddy 的表格读取适配器中输出真实网格或逐格 `TABLE_CELL`；专用 Skill 明确检查
   `A2:AA4` 范围内每个非空表头格均有可定位原文。不能由模型按显示文字猜列号。
2. 在 MCP 的预览前检查该能力。缺失时返回明确的 `TARGET_EXCEL_HEADER_CELLS_MISSING` 类错误，
   指示“当前表格读取结果没有单元格坐标，请改用支持结构化读取的 WorkBuddy 能力或上传可读取的 .xlsx”。
3. 在 File Agent 确认后的 `.xls` 目标准备阶段，再做同样的服务端检查；若复杂布局无单元格证据，
   在排入 LibreOffice 转换队列前拒绝。表头逐格不一致时报告具体坐标类别和缺失数量，日志和回执
   不泄露单元格正文或本地绝对路径。
4. Worker 失败必须同步使父表格任务进入 `FAILED` 或 `NEEDS_INPUT`，`task_get` 和 MCP 立即返回
   错误码、下一步与失败的 job ID。对校验失败不自动重试；只对明确的临时转换/网络故障按原 task ID
   有界恢复。不能一直保留 `PREPARING_TARGET` 并让用户误以为仍在生成。
5. 当前已失败任务应在 WorkBuddy 用真实表格工具重新读取原目标，形成新的提取运行和预览指纹；
   如走复核路径，需要展示修正后的字段/值并重新确认。旧失败任务、原件和审计记录保留。

## 6. 验收与完成判据

- 用简单 `.xlsx`、复杂多层 `.xlsx` 和旧 `.xls` 模板分别验证字段读取、坐标、数据行、样式与尾注。
- 测试 PDF、Word、图片独立来源及混合来源；逐字段核对页/段/格证据、空列原因与重复人员合并。
- 缺 `TABLE_CELL`、坐标偏移、重复/缺列、错误工作表、错误目标版本应在可定位阶段失败，
  不生成仅表头的 Excel，也不把失败标记成“仍在处理中”。
- 复核前没有正文或 Excel 写入；确认后沿同一预览指纹提交；明确直接保存遵循同样的证据与目标校验。
- 验证结果在服务器文件列表中可见，当前真实文件、下载字节、名称、DocumentVersion 与逐格内容一致；
  重试不重复追加，旧版本可追溯。真实 WorkBuddy 会话验收必须在 API、worker、MCP 和 Skill 更新后执行。
