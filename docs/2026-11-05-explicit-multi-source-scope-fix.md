## 修复加入哪个环节

```text
明确列出《完整题名》和正式文号的只读请求
→ 保留原问题，生成 evidence-answer 声明式计划
→ 原有白名单Tool分发与schema校验
→ 服务端核对共享工作区的ACTIVE副本及其当前版本
→ 两份来源全部唯一匹配后，固定真实Document ID
→ 原证据加载 → EvidencePackage → Shadow及可选采集 → 原回答
```

这是采集前的文件范围修复，不是根据评估结果补检或改变答案的策略。普通主题描述仍走原有理解与检索流程。

触发范围仅支持以“根据/依据”开始、在只读要求前逐份给出2至8个书名号题名且每份附带一个正式文号的请求。标题中的嵌套书名号允许保留。包含删除、移动、改名等操作时不会套用该规则。

后端要求完整题名和正式文号同时匹配同一个真实文件名称；名称可以来自活动工作副本、其当前版本或原始上传记录。只有当前版本绑定正确且位于授权共享工作区的ACTIVE副本参与匹配。候选上限内无法确认唯一、缺少任一来源或存在重复时，停止自动读取并请求补全或选择；不拿部分命中冒充两份材料，也不把原问题重新当作全库搜索词。用户已确认的选择范围保持锁定。
