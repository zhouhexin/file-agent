# WorkBuddy L 列从 PDF 末页向前定位的方案

> 已被[固定第 25 页方案](2026-10-08-workbuddy-l-fixed-page25-plan.md)取代。以下保留 v3 历史契约说明；新签发任务和当前 Skill 使用 v4，不再执行倒序找页。

日期：2026-10-08  
状态：已实现并完成本地 API/MCP 回归；2026-10-08 补上旧 v2 未完成任务的受控升级。真实 WorkBuddy OCR 与部署后的耗时、费用仍待实测。

## 1. 需求与现状

`file-agent-a-i-scoped-excel` 填写教授业绩汇总表时，B–I 身份任职信息仍按受控来源提取；物理 L 列“考核优秀情况”应从每份 PDF **实际最后一页开始，按页码递减**查找“任现职以来的考核情况”栏目，找到真实栏目后读取其中明确为“考核优秀”的年度，升序去重写入 L。找到后停止向前查找；只出现“合格”等结论时 L 留空并记录 `NO_EXCELLENT_YEARS`；识别不清时标记 `ANNUAL_REVIEW_UNREADABLE`，不为提高准确率反复 OCR。不能从文件名、样例或其他业绩栏目推断年份。

现有 `ScopedPdfExtractionService.prepare_for_ingest_item` 把 `annual_review.page_number` 写成 `page_count`，并按 25 页或 22 页版式固定末页裁剪框；`scope_digest`、区域 PNG 哈希、`ScopedSubmit` 与正式 `DocumentPage` 都依赖这份冻结清单。因此只改 `SKILL.md` 无法让 WorkBuddy合法提交倒序找到的其他页，必须同时调整 API/MCP 的受控定向任务契约。B–I 的第 1、3 页及现有版式校验先保持独立；本改动只让 L 的来源页动态确定，并不承诺任意版式的 B–I 都可自动读取。

## 2. 倒序定位流程

1. 服务端以当前 PDF 版本、SHA-256、实际页数签发新版本的定向任务；B–I 区域照常冻结，L 先记为 `DISCOVERING`，不预设第 25 页或任何固定页码。旧任务仍按原冻结范围运行，不能在处理中悄悄改页。
2. 先由服务端对 PDF 原生文本层按末页到首页寻找栏目标题；命中时仍验证页码、栏目位置和真实年度正文。文本层不存在或不足以定位时，服务端每次仅向 WorkBuddy 发放**一个**倒序候选页的低分辨率定位图与哈希。WorkBuddy 用现有 OCR Provider 定位标题，回传真实 OCR 文本、可得的文字框、Provider 信息和本页结论；服务端核对当前页、租约、哈希和标题。没有标题则签发前一页，不能跳页、并发预读后续页或把整份 PDF 发给 OCR。
3. 只有完整标题“任现职以来的考核情况”位于正文栏目、且栏目边界可界定才算找到；目录、页眉或孤立标题不算。文字层或定位 OCR 命中后先暂定 L 页，核对正式栏目裁剪图确含真实正文才停止向前查找；误裁剪可凭图像 SHA 退回并继续前一页。若确认真实栏目可见但文字不清，则标记 `UNREADABLE` 并停止，不继续寻找别的年度来替代；栏目确实空白或只有非优秀结论时，L 留空并记录相应原因。
4. 根据 OCR 标题文字框或 PDF 文字层标题坐标冻结该页的栏目裁剪框，再读取栏目。若定位 OCR 已提供完整、可定位的栏目文字且裁剪图核对完整，可直接复用，不再付费读取同页；否则只 OCR 一次栏目裁剪图。候选页 OCR 正文不写入服务端长期索引或 L 证据，正式提交只保存栏目文本。对于扫描件，`section_confirmed=true` 必须带真实标题坐标；坐标受单行标题尺寸约束。
5. 沿用现有 `annual_review_precheck.py` 对**将提交的栏目文本**做受限标点归一、人工核对和 `verify`；`years` 与服务端 `excellent_years()` 的结果须列表全等。然后同轮提交 B–I 与动态 L 区域，服务端从正式回读的冻结 `field_refs` 校验证据并写回，J、K、M–AA 仍不处理。

## 3. 服务端与 Skill 契约调整

- 新建独立契约版本，例如 `workbuddy-scoped-pdf-v3`：任务先有 `REVIEW_DISCOVERY` 阶段，增加“领取当前候选页／提交定位结果／获取下一页或冻结栏目”的受控 API 与 MCP Tool。服务端掌握页码递减顺序、单页图像渲染、SHA、租约和幂等键；模型不得自造页号或改写任务清单。
- 找到栏目后，服务端将真实 `annual_review.page_number`、`bbox`、定位依据和发现时已检查的页码写入任务清单，重新形成不可变 `scope_digest`。正式 `scoped_pdf_source_submit` 仍只接受冻结的 B–I 与 L 区域及对应 PNG 哈希；`DocumentPage`、来源回读和写回证据使用真实物理页号。若查至首页仍未找到，新契约应提供可审计的 `NOT_FOUND` 终态与 `ANNUAL_REVIEW_NOT_FOUND` 留空原因，并让写回闸门只接受该终态的空 L；不能伪造一个考核区域或把别处“优秀”写入 L。旧 v1/v2 已签发任务保持原契约，不迁移运行中的页号。
- `SKILL.md` 改为逐页处理服务端签发的倒序定位图、命中即停，并保留提交前归一门禁；回执写出 L 实际页码、检查过的页数、OCR 调用次数与留空原因。不得描述为“固定末页考核区域”。
- 优先复用现有任务与来源清单 JSON、页证据和审计字段；实现时若现有 JSON 无法稳定表达定位租约、进度或幂等恢复，再单独提出数据库迁移，不能在方案阶段承诺绝对无需迁移。

## 4. 时间、费用与失败边界

先用 PDF 文本层；扫描件才按末页向前逐页调用定位 OCR。找到就停；同一来源版本、候选页图像哈希与 Provider 结果在允许的权限范围内缓存，恢复任务时复用，避免重复 OCR。定位页使用能可靠识别标题的最低可用分辨率；具体成本须按实际 OCR Provider 的计费单位实测，低分辨率不必然降低单页价格。最坏情况下标题缺失，仍可能检查全部页面；到第一页仍未找到时返回 `ANNUAL_REVIEW_NOT_FOUND`，不得伪造 L 值或把其他页面的“优秀”当考核结果。

定位 OCR 可能碰到该候选页的其他文字，这是未知栏目位置下不可完全避免的查找成本；这些文字只用于判断标题和位置，不当作其他列的来源，也不进入长期全文索引。若标题位置无法界定、Provider 无法给出足够的文字或图像证据，停止该来源并报告具体原因；不得擅自切换整篇 OCR 或无限扩大裁剪范围。服务端仅保存已查页码、状态、Provider 名称及栏目范围，不保存定位页的 OCR 全文。

## 5. 落地与部署

实现位于 `apps/api/app/modules/external_extraction/scoped_service.py`、`scoped_router.py`、`scoped_schemas.py`，MCP 的 `scoped_pdf_tools.py`、`scoped_pdf_types.py`，以及 `file-agent-a-i-scoped-excel/SKILL.md`。新任务使用 `workbuddy-scoped-pdf-v3`；旧 v1/v2 冻结记录本身不改写，未完成的 v2 可按下文重签为新 v3。发现进度、当前页、已查页、真实 L 页和范围保存在既有 `source_manifest_json`，本次无数据库结构迁移。部署时需同时更新 API 与 MCP、重启相关服务，并让 WorkBuddy 重新装载新版插件。单独替换 Skill 无法启用倒序探测工具。

本地回归覆盖末页命中、跳过末尾两页后命中、查至首页仍未找到、正式 `DocumentPage` 页码、来源回读及 Excel 写回。真实 OCR Provider 的标题框、目录误命中、识别模糊和实际计费仍需在 WorkBuddy 使用真实 PDF 验收。

## 6. 已签发 v2 任务的补救

实测三份 22 页 PDF 的任务均被服务器签发为 `workbuddy-scoped-pdf-v2`；现有记录无法单独判定这是部署版本未更新，还是任务签发早于更新。旧任务领取时直接返回三张区域图，其中 L 固定在第 22 页；新 Skill 无法只凭升级插件改变旧任务的冻结范围。服务日志中这三份任务没有候选页 OCR 探测，WorkBuddy 会话记录确认其契约均为 v2。这是本次第 22 页误裁剪的直接原因。

对尚未完成、来源版本与 SHA 未变化且仍绑定原任务的 v2，新增 `POST /api/integrations/v1/scoped-pdf-sources/{task_id}/review-discovery-upgrade` 与 MCP `scoped_pdf_review_discovery_upgrade`。服务端在同一归档来源上签发 v3 任务、把条目绑定到新任务、作废旧租约并把旧任务标为 `SUPERSEDED`；重复调用返回同一 v3 任务，不重新上传 PDF，也不修改旧任务的已冻结历史。WorkBuddy 必须先 `scoped_pdf_source_get` 检查契约，遇到未完成 v2 就升级，然后只用新 `task_id` 领取和提交。已完成的 v2 不自动改写，须单独处理；旧任务被替换后无法再领取或提交。

v3 文字层或定位 OCR 也可能误命中页眉、孤立标题，或者标题坐标导致裁剪图落在签字/审批区。工作端下载正式 `annual_review` PNG 后必须核对图中确有完整考核正文；若显然不是，使用 `scoped_pdf_review_region_reject` 回传当前图像 SHA 与 `HEADING_ABSENT` / `SECTION_OUTSIDE_CROP`。服务端核对租约与哈希，作废该 L 区域，从其前一页恢复 `DISCOVERING`；查到首页则记 `NOT_FOUND`。同一退回键幂等，错误哈希拒绝。真实栏目只有“合格”或字迹不清时不得退回以寻找其他年度，仍按原栏目结果留空。正式提交只能引用最后一次核对过的当前 `scope_digest`。

## 7. 验收

用可控样本分别验证栏目在末页、倒数第 2 页、倒数第 3 页、仅有目录标题、完全缺失及已命中但文字不清；断言候选页严格递减、核对真实栏目后不再 OCR 前页、正式证据页码与工作簿 L 值一致。验证混合“优秀／合格”只写优秀年度、受限标点归一仍通过原有门禁、同句多个年份的证据按偏移去重。再检查中断恢复不重复计费、未完成 v2 受控重签、错误裁剪图退回与旧租约失效、同轮多份 PDF 各追加一行并只发布一个 Excel 新版本。最后在 WorkBuddy 实测定位 OCR 调用数、用时和费用，不预设固定节省比例。
