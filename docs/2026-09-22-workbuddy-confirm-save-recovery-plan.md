# WorkBuddy 确认后未保存、耗时与复杂 Excel 模板修复

## 已核实的问题

本轮真实调用有多次过期租约和参数校验失败；最终仅完成正文确认，没有成功提交正文，
也没有调用服务器数据集追加和导出。宿主另行生成本地表格不能代表服务器保存成功。
真实模板含三行合并表头、27 列、预留填写行及尾部说明；原先单行表头和末尾追加算法不适用。

## 实现边界

1. MCP 在宿主本地保存通过校验的正文草稿。预览仍只向服务端发送摘要和指纹，确认前不保存正文到服务器。
2. 预览在宿主缓存原始结果，增加短参数草稿提交入口，按原指纹重用正文；确认后的提交不再让模型重新生成长 JSON。
   租约失效只允许同一任务、Worker、来源版本和哈希的受控重新领取，不得改变正文或绕过确认。
3. 正文确认和正文保存是两个状态，正文保存和 Excel 发布也是两个状态。回执必须明确下一步；
   没有真实 export 回执、文件名、版本、已确认记录数，不能声称 Excel 完成。
4. 复杂 Excel 显式绑定表头范围和填写范围。多层合并表头按真实列映射生成字段；不把首行大标题当字段，
   不把尾注当数据。支持宽表和长表头；预留序号可以保留，其他非空值及公式不得覆盖。
5. 数据写入指定填写区域中的空闲行，保留模板其它 OOXML 部件。区域不足必须报错，不得写到尾注下。
   简单表格继续保留已有追加行为。布局随稳定数据集保存，并参与续写时的当前文件校验。
6. Skill 禁止用本地办公工具写入替代服务端累计表；源文档可由任意已授权 WorkBuddy 读取 Provider 读取。
   同一错误至多修正重试一次，随后报告精确阻塞，不能持续消耗租约。

## 验证

- MCP：草稿重启恢复、指纹一致、来源不符拒绝、过期租约恢复、确认前正文不发往服务端、失败不得返回保存成功。
- 服务端：三层合并表头/27 列/长标题/重复叶标题/预置序号/尾注；写入预留行、满表拒绝、模板包保真。
- 回归：旧简单表、XLS 异步转换、确认策略、幂等导出、同名冲突、版本及文件名一致性。
- 真实 WorkBuddy 需要升级插件并重建 MCP 会话后复测；自动测试不能代替真实宿主验收。
