# WorkBuddy 教师引进考察汇总表填表方案

日期：2026-10-09  
状态：已按本方案加入共享目录资源、部署导入命令、只读查询、教师引进列内受控展示契约和 Skill；本机尚未连接服务器完成目录导入或 WorkBuddy 真实会话验收。PDF/Office 原件和既有 Excel 均未修改。

## 一句话说明

用户把考察材料交给 WorkBuddy。WorkBuddy 先看本轮是否上传目标汇总表：只要上传了，无论首次还是后续，都以这份新表的真实列和已有内容为准；没有上传目标表时，才按完整 `.xlsx` 文件名找到已发布表并追加。每位新教师一行，按已填写汇总表的列内格式组织信息：学习经历分博士、硕士、本科且阶段间空一行；论文题目、刊物及收录情况逐篇用相同序号对齐；期刊等级依据**开发部署阶段已放入系统共享参考目录的** 2019 版目录和有证据的分区信息判断。该目录可供多个 Skill 调用，用户执行填表时不必上传。没有可靠信息的格保持空白。用户下载表格并手工补充后，可以再上传为同一张表的新版本。

本文暂按“**一位教师一行；同一人的多份材料合并到这一行**”设计。这个判断来自汇总表的用途，不从文件名直接认人。若实际业务要求“每份文件各一行”，实施前改这一条即可，后端归并工作也会减少。

文中的“证据”就是能指出值出自哪份文件的哪页、哪个表格单元格；“已发布版本”就是服务器上可下载的那一版 Excel；“原件不覆盖”表示用户交来的文件字节保持不变。

## 用户实际怎么操作

### 本轮上传汇总表：以新表填入本轮材料（首次和后续都适用）

1. 用户在 WorkBuddy 上传目标汇总表 `.xlsx`，同时明确指定已授权的本地“测试文档”目录；也可直接把人员考察材料作为本轮附件上传。`2019版学术期刊A++、A+,A,B类期刊目录.xls` **不属于每次填表必传的附件**：开发部署时已单独放入系统共享参考目录，运行中的 Skill 只读引用。若授权来源目录里也包含该 `.xls`，固定文件清单仍可记录它，但须从人员来源和 `source_indices` 中排除，不能借这次填表替换系统启用版本。若使用本地目录，WorkBuddy 先通过已有 `file_batch_ingest` 导入固定文件清单。该工具要求预配置的 `source_root_ref` 和相对目录；不能把聊天里的绝对路径直接当成任意文件读取许可。目录未获授权时，应提示用户配置受管根或上传本轮所需人员材料。
2. 文件助手读取本轮**上传的那份** Excel 的所有真实工作表、合并表头、列序、样式、预留数据区和已有内容。两份已检查的目标样本都包含“应届”工作表及 A–T，但新样本已经有第 5、6 行；必须先扫描现有人员和单元格，不能把有数据的表按空模板处理。若以后用户换模板，仍以当轮上传表为准，不把样本列名硬写进程序。多个可能的目标工作表且无法唯一判断时，请用户选表，不擅自选第一个。
3. 来源材料与目标表分别固定文件 ID、版本和哈希，完成真实读取后才形成待写行。必须将本轮上传目标的归档 `document_id`、`document_version_id`、`extraction_run_id` 连同真实工作表和布局传给 `excel_writeback_checkout`，由其先注册新目标；不能只传文件名，否则会误走旧累计表查找并在首次上传时报 `TARGET_EXCEL_NOT_FOUND`。如果服务器已有同名已发布目标，仍使用本轮上传的新模板创建新目标；新表发布成功后按既有规则归档旧目标，不把旧表数据偷偷追加进新表。
4. 先按来源正文确认人员身份，再检查目标已有人员；已有同名人员时按当前保护规则停止该人员新增并报告，不能为了展示新格式覆盖样例行。新人员的字段先套用下文格式规则，再形成待写候选。默认在来源证据、目标版本和写入候选通过校验后直接发布；只有用户明确说“先让我看/确认后再保存”才暂停等待复核。来源上传遇到重复文件时仍按既有流程让用户选择，不能替用户决定。

### 本轮未上传目标表：按完整文件名追加

只有本轮没有上传目标 Excel，用户才仅提交新的来源材料或指定新来源目录，并在任务文字中写出已发布目标的**完整实际文件名**；例如使用新样本时须写完整的 `西安理工大学教师引进考察汇总表-计算机学院（续兆攀、左逢源）-20260706(1).xlsx`，不能拿旧样本名或相似名替代。服务器按完整文件名唯一查找活动工作副本，读取它**当前版本**的表头、布局和已有人员；只对新人员按下文格式追加行，最后发布同名 `.xlsx` 的新版本。找不到、匹配多个、版本变化或发现同一批材料已经处理时停止并说明，不能靠相似文件名猜测或生成第二张表。后续若重新上传 Excel 并附新来源，仍回到上一节，以本轮上传的新表处理。

### 手工补充后回传

继续使用现有 `file-agent-manual-excel-revision`：先按完整文件名下载当前已发布版本；用户在本机补充已有行后，上传同名 `.xlsx`；服务器校验编辑前基线、文件结构和版本，把修改发布为**同一张表**的新版本，旧版本保留。这个流程只处理用户亲自编辑后的回传，不因本次输出格式方案而改变。

## 每份材料怎样变成表格中的值

1. **只读一次并复用结果。** `.xlsx` 读取真实工作表和单元格；旧 `.xls` 由服务器在隔离区受控转成可读的 `.xlsx` 派生件，原件不覆盖。PDF 先检查文字层能否可靠找到栏目；不能时只对本任务需要的页面/栏目做 OCR，保存每页结果供本次所有列复用。不能为了某一空格反复 OCR 整份文件。DOC/DOCX 若后续出现，也走现有正式正文读取。每个值都带来源文件和 PDF 页码或表格单元格位置。
2. **先认人，再合并。** 默认每位教师一行，不按论文条数或文件数拆行。依据正文姓名及必要的身份线索识别同一人，不能仅凭文件名合并。多份材料属于同一人时，合并其可核对字段；同一字段在来源中相互矛盾时留空并在回执列出双方证据。目标表已有人员沿用重复保护，不复制样例行，也不因同名再追加一行。
3. **先取事实，再按列格式化。** A 由目标表已有序号续排；B–H、Q–T 按真实表头和来源明确值取数；I 按学历阶段整理；J–L 和 M–O 按同一事项序号并列；P 按实有条目整理。汇总表已有行只提供输出格式参考，不是其他人员的数据来源。年龄、是否符合条件和引进方式等需计算或判断的值，除非来源明确给出或用户提供获授权规则，否则留空。详细输出规则见下一节。
4. **找不到就空着。** 来源缺字段、文字不清、相互矛盾或无法可靠对应目标列时，Excel 中留下真正的空单元格，不写“未找到”“待核对”或猜测值；分类依据不足时只留该篇的学校等级部分为空，已经可靠取得的论文题目、刊物和其他收录事实可以照填。回执另外说明每个空格的原因。写回工具只接收确认有证据的非空列键，不依赖模型传 `null`。若人员身份无法确认，则不创建无名行。
5. **不动原件和旧数据。** 来源文件与上传模板的不可变原件不覆盖；新增行只改目标工作表允许的数据区，保留标题、合并单元格、列宽、行高、隐藏列、原有单元格格式和其他工作表。旧空模板样本的 O6 `.` 必须保留；新两人样本的 O6 本来为空，不能凭旧样本补 `.`。如果行插入会碰到无法安全移动的内容，停止写入并报告，而不是覆盖。

## 列内输出格式：按已填写汇总表执行

| 物理列 | 输出规则 |
| --- | --- |
| A | 由写回工具按目标表当前最大有效序号续排；不能从考察表拷贝序号。 |
| B–H | 学院、拟补充学科、系所、姓名、性别、年龄、政治面貌各占本列一个普通值。学院全称与汇总表简称不一致时按来源真实值并在回执提示，不凭样例自动缩写。G 年龄只有来源明确值或获授权算法时才填。H 虽可隐藏，仍按真实表头处理并保持隐藏属性。 |
| I | 固定顺序**博士 → 硕士 → 本科**。每阶段依次写 `阶段：毕业时间`、`毕业院校`、`专业`，阶段之间恰好一个空行（两个换行符），尾部不多加空行。只取学习经历的结束时间作为“毕业时间”，不把入学时间误填进去。若博士信息存在但硕士阶段未填写，则中间阶段写 `硕士：硕博连读`；本科或博士自身缺少的事实不编造。 |
| J | 每篇论文一项，按来源顺序从 `1.` 开始连续编号；一篇占一个条目，条目间换行。英文题目里的句点、冒号、连字符不作为拆篇依据。 |
| K | 与 J **共用论文序号和顺序**：每篇写来源明确的 ISSN/刊号、刊物或会议名称、本人角色（如 `1/5`）。缺哪一项就省略该项，不写“无”；整篇的 K 信息均缺失时不输出空的 `n.`，后续有值的篇目仍沿用 J 的原序号。会议材料没有 ISSN 时不为它造 ISSN。 |
| L | 与 J/K **共用论文序号和顺序**：逐篇读取来源“收录与被引用情况及期刊影响因子等”中的 SCI/EI、分区、CCF、IF、被引次数等事实，再按下文规则判定本校期刊等级或经 WorkBuddy 搜索核定 CCF 等级。学校等级与 CCF 等级分开呈现，不能把 `CCF A类` 直接改写成 `A++类`。某项缺证据只省该项；整篇 L 信息均缺失时不输出空的 `n.`，不能用前一篇或下一篇的等级填补。 |
| M–O | 从同一份项目条目清单生成三列：M 写立项号和项目名称，N 写项目级别和本人角色，O 写完成状态。单项目也从 `1.` 编号；多项目同号对齐，项目间空一行。某项目在某列缺值时，不输出孤立的 `n.`；其他列及后续项目仍保留原项目序号。具体标点和示例见下文。 |
| P | 专利、软件著作权、获奖等按来源事实逐项写；多项用连续序号和换行，缺少证据则整格空白。 |
| Q–R | 结合 Q3“引进方式”、Q4“学院推荐意见”和 R4“符合”及已填样例解释：Q 是已正式填写的推荐引进方式，R 是已正式填写的符合结论。印制句、空白勾选框及未签署的占位语不产生值。 |
| S–T | 身份证号和电话只取来源明确值；作为文本保存以保留前导零和原字符，不在回执重复展示完整敏感号码。 |

单元格内的阶段空行和条目换行必须是真实换行符，同时沿用目标物理列的字体、对齐与自动换行。新插入数据行应根据 I–P 的实际行数设置足以显示内容的行高，参考样例行高但不能固定写死 239 或 290 点；原有行高、列宽和隐藏状态不变。生成后用真实工作簿读取回验收文本、样式与可见行高。

I 列以左逢源来源的三个阶段为例，写入时使用下述**单个单元格内的换行**；此例仅演示版式，不能复制给其他人员：

```text
博士：2026.09
西安理工大学
计算机科学与技术

硕士：2021.07
北方民族大学
计算机技术

本科：2017.07
西南民族大学
网络工程
```

若考察表只写博士和本科，I 列的中段改成 `硕士：硕博连读`，博士与硕士、硕士与本科之间仍各空一行。这是用户指定的显示规则；回执应注明它由“硕士栏未填写 + 博士资料存在”触发，不把它当作来源原文引文。若来源明示不同学习路径或存在矛盾，先报告，不套用该默认句。

J/K/L 列的序号从同一份**论文条目清单**生成，不允许分别从三段文本独立编号。以左逢源考察表第 14 行的四篇为例，三列都有实际信息，因此都应出现 `1.` 至 `4.`，并让第 3 项的 IJCV 与第 4 项的 TCSVT 各自对应其题目、作者角色和分区；第 1、2 项是会议，不应套用期刊等级。若其他来源缺少某篇的 K 或 L 内容，就跳过该列该篇的空条目，后续篇目保持原序号而不重新编号；若没有足够信息确认一段刊物或收录文字属于哪篇论文，则不强行配对，回执说明。每列多篇之间用一个换行符，保留标题本身的拼写与标点，不在末尾附加空的序号。M/N/O 则另从同一份**项目条目清单**编号，采用下述项目专用的空行间隔。

### M、N、O 项目列的统一输出格式

三列都从同一份已核对身份的**项目清单**取数；每个项目只分配一次序号，按来源中可确认的项目顺序从 `1.` 开始。目标样本 M5/N5/O5 是单项目且三列均有 `1.`；刘行的多项目样本证明三列同号指向同一个项目。其他样本有单项目不编号、项目间只换一行的差异，因此**新生成行统一**为单项目也编号，多项目间恰好空一行（两个换行符 `\n\n`），M/N/O 使用同一规则；已有行保持原样。

| 列 | 每个项目的单条写法 | 缺项时 |
| --- | --- | --- |
| M | `序号.立项号,项目名称`，沿用已填样本的英文逗号；立项号或名称仅有一项时只写有证据的那一项，不留下孤立逗号。 | 两项都缺则不输出该项目的 M 条目。 |
| N | `序号.项目级别,本人角色`；两项只取得一项时只写这一项，不留下孤立逗号。项目级别按来源原有说法填写，不凭项目名称推断“国家级”等。 | 两项都缺则不输出该项目的 N 条目。 |
| O | `序号.完成状态`，例如来源明确写出的 `结题`、`在研`；没有证明时不根据日期或其他项目的状态猜测。 | 无状态则不输出该项目的 O 条目。 |

例如从同一人的两个项目分别提取出“立项号、名称、级别、角色、状态”后，三列按下列**版式示意**组织；示意词不能作为真实人员的数据：

```text
M：1.<立项号1>,<项目名称1>

   2.<立项号2>,<项目名称2>
N：1.<项目级别1>,<本人角色1>

   2.<项目级别2>,<本人角色2>
O：1.<完成状态1>

   2.<完成状态2>
```

上例中的 `M：`、`N：`、`O：` 和用于排版的缩进**不写进单元格**。若第 1 个项目只查到 M，而第 2 个项目三列都有值，则 N/O 都只显示 `2.`，不得重新编号为 `1.`；某列完全没有可用值时，该单元格保持真正空白。项目标题本身的换行不能据此拆成新项目。来源项目名、立项号、级别、本人角色、状态相互矛盾或无法对应同一项目时，只留有证据的对应项，其余留空并在回执说明。

### L 列先读收录信息；遇到 EI 时检索 CCF

1. 对每篇论文，优先读取其考察表中**“收录与被引用情况及期刊影响因子等”**对应的原文，并与同篇题目、刊物/会议名称、ISSN、DOI、发表年份对齐。分别保存收录类型（如 SCI、EI）、明确写出的分区、CCF 级别、IF、被引次数；不能把整段多篇论文信息当成一篇，也不能从 IF 或被引次数大小推算分区、学校等级或 CCF 等级。若该段已经明确给出 SCI 分区，按下面的 2019 版目录规则判本校期刊等级；若命中可见逐刊目录，按目录类别判定。来源仅有 `EI` 时，不得直接推出本校 A++/A+/A/B。
2. **遇到 EI 索引，就使用 WorkBuddy 的搜索能力核对 CCF 等级。**先确认该篇的实际发表载体是期刊还是会议，再以论文题目/DOI 核实发表载体的完整名称、年份与论文类别；据此在 WorkBuddy 中搜索 [CCF 官方会议和期刊目录](https://www.ccf.org.cn/Academic_Evaluation/By_category/2023-03-08/787209.shtml)及相应领域的正式条目。期刊查期刊表，会议查会议表；仅在正式条目的全名或可核实别名与该篇发表载体一致时，写 `CCF A类/B类/C类期刊` 或 `CCF A类/B类/C类会议`。`EI` 是触发检索的线索，不是 CCF 级别；ISSN、出版机构名（如 `Association for Computational Linguistics`）或检索结果摘要也不能单独证明论文属于哪一场会议。会议还须确认论文为主会的 Full/Regular Paper；Short Paper、Demo、Findings、Workshop 等不得仅凭同名会议或共用 ISSN 套用主会 CCF 等级。此范围限制依 [CCF 目录说明](https://www.ccf.org.cn/Academic_Evaluation/By_category/2023-03-08/787209.shtml)。
3. 搜索结果必须留有**官方目录页面、目录版本或查询日期、命中条目的完整名称与类别，以及该论文发表载体/论文类别的核对来源**；回执逐篇说明判定路径。若 WorkBuddy 只能搜索已归档文件，就先在授权范围内使用已归档的 CCF 正式目录；若宿主支持联网搜索，检索结果仍须回到 CCF 官网或该论文的正式出版页面核对。未取得可追溯的官方条目、发表载体有歧义或论文类别无法确认时，L 仍可写已经核实的 `EI`、IF、被引次数等事实，**CCF 等级留空并标记待核对**，不得用普通搜索摘要补全。
4. 同一轮对**同一规范化发表载体 + 同一 CCF 目录版本**只搜索和核对一次，结果供该批论文复用；已取得的 PDF/OCR 或表格文本也复用，不为 EI 分级重复读取整份材料。CCF 官网目录不是 2019 版西安理工大学期刊目录，两个等级分别记录；相互冲突或依据不足时只留可证明的部分。实施前须确认 WorkBuddy 宿主的搜索能力能否把命中的官方来源及链接交给本 Skill；若仅有本地文件搜索且没有授权归档的 CCF 目录，按上条留空并报告，不把库内搜索误说成已核对官网。

### 2019 版目录如何参与 L 列分级

1. **目录在开发/部署阶段入库，不由任何一次 WorkBuddy 填表任务入库。**开发调整 Skill 时，使用 `2019版学术期刊A++、A+,A,B类期刊目录.xls` 建立系统级、可供多个 Skill 受控读取的共享参考目录：服务器保存不可变原件、可读派生版本、SHA、正式可见工作表的 ISSN/刊名索引，以及稳定目录 ID 与启用版本。教师引进 Skill、其他需要判级的 Skill 都通过同一个受控只读接口按目录 ID/版本查命中条目；不把整份目录复制进各 Skill 包，也不把它算作某位教师的业绩来源或放进 `source_indices`。每次任务仅引用已部署的版本，回执记录所用版本，用户不需要上传目录。若共享目录未部署或不可读，报告系统参考资料缺失；来源已有的分区/收录信息照填，无法判定的学校等级留空，**不得把用户的填表附件当作自动补库入口**。未来更新目录也由受控部署流程显式启用新版并保留旧版，不能因某次任务出现同名文件而替换当前规则。
2. 先确定每项是**期刊论文还是会议论文**。只对期刊核对目录；会议可保留来源写明的 `CCF A类会议` 等，但不按期刊目录给 A++、A+、A、B。对期刊读取**第二张可见工作表** `A+、A、B类期刊目录` 的第 3 行及以后：优先将来源 ISSN 与该表 **D 列刊号**去连字符和空白后精确匹配，并用 **B 列期刊全名**复核；无 ISSN 时仅在规范化完整期刊名与 B 列唯一吻合时使用目录等级。E 列 `所属类别` 中的 `A+`、`第三类 A`、`第四类 B` 分别呈现为学校 `A+`、`A`、`B`；保留原 E 列值和行号作为回执依据。简称或近似字符串不能单独决定等级。目录里的草稿、重复清单与“待确定”隐藏页不参与自动分级。
3. 可见 `Sheet1` 的 2019 版规则把 SCI/A&HCI/SSCI **一区**列为 A++、**二区**列为 A+、**三区/四区**列为 A；B 只在可见正式目录中有明确对应时判 B。若来源对**该篇论文**明确给出相应分区，可结合该规则形成学校等级，并在回执注明“考察表分区 + 2019 版规则”；ESI 高被引或“中国百篇”等其他 A++ 条件也必须有该篇的明确证明。可见目录没有逐刊 A++ 清单，期刊名不在 A+/A/B 表中本身并不能证明 A++。
4. 同篇论文若目录的明示类别与按分区规则算出的类别不同，或 ISSN 与刊名分别指向不同期刊，**不自动择高、不猜测**；该篇学校等级留空并在回执列出冲突，待人工核对。来源只有 IF、CCF 级别或“Top”，没有可用分区/目录命中时，也不能推断学校 A++。引用次数和 IF 仍只写来源实际给出的数，不联网补缺。
5. 左逢源样本的四项中，前两项为 CVPR、AAAI 会议，保留 `CCF A类会议`；第 3 项来源写 `SCI-2区`，可按 2019 规则生成 `A+类`；第 4 项来源写 `SCI-1区 Top`，可按规则生成 `A++类`。这两项属于**按考察表所载分区判定**，回执必须给出来源 `sheet1!AC14` 与目录 `Sheet1` 的对应条款；不能把汇总表另一人员 L5 的 A++ 或西南交通大学目录用作依据。若正式分区证据不能确认，则等级留空，仅保留来源原有的分区描述。

**控制时间和费用：**原目录样本的 PDF 仍只对必要页面做一次 OCR；两份 `.xlsx` 直接读取单元格，不调用 OCR。2019 版 `.xls` 在开发部署时于隔离区生成一次受控可读派生件，原件不覆盖；服务器按 SHA 持久保存 ISSN/刊名索引，多个 Skill 和后续批次复用，不要求用户在填表任务中上传，也不把整个目录送进模型。EI 的 CCF 核对按发表载体和目录版本去重搜索，避免逐篇重复查询。格式化在已取得的字段上进行，不为一个缺值重新读取整份文件；整批候选只发布一次 Excel。

**需要特别处理的现有约束：**当前 `TEMPLATE_ALL` 逐格要求 `raw_text` 可在同一来源 `quote` 中找到，最终 Excel 值又必须等于服务端据该字段核验的展示值。若 Skill 直接在 `raw_text` 加入原文没有的 `博士：`、空行、`硕士：硕博连读`、重新编号或目录生成的 `A++类`，服务端会因证据不匹配拒绝；若只改 `excel_writeback_apply.rows`，服务端会因行值与已核验字段不一致拒绝。因此本次新格式**不能只改 Skill 文案**。后续必须扩展受控契约：保留逐条原文引文和来源版本、将目录版本作为独立只读依据、由服务端使用固定格式规则生成或严格复核 `rendered_value`，再按该值校验实际 Excel；不得让模型提交无证据的任意展示文本。此扩展只适用于教师引进模板，不放宽教授 B–I/L 或通用模板证据闸门。现有 `TEMPLATE_PERSON_ALREADY_PRESENT` 重复人员保护保持原样。

**实施中的设计细化：**复用可信附件导入与授权目录导入两条现有入口，不再增加重复的任务接收 MCP Tool；授权目录入口使用受控 `WORKBUDDY_DOCUMENT` 参数，普通目录导入保持原样。新增行仍用 `write_scope=TEMPLATE_ALL`、每行 `source_indices` 绑定同人的多份人员来源；`structured_dataset_members.source_versions_json` 记录每行全部人员来源版本，服务端逐格只接受该行来源组内的正式引用，并要求每份合并材料的真实正文包含姓名或已核实身份证号；这一字段使用既定 `20261009_0001` 迁移。2019 版目录是单独的 `reference_catalog`，不能塞进 `source_indices` 冒充某位教师的材料。当前模板写回限制 A 列为真实“序号/编号”，且有唯一“姓名”列；其它业务列仍从上传表头动态读取。新展示策略需以白名单格式标识、冻结目录版本和逐篇来源片段为输入，保留原文与加工后文本的对应审计；实施时评估现有 JSON 审计字段是否足够，只有不足才增加迁移。若未来目标首列不是序号或没有姓名列，需要扩展契约，不以假列名绕过。

## 怎样验收

1. 用前期的空模板与当时的 4 份材料做基础隔离测试：先展示真实 A–T 表头及每位确认身份的教师候选；有证据的格有值，没证据的格为空，逐文件说明未处理原因。两份 PDF 最多各做一次所需页面的 OCR；来源 `.xls` 原件哈希不变。本次新增的 2019 版期刊目录另按下文验收。
2. 检查 J–L、M–O 的多条项目不会错位，Q/R 不会因为上层“引进方式”标题而串列；A1:T4、样式和 O6 的 `.` 保留。本轮上传的目标始终优先于服务器同名旧表，首次测试时不能因旧表不存在而返回 `TARGET_EXCEL_NOT_FOUND`。
3. 再只给完整 `.xlsx` 文件名和新材料，确认新增行号、同一 WorkingCopy/Document 的新版本、下载链接；重复提交不会多加一行，旧版可下载。后续另一次上传同名新 Excel 并附材料时，确认以新上传表为目标，不追加进旧工作副本。
4. 下载后人工补充一个原本空白的格、修改一个已有数据格并回传，确认仍是同一张表的新版本、原有行数不变；旧基线上传、改动表头或清空已有非空值被拒绝。
5. 对无法辨认身份、来源冲突、未授权目录、同名目标歧义和发布中版本变化，确认不会生成错误行或声称发布成功。

### 新格式的专门验收（格式能力完成后）

1. 用已填写的两人汇总表和左逢源考察表做**只读格式对照**：确认 I6 顺序是博士、硕士、本科，阶段间空一行；J6/K6/L6 均有 1–4 号并逐项对应；M–O 空白没有被伪造；已有第 5、6 行完全不改。随后用空模板或另一位尚未入表的教师进行实际新增行测试，不能在样例表中重复添加左逢源。
2. 构造仅有博士、本科而硕士栏空白的来源：I 列必须依次显示博士、`硕士：硕博连读`、本科，每段间恰好一个空行；只显示证据明确的院校、专业和毕业时间。若硕士明确有记录，则不得写“硕博连读”。

7. 在 WorkBuddy 填表验收**之前**，先由开发部署流程将 2019 版目录导入系统，检查不可变原件、可读派生件、SHA、索引、稳定目录 ID 和启用版本；随后进行两轮**都不上传目录**的填表任务，确认教师引进 Skill 均引用同一共享目录、回执注明版本，并让另一需要判级的 Skill 通过同一个只读入口取得相同目录命中。目录原件哈希不变，同批多篇论文复用索引，不对 PDF 重复 OCR；在填表任务上传不同内容的同名目录不得替换已启用版。未实现受控展示契约前，上述格式写入验收标为**待实现**，现有 Skill 不得绕过证据或行值校验声称新格式已经发布。

## 实施顺序与上线

新增行流程仍先冻结目标表头与人员来源，完成 PDF/Office 一次读取及逐格证据。此次格式调整先实现共享参考目录的受控导入、版本管理与只读查询，在开发部署阶段把 2019 版目录放入系统并核对可供多个 Skill 调用；然后补服务端受控展示契约、MCP 行值一致性校验和对照测试，最后更新 WorkBuddy Skill 与真实会话验收。手工回传流程保持原有路径。涉及共享目录与展示契约的 API、MCP 和 WorkBuddy 插件要同步发布；若启用多来源同人合并，应先执行对应数据库迁移。只有服务端返回已发布版本和下载资源，WorkBuddy 才报告填表完成。

原有空模板场景已做的隔离验证包括：PDF 与 XLSX 两份正式来源合成一行、空列保持空值、保留原有 `.`、第二轮按同名目标发布新版本、拒绝无同人身份依据的合并、拒绝重复使用已作为补充来源的版本，以及旧写回和目录传输回归；当时核对的 A5 从 1 开始、O6 保留 `.` 只适用于**旧空模板**。本次对已填写汇总表、左逢源考察表和 2019 版 `.xls` 只做了只读结构与内容核对；没有写入样本 Excel。真实 WorkBuddy 宿主 OCR、目录授权、新格式发布与手工回传仍需部署后的会话验收；隔离测试不能替代该验收。

### 本次实现与部署位置

2019 版原始目录作为共享部署资源放在 `apps/api/app/modules/reference_catalogs/assets/xaut-journals-2019.xls`，固定 SHA256 为 `273f8a8cf47268a5016da26a79133a0e29ea4a6edd24c78796ccec6d02c06775`。它不复制进教师引进 Skill，也不要求填表用户上传。服务器在具备 PostgreSQL 与 LibreOffice 的环境执行 `cd apps/api`、`alembic upgrade head`、`python -m app.modules.reference_catalogs.seed` 后，原件归档到 `<FILE_STORAGE_ROOT>/reference-catalogs/xaut-journals-2019/<上述SHA>/original.xls`；可读 `.xlsx` 派生件使用现有 `CONVERTED_XLSX` 文档派生件存储，索引在同目录 `index.json`。数据库 `reference_catalog_versions` 记录启用版本、原件版本、派生件和索引哈希。`reference_catalog_get/query` MCP Tool 与 `/api/reference-catalogs/xaut-journals-2019` 只读接口让其他 Skill 共用同一目录。

本机没有可用的 LibreOffice，也没有服务器数据库连接，因此这里只完成了**资源随代码保存和部署命令**，不能把本地状态称为服务器已入库。上线前须在服务器运行上述迁移与导入命令，并核对返回的 `entry_count=621`、版本 ID 和只读查询结果。目录入库不由任何 WorkBuddy 填表请求触发。开发隔离测试用受控 `.xlsx` 样本验证了“仅取可见正式工作表”“ISSN 与完整刊名冲突拒绝判级”和学历格式推导，尚需真实 `.xls` 转换与 WorkBuddy 会话验收。

列内格式由 `teacher_render` 白名单契约驱动：I 列学历、J–L 论文、M–O 项目、P 列成果分别按固定规则生成；每个展示片段必须能回指正式来源 `fragments`，目录等级再绑定本次启用的共享目录版本。服务端把生成值保存在字段展示审计信息中并核对最终 Excel；WorkBuddy 写入器优先从数据区内内容较完整的真实数据行复制新增行样式，保留空模板预留行样式作为缺列后备，再为多行内容设置行高，不改动工作簿其余 OOXML 部件。未通过证据、序号、等级或工作簿校验时不发布。对于仅从外部网页检索得出的 CCF 信息，当前任务缺少可归档正式来源引文时只写回执，不把搜索摘要冒充 Excel 来源证据。

### 2026-10-09 L 列漏判修正

实测 WorkBuddy 发布载荷把 `SCI/A&HCI/SSCI中科院1 区`、`2 区` 均作为 L 的纯 `TEXT`，没有 `ZONE`、期刊 `ISSN/JOURNAL_NAME` 或冻结的 `catalog_version_id`，服务端因此只写原文、不执行学校判级。修正后，Skill 要求逐篇把明确分区截为原文子串 `ZONE`，期刊的 ISSN/完整刊名要作为 L 字段中的正式来源片段供目录查找；K 列已有刊号不自动传递到 L。服务端分区规则接受多个索引名用 `/` 连接及可选“中科院”的写法，同时在明确分区仍全部按纯 `TEXT` 提交时拒绝发布，避免静默漏级。`JCR Q1/Q2` 仍不等同中科院分区；目录和分区冲突时仅保留原文事实并报告冲突。验收增加组合写法的一、二区判级和纯 `TEXT` 漏标拒绝测试。

### 2026-10-10 Excel 换行标签与排版校验调整

正式来源引文、`raw_text` 和原始字段值继续保留原样。仅在生成展示值和写入新的 Excel 数据格时，将大小写不敏感的 `<br>`、`<br/>`、`<br />` 换为真正的换行；不解析或删除其他 HTML 标签，不改动目标表的既有单元格。WorkBuddy 写入器在防公式检查和设置单元格值前完成转换，服务器的展示值与导出也使用相同规则，避免预览和下载出现标签。

发布时对新增格的期望值与实际值先做相同的换行标签转换，再把连续空白（空格、制表符、换行）归一为一个分隔空格后比较；这样只忽略换行位置和多余空白，不忽略文字、数字、论文序号、等级和条目顺序。实际新格若还残留 `<br>` 标签则拒绝发布，确保下载文件已清理。`None` 与非空值仍严格区分，原始证据、来源版本、目标表头、旧单元格、公式和非目标工作簿部件仍按原校验。自动换行和行高由写入器尽力设置，服务端不因其未达到固定高度拒绝发布；其他工作簿结构保护不放宽。

验收使用混合大小写及三种 `<br>` 写法确认 Excel 格内只出现换行、不出现标签；用等价换行/多余空白确认可以发布，用不同正文或论文等级确认仍拒绝；另用没有自动换行样式或行高不足的有效内容确认不因排版失败。

### 2026-10-10 L 列 CCF 优先规则

“收录与被引用情况”按论文条目而非整列判断：某篇的正式来源引文已含 CCF 标签时，保留该篇 CCF 及其他有证据的原文事实，不对这一篇调用 `xaut-journals-2019` 的逐刊查询或分区判级，也不追加 A++/A+/A/B 学校等级；同列其他没有 CCF 标签的期刊仍走既有目录规则。仅外部搜索得出的 CCF 结果未成为正式来源时，不视为该篇已有 CCF 标签。若本轮所有论文都无需目录判级，WorkBuddy 不调用 `reference_catalog_get/query`；混合批次只为无 CCF 的期刊冻结目录版本与查询结果。

现有服务端要求 L 中明确 SCI 分区必须标 `ZONE`，并据此强制读取目录。因此需要在列内格式器增加按 `item.ordinal` 生效的 CCF 优先分支：CCF 只从该篇展示用的正式来源 `TEXT` 判断，保留同篇 `ZONE` 原文显示，但跳过版本校验、分区等级和 ISSN/刊名查询；其他条目继续按原有闸门处理。这样同篇同时有 CCF 与 SCI 分区也能保留原文并发布，且不把 CCF 条目误判为学校期刊等级。测试须验证纯 CCF、CCF+SCI/ISSN 混合、同一 L 格中 CCF 与非 CCF 两篇共存，以及仅外部搜索 CCF 不触发优先规则。

### 2026-10-10 L 列等级前置

L 列每篇论文仍以原序号开头；只要该篇有已确定等级，就把等级紧跟序号，排在其他收录、分区、被引和影响因子事实之前。学校 A++/A+/A/B 等级由现有冻结目录与分区规则判定，正式来源明确写出的 CCF A/B/C 等级仍走 CCF 优先分支；不改判级、冲突和证据规则。示例：`1.A+类,SCI-2区,IF 2.1`、`2.CCF A类会议,EI索引`。无等级时维持原有事实顺序，不为缺失等级加占位。服务端 `teacher_render` 统一生成该顺序，Skill 和写回候选必须与其展示值一致。
