# Harness扩充真实问题：从3题到15题的准备方案

日期：2026-11-10。当前状态：已选好15题候选（原3题＋新增12题），未采集新增实际检索包，未发起模型调用，也未放宽现有Harness的3题/19请求限制。

新增题的具体采集命令和前端操作见[实际检索证据采集步骤](expanded-real-input-capture-steps.md)。所需14份文件已于2026-11-10核对全部解析及索引就绪；计划仍需按步骤生成并加载。

## 1. 直接回答

当前`harness cycle`仍使用R001、R016、R034三题。可以新增问题，推荐先扩充到15题，随后补足真正的冲突、旧版本正例，再逐步达到[60条目标](manual-60-plan.md)。

不能只向JSON追加题目就直接运行：目前入口、执行器、比较器均检查3题，授权最多19请求。扩大题数需要同时处理输入、预算、比较分母和候选门槛，不仅修改一处数量限制。

## 2. 已准备的候选题

完整题干、限定文件、参考答案、原文位置均已写入本机私有[问题扩充清单](../../runtime/evidence-test/datasets/expansion-candidates-v1/问题扩充清单.md)。结构化信息见同目录`candidate-questions.json`，它不是`--dataset`可运行的数据集。

本次复用用户已经确认的真实材料题库和原文件范围标签，没有改写原问题或重新编造答案，也没有重新检查外置硬盘原件。旧人工表和已标注样本保持不变。F编号沿用[原选材包](workdocs-question-pack-20261031.md)。

| 分组 | 题号 | 重点 |
|---|---|---|
| 开发集，原3题 | R001、R016、R034 | 完整证据、培训费缺失、申报与立项的不同阶段 |
| 开发集，新增7题 | R002、R005、R017、R018、R027、R029、R035 | 普通通知、实际当选结果缺失、岗位占位符、不同年度/场次、目标与实绩 |
| 预留验收集，新增5题 | R009、R013、R024、R025、R040 | 规则例外、历史文件金额上限、考试要求缺失、注册资本缺失、不同日期字段 |

开发集10题、预留集5题，两个集合不共用同一个F编号文件。预留集仅是本次的材料划分，尚未证明这些材料此前完全未被测试；也不能以F编号不重合证明所有业务文件族完全独立。正式验收前需核对历史使用情况，必要时换成新的文件族。

按已确认的完整原文件范围参考，15题中NORMAL为10题、MISSING为5题。**这批没有CONFLICT或OUTDATED阳性样本**，只能扩大缺项和误报边界的覆盖，不能证明冲突与旧版本召回能力。原文件早、日期不同、目标和实绩不同均不能直接贴成这些阳性标签。

## 3. 先做哪些准备

1. 查看私有清单，核对每道题限定的文件已经上传并就绪；未上传的再上传。新清单本身及参考答案不得作为检索材料上传。
2. 用新的采集目录和计划采集新增题，明确选中文件范围、完整复制题干；保留旧`frozen-real-v1`及其报告。准备方法见[固定输入操作文档](frozen-real-input-usage.md)。
3. 根据实际`package.json`核对每项事实。原文件标签仅作参考：检索包若缺了原本存在的内容，应记录检索差异，不能直接套用原文件标签。
4. 由用户确认新增包及Gold，绑定各自输入散列，生成新版本开发/预留数据集。旧三题如重新采集到不同证据，也属于新输入，应重新核对。
5. 为新数据集重新生成可核验的基线报告和反馈。旧三题报告及NO_GAIN实验继续保留；它们与新数据集散列不同，不能直接合并或冒充新集控制组。当前代码会拒绝跨数据集历史。

候选清单只完成了选题工作，不宣称完成上述采集、确认、冻结、基线或评分。

## 4. Harness需要怎样适配

后续开发应同步修改并验收：

- `schemas.py`：为扩充实验定义明确的样本数、重复次数和操作者总授权，保留原协议及旧实验可核验性。模型不能更改预算。
- `service.py`和`executor.py`：按实际题目数校验计划、按每次请求前计数；继续拒绝把多批问题套进单批授权。
- `comparator.py`：按实际样本及重复次数计算全部分母、失败、每题退步和候选门槛，删除仅适用于9轮的假设；不能只放宽入口。
- CLI：默认检查时展示控制/候选的实际次数与总上界，真实执行仍须显式`--live`。时间预算不足时停止，不能由模型自动增加。
- 回归：原3题旧协议兼容，新题数完整执行、部分执行、预算耗尽、中断、逐题退步、开发/预留隔离及未知用量。

在“三轮、每题单批、一个候选”的条件下：

| 数据规模 | 建议调用 | 控制＋候选复测 | 合计上界 |
|---|---:|---:|---:|
| 目前3题 | 1 | 3×3×2＝18 | 19 |
| 建议的10题开发集 | 1 | 10×3×2＝60 | 61 |
| 若全部15题用于开发 | 1 | 15×3×2＝90 | 91 |

这些是规划数，当前程序尚不允许61或91请求。等待预算也需重算：例如10题、控制60秒/候选120秒，全部请求均接近超时时，等待上界约90分钟再加建议及处理开销。保留30分钟上限可以正常提前停止，但不能承诺完整跑完；需由操作者选定预算，不能静默放宽。

建议先只让10题开发集驱动建议。候选方案确定后，在预留5题独立验证。预留结果不反复回传给优化器；如果据此继续调参，这5题应转为开发数据，并补充新验收材料。

## 5. 还需补哪些材料

CONFLICT需要同对象、同时间、同口径、同事实阶段且相互矛盾的两条依据，排除明确更正/替代关系。现有不同年份或场次问题是误报反例。

OUTDATED需要真实逻辑文件的内容版本链、当前索引事实以及当前问题实际引用旧版本的证据。历史问题按当时版本回答是反例；仅仅文件年代早不算正例。需要派生材料时必须单独标记，不能伪称原业务文件天然存在矛盾或版本关系。

本次新增私有候选JSON、问题清单、manifest及本文；不改运行代码、env、数据库或模型配置，未执行收费测试。
