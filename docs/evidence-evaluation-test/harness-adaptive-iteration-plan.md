# 把自动诊断接到建议器，有限轮次自主试改

日期：2026-11-16。状态：初版开发与工程验收完成，真实首轮建议因反馈哈希漏字被拒；短引用修复见第10节，真实候选效果待用户复测。

## 1. 这次解决什么

目前真实 C 实验已经保存模型的工具参数，但反馈往往只剩 `TOOL_SCHEMA_INVALID`。建议模型不知道具体哪个字段不合规，C 本身也只复测同一个候选。本次增加一个独立入口，让程序自动提取可核实的错误，模型自主写新的通用规划说明，在隔离副本试跑，再把独立评分和本轮诊断交给下一轮。

不是给每道题人工写修复答案，也不让模型修改裁判。具体修改内容仍由建议模型决定，可以选择 `NO_CHANGE`。

## 2. 流程和范围

`已完成且独立核验通过的 C 实验 → 只取开发题 → 按真实 Tool schema 重验参数 → 机器反馈 → LLM 建议 → 校验候选差异 → OS 隔离运行原版/候选 → 独立重放评分 → 下一轮或停止`。

新增 `adaptive-iterate`（默认只检查，`--live` 才执行）和 `adaptive-iteration-compare`（零模型调用，只读重算）。复用现有测试 env 的 Codex/API 选择，建议器和规划器都固定在本次选择的 Provider；两者输出额度分别配置。

每轮只允许替换“原提示末尾的一段通用补充说明”，不在上轮说明后无限叠加；原提示、函数代码、Tool schema、权限、确认机制、Gold、评分器和预算均不允许改。每轮控制组始终是同一原版，上一轮候选和得分进入历史，不把换控制组误当改善。只运行初始规划，不执行检索、文件操作或回答。

## 3. 自动诊断怎样产生

在可信宿主中，用真实 ToolRegistry 的输入模型重新校验已核验的计划。输出工具名、步骤序号、schema 字段路径、Pydantic 错误类型及允许的长度等约束。已知的跨字段约束映射成固定错误码和可读说明，例如“全部结果需要真实已完成的澄清选择”。不记录输入值、异常全文、密钥或路径；字段名也必须来自真实 schema，拒绝把模型编造的键写入诊断。

未知校验错误如实记为未分类，不能凭猜测贴根因。诊断区分“已经观察到违反约束”与“为什么模型这样做的假设”。真实检索和回答质量继续标明未执行。固定预检、回退和模型失败单独记录，不能冒充 Adaptive 正确。

## 4. 开发题和保留题边界

先独立核验 C 来源及冻结题库，再投影开发题。新实验的输入、反馈、建议载荷及候选进程只含开发题；不复制保留题问题、人工标签、文件族或参考答案。建议器只收到开发题对错，不收到预期路由、人工理由和参考答案。

所有开发题都计入分母，包括固定预检题。沿用严格验收：任一有效配对退步、意图契约退步或候选违规都不能接受；未全部实际使用 Adaptive 则无法证明整体策略改善，不自动排除难题。比如现有 R035 若仍由前置规则处理，会明确显示提示策略不可覆盖的原因，可能使整体结论为无法判断。模型可以据此不改，程序不放宽裁判求通过。

保留集不进入迭代。开发集改善最多表示保留一个离线候选；独立保留集的最终泛化验收另行执行，不能把本次开发结果宣布为 C 已通过或自动上线。

## 5. 有限迭代与总预算

轮数明确为 1—3；建议与所有原版/候选规划调用使用同一个 Journal，总请求和总时长不按轮重置，失败、回退、未知费用均计入。每题每组最多 3 次调用。上界为 `轮数 × (1 + 2 × 开发题数 × 重复数 × 3)`，提供上界与本次授权是否覆盖的信息；授权较小可以提前停止，不能自动加钱续跑。

停止条件：独立验证开发集改善、合法 NO_CHANGE、重复候选、连续无进展达到上限、最多轮数、请求/时间耗尽、建议失败、保护检查失败、隔离基础设施错误或人工中断。不自动重试失败调用，不自动恢复旧实验。每轮落盘反馈、建议、补丁、检查、试次和得分，整个实验保留最终停止原因。

## 6. 文件和兼容方式

- 新增 `improvement/planning_diagnosis.py`：机器可读参数诊断与开发反馈。
- 新增 `improvement/adaptive_iteration.py`：准备、固定配置和有限循环。
- 新增 `improvement/iteration_comparator.py`：独立核验来源、逐轮请求/代码/反馈及实际规划重放，重新评分。
- 扩展 Harness CLI；新增专项 Fake 与真实 OS 隔离测试；补操作文档及 README/runbook 链接。
- 只为已经核验过的旧 C 宿主身份登记兼容；不更改旧来源、冻结输入、执行快照或历史结论。旧 A/B/C 命令继续有效。

## 7. 验收要求

Fake 验证详细错误可自动产生且脱敏、开发投影不泄漏保留集/Gold、第二轮自动读到第一轮诊断与对错、候选是真实字符串差异、合理 NO_CHANGE、重复/无进展/失败/预算/中断停止、独立重算拒绝篡改和缓存假成绩。真实 OS 测试用 Fake 模型运行候选规划和固定保护回归，验证权限隔离；不调用真实模型、不重启服务或修改 env。最后对当前真实 C 来源做零调用检查，确认兼容且不写旧目录。

工程测试通过后交付执行步骤。是否能实际改善须由用户显式 live 后的数据证明；失败或不修改也属于有效实验结果。

## 10. 反馈短编号修复（代码修改前冻结）

真实`adaptive-iteration-v1`中，模型第一个反馈引用只返回了原64位哈希的前63位，建议因此被拒绝。按用户授权修复引用协议，不猜测补齐错误哈希，不编辑旧建议或重新发起真实请求。

新实验升级为v2：每轮把完整反馈编号映射成`R1F001`、`R1F002`等短编号，下一轮使用`R2F001`，以免跨轮误用。模型只看到短反馈编号，输出schema枚举本轮实际允许的编号。程序保存只供宿主读取的`reference-map.json`，绑定轮次、完整反馈散列和原版源码散列；收到建议后严格查表，恢复完整反馈引用，继续交给既有业务及补丁校验。

同时用固定`baseline_ref: BASELINE`代表已绑定的原版源码，让模型无需抄写另一条源码哈希；真实源码身份仍由宿主从冻结原版计算和核验。原始模型回复保存在`proposal.json`，映射后的结构另存`resolved-proposal.json`，不偷偷覆盖模型原文。

建议格式不合法或引用不存在时，记录脱敏的字段位置、错误类型及明确拒绝码。不记录错误输入值或异常全文，不自动修正、不重试、不强迫生成补丁。新提示说明引用格式及原有内容约束，提醒使用“和”等自然语言表达并列，原路径、命令、样本及权限校验均保持原样，不在本次放宽。

新增`iteration_proposals.py`集中处理短引用协议；迭代器及独立比较器同步接线，比较器从实际反馈重建映射，不相信缓存映射或恢复后的结构。旧v1按原提示、原schema、原错误码和已核验宿主身份只读重放，旧结论不升级；未知宿主身份继续拒绝。

验收覆盖：允许编号枚举、短编号到完整哈希精确映射、未知/截断/重复/旧轮编号拒绝、原始回复不覆盖、每轮映射固定、映射与恢复结构篡改拒绝、NO_CHANGE及两轮预算不变、API/Codex均使用同一短引用协议。运行Fake与本机OS隔离，不调用真实模型。复测另用`adaptive-iteration-v2`新目录。
