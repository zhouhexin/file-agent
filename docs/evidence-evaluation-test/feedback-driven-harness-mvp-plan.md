## 1. 大白话说明

要新增的是一个“提出改进建议并验证建议”的流程：

```text
已有执行结果与评估报告
→ 程序整理失败反馈
→ LLM提出一个受控调整，或者说明没有合适调整
→ 程序检查建议是否合法、是否重复、是否超预算
→ 在同一测试条件下运行控制组与候选组
→ 程序对照人工标签比较结果
→ 保存有效、无效、退步或无法确定的结论
→ 有效的方案也只作为待复核候选，不自动改线上配置
```

LLM负责“看反馈、提方案”；程序负责“控制执行、复测和评分”。不是让模型凭一段自我评价宣布优化成功，也不涉及模型权重训练。

R034已经提供了一个失败案例：3000输出额度时被截断，6000时在60秒附近超时。现阶段应让优化器读到这些已发生的失败，而不是继续由人手动挑每个参数。模型可以提出其他合法实验，也可以返回NO_CHANGE；不预先写死它必须建议120秒，更不预先写死它必须优化成功。

## 2. 必须区分的两个阶段

| 阶段 | 优化什么 | 固定什么 | 本轮是否实现 |
|---|---|---|---|
| A：离线调用可靠性闭环 | 评估调用的输出额度或等待预算 | 问题、证据包、版本事实、人工标签、提示词、模型及评估规则 | 优先开发的最小原型 |
| B：文件任务策略闭环 | 缺证后怎么补检、冲突后怎么取证、旧版本怎么定位 | 问题、授权范围、语料/索引版本和任务参考答案；逐次保留变化前后证据包 | 后续扩展，暂不接线上 |

A只验证“反馈能否驱动受控实验”，不能宣称已实现完整文件任务自优化。当前R034语义评估失败，没有有效的MISSING/CONFLICT/OUTDATED判断，不能据此自动补检、扩大范围或拒答。

B才直接对应文件智能体的策略改进，例如MISSING触发有限补检。进入B后证据包会变化，不能一面固定EvidencePackage、一面声称验证了新的检索策略；新证据包的标签也不能机械沿用旧包标签，应独立复核其覆盖情况和任务正确性。

原指南写明第一版不包含“上线自进化Harness或自动改Prompt”，并要求“只有评估集稳定后才增加补检/澄清/拒答决策器”。因此本次A为额外的离线研究原型，与既有MVP评估器分开交付。现有3题不足以验收全部状态；进入B和上线决策前仍需扩充并验证包含冲突、旧版本与易误判案例的人工测试集。

## 4. 最小闭环的六个模块

### 4.1 反馈整理器

读取已存在的报告，生成FeedbackPacket。它应包含：

- 数据集/输入/人工标签散列、评估器和提示词版本、基线报告标识。
- 每题每轮的执行状态、错误类别/阶段、安全异常类型、HTTP状态及是否截断。
- 已有问题标签、是否有有效语义判断、输入长度、证据条数、已知Token与耗时。
- 同一条件下已经尝试过的候选及其无效/失败结果。

区分两类反馈：证据语义问题，和模型/基础设施执行错误。EVALUATION_FAILED的空issues不能解释成NORMAL。

A阶段给建议模型的载荷只需要安全错误、结构统计、预算和历史尝试，不发送原文、参考答案、expected_issues、用户身份、实际路径或密钥。程序内部可以读取Gold评分，但不将其混入优化器或被测评估器的模型输入。

第四步实现采用v2反馈扩展：保留v1原产物，历史实验必须独立重算，模型只看到比较结论、受控预算及安全执行信号。新结果写到新反馈目录，不回写旧反馈。`--previous-cycle`显式开始新一轮并继承历史，不自动续跑；每轮最多一个候选。最多9条既有历史、完成后10条，嵌套最多8层、输入最多64000字符；越界拒绝，不静默删除历史。

### 4.2 LLM策略建议器

独立调用模型读取反馈和受控能力目录，只允许以下两类输出：

1. NO_CHANGE：当前允许动作无法合理改善，给出依据。
2. PROPOSE_EXPERIMENT：提出一个变量调整，并引用真实反馈条目说明假设。

建议结构示例（仅说明协议，不是已经生成的LLM建议）：

```json
{
  "decision": "PROPOSE_EXPERIMENT",
  "target": "evaluation_runtime",
  "feedback_refs": ["feedback-item-1"],
  "change": {
    "field": "timeout_seconds",
    "from": 60,
    "to": 120
  },
  "hypothesis": "在相同输出额度下验证更长等待时间能否取得完整响应"
}
```

必须实际接入LLM Provider并保存脱敏调用记录；不能用if/else固定生成“增加超时”冒充模型提出策略。Fake仅用于测试，并明确标记。

优化器自己的超时、无效JSON或额度不足另记OPTIMIZER_FAILED，不得算作R034的业务证据问题。一次失败停止本轮，不无限要求模型重新思考。

### 4.3 策略校验器

A阶段只提供一个很小的可执行集合，由开发者固定，而非由LLM扩展：

| 受控字段 | 首批候选值 | 规则 |
|---|---|---|
| max_output_tokens | 3000、6000、8000 | 一次只能改此字段或超时字段之一 |
| timeout_seconds | 60、120 | 120只在新的离线实验Profile中允许 |

说明：现有普通env配置将评估超时限制在60秒。实现阶段须新增严格的离线ExperimentProfile，允许经校验的120秒通过运行时依赖传给实验客户端；不放宽生产env限制，不让模型写.env，不默默裁剪120为60。Profile生效值必须写入报告，并与实际客户端参数一致。

校验至少包括：

- schema严格，拒绝额外字段、Shell、SQL、路径、任意URL和任意Prompt。
- from必须等于服务端确定的当前实验基线，field/to必须在白名单中。
- 一次只改一个字段，其他配置、代码、输入及标签散列保持一致。
- 引用的反馈必须存在，不能基于文件中的伪指令授权动作。
- 相同条件下已被证实无效的相同候选不重复执行；新的基线或上下文需明确关联后另算。
- 成本上限、允许外发范围、总调用数与时限来自操作者冻结的实验授权，不由模型增加。

越界建议记录REJECTED，不暗中改写成另一个建议后声称仍是模型原建议。

### 4.4 受控复测执行器

复用现有独立评测服务，在固定数据集上分别执行当前控制Profile与候选Profile。已有两组报告保留为历史；若采用新的客户端、代码或提示词，必须建立同版控制组，不能假装与旧报告仍只有一个变量不同。

默认一轮只接受一个候选，不自动循环搜索参数。对当前3个单批样本，每组3轮，共控制组9次、候选组9次，加1次建议模型调用，最多19次请求；这是新增live前需要显示的上界，不把之前花过的请求算成本轮控制组。

全局计数器须在每次发送请求前扣减预算，失败也计数；不得只限制外层循环，任由内部重试或分批突破上限。当前模式要求3题均可单批处理；遇到需要多批或新的数据集则拒绝套用这份19次授权，重新准备预算。HTTP与供应商可能有服务端继续生成行为，客户端超时不表示服务端零消耗。

除调用数外，设置整轮墙钟时限，例如30分钟。Token不完整时标UNKNOWN，不能用错误记录中的0证明未花费；不能仅依靠供应商usage作费用硬限制。达到预算就停止并保存已完成的各次记录，不丢弃中途失败。

默认prepare/propose只读报告或使用Fake。真实建议调用和真实复测均需由显式live实验命令启动；它与现有配置授权一致，不新增隐式后台外发。

执行器只能写服务器确定的私有实验目录，不改原文件、数据库业务事实、旧输入、金标、旧报告、原env、ACTIVE Skill或生产策略。

### 4.5 独立结果比较器

程序依据人工标签评分，LLM建议中的“预计有效”不作为得分。必须逐题逐轮统计，不能只使用现有报告顶层按首轮计算的部分汇总字段。

先过硬门槛：输入/标签不变、授权不变、单变量成立、未超预算、引用有效。随后比较：

- 完成且与人工标签匹配次数 / 全部执行次数；失败不能从分母排除。
- 各题完成率、误报、漏报和历史正常题是否退步。
- MISSING/CONFLICT/OUTDATED/NORMAL的P/R/F1及适用样本数；没有阳性样本时N/A。
- 成功与失败各自延迟，整体p50/p95；评估器耗时与整个优化流程耗时分开。
- 已知Token、记录是否完整、未知用量的调用数；不能拿不完整小计宣布节省费用。

首批三题的“可供人工复核候选”门槛可固定为：9次全部完成并匹配人工标签，R001/R016不退步，未突破已授权成本与等待预算。7/9或8/9属于局部改善，可记录但不达到该门槛。真实无效或全失败也应正常完成工程闭环，不要求模型必须找出改进。

结果区分IMPROVED、NO_GAIN、REGRESSION、INCONCLUSIVE和INVALID_EXPERIMENT。完成率改善但用量未知时，可记录可靠性改善，成本仍不确定，不自动升级成“整体最优”。不得把等待时间增加后完成率改善说成“推理速度优化”。

### 4.6 实验记录与候选管理

记录experiment_id、父实验、输入/标签/代码散列、反馈、原始受控建议、校验结果、实际Profile、每次请求、逐轮结果、对比结论、预算消耗和停止原因。

不可覆盖历史。建议、结果与真实来源数据保存在Git忽略的本机私有目录，普通日志只写ID、状态、错误码和耗时，不写正文、Prompt、密钥或原始异常内容。

自动比较后的“保留候选”只表示保留实验产物，不是自动启用生产策略。项目agent.md要求自动学习只创建候选Skill、不得直接覆盖ACTIVE Skill；未来上线需复用候选评测、人工批准与回滚流程。本阶段不实现发布。

## 5. 状态流与系统位置

```text
FEEDBACK_READY → PROPOSING → PROPOSAL_READY
  ├─ NO_CHANGE / OPTIMIZER_FAILED → 保存并结束
  └─ VALIDATING
       ├─ REJECTED → 保存并结束
       └─ VALIDATED →（显式live执行授权内）
            CONTROL_RUNNING → CANDIDATE_RUNNING → COMPARING
            → IMPROVED / NO_GAIN / REGRESSION / INCONCLUSIVE
            → 保存候选或失败记录，不自动发布
```

首次做独立离线CLI，不塞进用户上传或问答链，也不修改现有LangGraph状态。它是实验驱动器，不另起外部多智能体平台。服务对象仍作为运行时依赖，不能写入状态或JSON记录。

未来B接入线上时，动作必须成为真实白名单Tool，由现有LangGraph的planning/tool-dispatch集中校验，并对齐Adaptive Planner的Tool Catalog、授权与预算。需要业务写入时保留AgentRun、ToolInvocation、ChangeSet和OperationPlan，不能用本机实验JSON替代线上审计。

## 7. 开发顺序与验收

1. **先做协议和反馈整理。** 用两组现有真实报告整理出“截断”和“读取超时”，无需再调用模型。验收：不能把R034当NORMAL或MISSING，反馈不含Gold、原文、密钥。
2. **做建议器与校验器。** Fake覆盖NO_CHANGE、合法候选、两变量、非法字段、编造反馈、重复无效候选、优化器失败。验收：合法schema不等于可执行，越界候选一律不运行。
3. **做受控执行与比较。** 用确定性Fake分别跑出改善、无效、退步和中断。验收：预算逐请求生效，失败计入分母，正常题退步会被发现，历史不覆盖，原快照/标签字节不变。
4. **串成一次完整离线流程。已完成工程验收。** 不用真实模型即可验证“反馈→建议→校验→复测→比较→记录”，加入历史回写与下一轮继承；Fake报告不可冒充真实优化结果。307项相关回归通过，原真实实验只读重算仍NO_GAIN。
5. **再显式执行一次真实闭环。** 模型看到真实失败摘要并自主提出允许范围内的一个候选；程序受预算约束执行和评分。无改善也保留结论，不人工调标签替模型过关。
6. **扩充与隔离测试集。** 新增真实或明确标记的派生冲突/旧版本样本。策略研发集与冻结保留集分开；不能用给建议模型反复看过的同三题证明泛化效果。通过后再设计B阶段的任务策略实验。
