# Harness下一步：从修改一条旧规则，扩展到改进模型的任务规划

日期：2026-11-12，2026-11-16更新。状态：A、B、C工具已完成开发和工程验收；B-v2已有真实首轮改善，14题真实C验证已完成但未通过，现接通开发集有限自主迭代；D仍为后续方案，不改线上配置。第9—12节保留阶段交付记录，最新进展见第13节。

## 1. 先说清楚当前做到哪里

`self-live-v3`已经完成一次真实、受限的自主修改：建议模型读取失败反馈，自主生成条件补丁，程序在隔离副本中应用，再由独立比较器复测。两题首轮路由从1/2提高到2/2，补丁只保存在实验目录。

目前的边界是：只支持legacy模式，只能给`agent/planner.py`的一条前置判断增加保护条件，只检查首轮路线。它尚不能改进整个执行框架，也未验证真正检索、读取和最终回答是否成功。

Adaptive接入与自主修改是两个不同问题：前者决定日常任务是否由LLM提出工具计划；后者决定优化模型能否自主修改任务执行策略并验证。接入Adaptive本身不能当作自主优化已经完成。

## 2. 下一步优先开发什么

建议先开发“Adaptive规划的离线评测与自主优化入口”，复用项目已有Adaptive Planner，不重写整个Agent。先证明它实际由模型生成步骤，再让Harness依据该模式自己的失败提出修改。

目标流程为：

```text
固定真实任务和原始授权范围
→ Adaptive Planner由LLM生成计划
→ 后端校验工具、参数、文件范围和确认要求
→ 保存模型计划、后端接受/拒绝及降级轨迹
→ 独立程序判断是否做对
→ 优化模型根据失败提出受控候选
→ 隔离副本运行候选并与同版原版比较
→ 保留有效候选，或如实记录无收益、退步、无法判断、不修改
```

程序仍负责权限和执行约束；普通业务目标与工具步骤主要由模型提出，不能用泛化关键词擅自覆盖有效计划。

## 3. 分四个小步骤推进

| 步骤 | 开发内容 | 怎么知道完成 |
|---|---|---|
| A：接通Adaptive评测 | 隔离worker支持明确的Adaptive实验配置，模型代理支持PlannerDecision请求，保存实际模式及回退轨迹 | 同一输入可以真正运行Adaptive；明确识别模型生成的步骤和后端校验结果，不能回退legacy后冒充Adaptive成功 |
| B：开放一类可优化策略 | 依据A中真实失败，固定一个可修改的策略模块或区域，让模型生成实际候选，而非选择人工预写修复 | 候选有真实差异、可追溯假设，通过隔离与独立复测；允许有依据的NO_CHANGE |
| C：扩大并重复验证 | 增加开发题、独立保留题，固定候选多轮复测，比较正常题退步 | 不依赖同两题的一次通过；报告逐题结果、适用范围和成本完整性 |
| D：接通完整任务执行 | 从首轮计划扩展到实际检索、读取、证据状态评估和回答，保留每步观察 | 不只选对路线，还能找到材料并生成有证据支持的回答；策略改善能在最终任务结果中体现 |

最近的一次开发先做A。不能直接把`adaptive_mode`改成enabled就开始收费试验，也不能仅移除legacy检查后声称兼容。

## 4. A步骤需要改哪里

- `improvement/service.py`：实验身份和预检查支持明确的规划模式，保持原legacy实验入口；为Adaptive建立新基线。
- `improvement/worker.py`：按可信宿主交付的受控模式构造测试配置，继续禁止读取上级.env，不接收任意配置或模型密钥。
- `improvement/executor.py`：模型代理核验Adaptive的系统提示、PlannerDecision schema、原问题、附件和Catalog；回退请求全部计入预算，不能放开任意Prompt外发。
- `routing/runtime.py`与`diagnostics.py`：复用现有planning节点，完整记录模型计划、实际模式、后端转换和降级，不只依赖最终intent猜模型是否参与。
- `improvement/comparator.py`及反馈：只读核验同版输入与授权，区分“找文件”与“先发现文件、再回答”的业务目标。两者首步可能都是hybrid-search，不能只看工具名评分。
- 测试及操作文档：增加Adaptive成功、非法计划、范围错误、模型失败、回退、预算和模式身份篡改等Fake测试；真实运行依然显式live。

旧数据和旧报告不覆盖。原问题、附件与上下文保持不变，在新实验身份中明确指定Adaptive模式，固定模型及Catalog；不能暗改原冻结集后沿用其散列。Legacy和Adaptive可做迁移对照，但补丁效果必须用同模式原版/候选比较，不能把模式切换与代码补丁混成一个变量。

## 5. B步骤应开放什么，而不是预先替模型修什么

可考虑的目标包括：提供给规划模型的上下文如何组织、任务规划说明、读取工具观察后如何继续。只选A步骤证明存在问题的一类，先冻结允许修改的文件、输入输出和检查规则，再接候选协议。

候选可以是模型生成的策略配置或源码补丁。若涉及源码，必须新增对应的受控差异校验与回归，不能把当前“只允许增加and条件”的校验直接撤掉；若是模型生成的提示内容，仍需保存真实内容和版本，不能把人工固定提示的选择包装成自主生成。

文件权限、Tool白名单、确认要求、Gold、独立评分器、外层总预算和隔离器始终由可信程序控制。优化对象是任务执行框架中的策略，不是让模型修改自己的裁判或解除运行限制。

不能将R002在legacy中的失败当作Adaptive也必然失败。先测新的真实基线；若已正确，保持不修改，再从其他真实失败中选目标，不人为制造错误来证明优化成功。

## 6. 测试和预算要求

现有两题仍用于冒烟与迁移核对；原成功补丁作为可追溯实验资产保留，不直接上线。固定补丁的重复验证应使用锁定候选的评测方式；重新运行self-cycle会重新请求建议，不能假称复测的是同一补丁。

扩大样本时，先选含正常找文件、正文问答、明确附件、缺少文件范围及需要澄清的开发题，独立人工确认路由标签。已有15题材料题库可供选取，但旧证据状态Gold不能直接当作路由Gold，未采集的真实上下文也不能编造。

保留集不向建议模型提供逐题标签和答案；如果用于继续修改策略，就应转为开发数据，补充新的独立保留题。两题上的P/R/F1不能证明一般可靠性。

每题模型请求可能包含Adaptive、Legacy回退及修复，需根据实际执行路径重新核算上界，再由操作者固定总请求、总时长和重复次数；模型不能自行加预算。不能直接套用旧两题26次授权运行更大集合。

开发验收使用Fake及本机真实隔离，不发起收费模型请求、不切换线上模式、不安装服务。A完成后提供默认检查和显式live步骤，再按真实失败进入B。

## 7. 与原四阶段的关系

原来的“机器反馈、生成候选、隔离执行、自动验收”继续复用。这份方案扩展的是它能评测和修改的对象，不另起一套不相干的Harness。

完成A只能声明“Adaptive规划已可独立复测”；完成B且真实比较改善后，才能声明“模型自主改善了这一类Adaptive策略”；完成D后，才能对实际检索与回答质量作出结论。正式启用仍须经过独立回归和可回滚发布。

## 8. A阶段实施细化（代码修改前冻结）

新增独立的`planning-evaluate`和`planning-compare`入口，先跑原版规划基线，不调用建议器、不生成补丁。`self-cycle`原有legacy代码补丁流程保持原范围；不能通过A阶段顺便开放Adaptive源码修改。

`planning-evaluate`读取原冻结路由数据集，操作者通过`--planner-mode enabled`（或legacy）显式固定本次实验模式，只在本次输入副本中覆盖模式，并保存原数据集散列、原模式、新实验模式及实际输入身份。原题干、附件、上下文、Catalog和Gold都保持原样，不写回源数据。默认只检查，追加`--live`才运行；输出只能是全新私有实验目录。

复用已有隔离器、模型预算日志和真实LangGraph planning节点，新增`improvement/planning_evaluation.py`负责基线驱动，`service.py`提供预检查/运行接线，`comparator.py`提供只读重算接线。预算上界按`题数×重复次数×3`计算：首轮Adaptive1次、Legacy回退最多2次来源参数修复；没有建议请求。每题最多3次，所有失败和回退计入同一授权，总时限含隔离启动及检查。

worker只允许宿主明确传入legacy或enabled，不允许shadow或任意配置；规划输入模式必须等于宿主模式。模型代理仅接受两套真实服务的固定Prompt/schema及原始输入，Legacy请求只有在Adaptive已实际尝试后才能作为回退出现，权限不放宽。

离线运行新增私有审计：保存每次模型返回的原始结构、请求身份、schema校验、后端接受/拒绝轨迹、最终计划来源，以及Adaptive→Legacy→规则的真实路径。原始结构只在Git忽略的实验文件内；普通日志仍不含Prompt、响应或任务正文。即使最终路线正确，回退产物也不能计入“Adaptive独立正确率”；另行报告整个降级链任务结果和有效模式占比。

独立比较器从绑定数据集、调用记录和模型原始结构重放纯规划（不再调用模型、不执行Tool），复算最终计划和模式；不能信候选自报模式或缓存分数。为保证重算只读，在`core/logging.py`增加仅离线回放上下文生效的静默选项，默认行为不变；不关闭线上审计。工具路线分类覆盖受控正文意图同义枚举，首步同为hybrid-search时仍区分“文件列表”与“发现证据后回答”。

验收采用Fake和真实OS隔离，覆盖Adaptive成功、schema非法、未知工具、文件越界、需要确认的步骤、回退成功、全模型失败、来源修复、无模型预检、预算耗尽、中断、模式/请求/审计篡改及默认零调用。完成后提供真实两题基线命令，不实际启动收费调用，不安装服务或切换线上设置。

## 10. B阶段交付

当前两题一次对照上界13次，通常5次。源A数据、实际输入、Gold、模型/接口、Catalog和原版源码绑定；两组从同一快照开始。独立比较器重建候选、核验唯一字符串差异并重放两组请求和计划，回退不能算Adaptive自主改善。实际检索和答案仍未执行。

下一步由用户按B操作文档运行真实候选。只有真实比较改善后，才能声明这类Adaptive策略在本次开发题上得到自主改善；之后按C扩大并重复验证。
