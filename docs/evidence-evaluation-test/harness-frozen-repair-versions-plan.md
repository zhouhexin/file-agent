# Harness 自修复：逐版本冻结与测试

日期：2026-11-20。

## 1. 本轮规则

发现错误 → 判断类型 → 生成受限补丁 → 冻结独立版本 → 模拟测试 → 小规模真实对照。

不设置胜者，不自动留用，不替换参考方案，不因初测分数低而跳过某个已冻结版本。每个版本有固定身份、补丁、模拟结果和独立的真实对照结果。编译失败、越权或未通过受保护检查的版本明确标记阻塞，不能为了“每版都测”绕过安全检查。

冻结版本不代表质量合格。业务分数低、无提升或回归都如实保留。预算不足、连接故障或中断导致未测的版本必须逐一列明，不能当成已完成或自动重试。

## 2. 第一批受限补丁边界

沿用当前实际支持的唯一 AST 白名单：`adaptive_planner.py` 的提示字符串常量，原系统提示逐字保留。第一批不开放任意 Python 函数体修改。生成模型可提出完整规划补充说明，并选择是否由可信宿主机械附带实际应用意图清单及参数约束。意图清单来自现有映射，参数限制来自真实 Tool schema；生成模型不能自行编造枚举或放宽阈值。

契约信息直接写入候选实际会收到的系统提示，明确提供数据内容，不再只引用规划模型没有收到的 `application_contract` 对象。仍受总长 3000 字符、样本泄漏、命令文本和 AST 限制。此方式修复契约交付信息缺口，不宣称实现了任意代码自修复或强制保证模型永远输出正确参数。真实效果必须逐版测试。

网络、认证、额度和代理问题只做固定诊断及停止处理。连续基础设施调用失败达到冻结阈值时停止，不自动改配置。评分器、题库、Gold、权限、真实业务文件和现有生产代码不属于修复目标。

### 生成阶段单次调用失败的修正

首批真实运行中，第1版已冻结，第2次建议调用在17.516秒后收到 CLI `turn.failed`，诊断为 `PROVIDER_ERROR` 且带连接线索。原生成循环把异常直接交给整批兜底捕获，造成单次失败即停止，和连续失败阈值的预期不一致。旧 `VERSIONS_FROZEN` 也只表达“存在可测版本”，容易误读为整批成功。

新协议 `frozen-repair-versions-v2` 在每份版本内处理建议调用失败：保存 `generation-failure.json`，标记 GENERATION_FAILED；对连接、超时、提供方或返回格式失败，在原轮数、请求数、时限内继续下一版本，不重试同一版本，不自动补足成功数量。连续基础设施失败仍由同一 Journal 累计，达到阈值停止；认证、权限、额度、限流错误立即停止。未发出请求的预算停止不伪造版本调用失败。

只有全部版本可测时显示 VERSIONS_FROZEN；已有可测版本但其余失败、被拒或未生成时显示 PARTIAL_VERSIONS_FROZEN。阶段与逐版本诊断一并展示。

只兼容已知 v1 控制器 `2ae38a5395b87797b2bcb04ecc492aef8eccaa2db87d4c62b25c7793e2a9c533`，仍重建原提案、请求、补丁及模拟结果。旧批次中没有单独失败文件的调用从原账本只读推导；不改写旧缓存或清单。已有0001可继续测试，不必重生成。旧编译、评分及隔离身份不变。

## 3. 冻结与模拟

新增独立 `repair_versions` 协议和 CLI，保留旧 reference-loop 协议及历史结果。来源继续使用已经核验的开发集、固定参考方案和只读导出的诊断记录。

建议器根据标准化错误摘要及真实契约提出候选；每份提案记录原始 JSON、来源引用和真实调用账本。有效补丁生成独立版本号、提示身份和差异。模拟测试执行原固定编译与受保护回归；另外记录契约交付和参数校验检查。模拟不调用真实规划模型，不把模拟通过当成实际业务质量提高。

模型返回非法提案时记录 REJECTED；已冻结但模拟未通过时记录 SIMULATION_FAILED。二者都出现在版本列表中，不能悄悄消失。旧参考和各版本互不覆盖。冻结目录封存后只读，真实测试输出必须使用另一个新目录。

## 4. 真实对照

默认按每个版本单独给命令，由操作者显式 live 启动，不隐式花费。也提供显式选择全部版本的入口，共用一次授权的总调用及时间预算。仅未通过安全/模拟检查的版本阻塞；分数低不阻塞。

每个版本与同一份旧参考使用相同开发题、相同 Profile、相同重复次数，独立交错运行。没有建议器调用、选优、父版本更新或提升后留用。全部预定试次包括失败、预检和回退继续参与原评分。原始提示与旧参考之间的首次对照不按版本重复执行，固定对照始终为旧参考与该版本。

所有本次测试共享 Journal。达到总额度、时限、连续失败阈值或人工中断后停止，保留未完成试次及各版本状态；下次需要新目录及明确新授权。

## 5. 独立核验及验收

独立比较器重新核验来源、诊断身份、实际提案输入、机械契约生成、完整补丁、快照、模拟结果、版本选择、真实请求、配对评分和总预算。不能只读取缓存赢家或自报成功。旧实验和旧控制器身份不改。

确定性模型替身覆盖：所有版本均列出、同分及低分版本可测、无自动留用、契约具体名称确实进入候选提示、非法补丁拒绝、模拟失败阻塞、固定参考不变、总预算不重置、连续调用失败停止、未测版本显式列明、重封篡改拒绝、CLI 默认零调用。真实 Windows 子进程做独立专项，模型仍用替身。本轮不自动发起真实付费实验。
