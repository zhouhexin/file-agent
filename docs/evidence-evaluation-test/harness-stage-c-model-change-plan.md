# C阶段补充：旧模型额度耗尽后，明确使用新模型复测

日期：2026-11-13。状态：开发前写入；现已实现并完成工程验收，未运行新一轮真实模型测试。

## 1. 为什么需要这次改动

第一轮C实验遇到旧模型额度耗尽，大量调用失败，结果不能证明候选是否有效。现在测试配置已经更换模型，原程序为了防止把不同模型结果混在一起，会在调用前报`VALIDATION_MODEL_PROFILE_CHANGED`。

这次允许操作者明确选择：用当前新模型，同时运行原版提示和已经固定的候选提示。比较的是“同一个新模型使用两种提示”的表现；不能把新模型分数直接减去旧模型分数，当成提示优化收益。

## 2. 最小改动

1. 仅给C的`adaptive-validate`增加`--allow-model-profile-change`。默认仍要求与候选来源B使用相同模型和接口；没有开关时，配置不同仍在建目录和调用模型前拒绝。
2. 检查输出列出来源配置、当前配置的脱敏身份、模型/接口是否改变，以及`SAME_MODEL`或`CROSS_MODEL`。只保存模型名和接口的哈希，不保存密钥或私有接口明文。
3. 新实验使用`adaptive-validation-experiment-v2`，固定来源配置、实际配置、允许变更的选择和比较范围。开始执行前复制当前Settings，两组共用这一份配置，不在轮次中重新加载env。
4. C逐次模型调用的开始和结束记录增加实际配置身份。独立比较器核对每次调用和实验配置一致，也核对来源配置确实来自锁定B实验。建议器仍不参与；A、B及原自改流程的记录格式不变。
5. 明确保留已知旧C执行器身份`6d1f4185af9a05b3fe2c355f2d7c69f2fe4725bf495e8bd8e44b3bd4ae9d043b`的只读重放，按旧版同模型规则核验。未知旧身份仍拒绝，不修改任何旧产物。

## 3. 不改评分和候选

继续使用已经冻结的14题、人工标签、开发/保留分组和原候选。不会重新请求建议、重写原题、调整Gold或改正式运行提示。新实验另建目录，不续跑旧实验，不合并两轮分数。请求/时长总预算、隔离、白名单请求核验、原始响应重放和不自动上线的边界继续生效。

本改动只解决更换模型的受控复测。原R035走确定性预检、没有进入Adaptive的情况仍如实记为不可用于本阶段策略比较；因此修复额度问题后，也不能保证本批最终为`VALIDATED`。
