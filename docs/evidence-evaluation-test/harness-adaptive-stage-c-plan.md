## 2. 数据准备与人工确认

新增`adaptive-validation-prepare`，从已经独立核验的B候选及原A真实任务开始，合并一个或多个既有`routing-prepare`导出的真实inputs。原两题保留原句、原附件、原上下文和源运行身份，只在新的C输入副本统一启用Adaptive；新增题必须来自真实运行，不把参考文件清单或预期附件伪装成实际上下文。

生成独立私有`dataset-draft.json`和中文核对说明。原两题可复用原人工路由标签，但所有题的分组、文件族和决策要求仍需操作者确认；新增题不从证据状态Gold推导路由Gold。正式`adaptive-validation-freeze`逐题检查后另存新冻结文件，旧题库和旧实验不改写。

每题记录：题号、DEVELOPMENT/HOLDOUT、业务文件族ID列表、预期路线、可选的预期决策类型、人工理由、confirmed。对于OTHER必须明确预期决策类型，避免把任意OTHER误算为正确澄清。

冻结至少4题、比B原题更多，开发和保留各至少2题、各含正文任务和文件清单；原B两题必须在开发集并保持原输入。可增加有真实附件的正文题及缺少范围需CLARIFY的题。报告实际覆盖，没有哪类就不声称覆盖。建议目标为开发6题＋保留4题，未采到或未确认的题不能凑数。

隔离检查包括：输入、题号、源运行唯一；原两题或相同原句不得放入保留；两个集合不得共用业务文件族或实际文档ID。文件族必须人工核对，不能把不同文件ID自动当成不同业务族。无法自动证明的隐式同族和历史暴露情况需人工确认；用保留集继续调参后，该批保留题失去独立验收资格，需要换新材料。

开发时可只读盘点本人测试库现有任务并导出真实上下文，连接失败或任务不全时给出缺项。选择运行依据固定时间顺序和明确范围，不按模型是否答对选择。未确认的新标签始终保留草稿，不代替用户确认。

## 4. 执行和预算

新增`adaptive-validate --dataset <冻结C题库> --output <新实验> --max-requests <明确额度>`，默认只检查、不建实验目录、不调用模型。检查展示题数、开发/保留题数、重复次数、实际总上界、预算能否覆盖、锁定候选身份。追加live才运行。

C没有建议调用。请求上界=`两组×题数×重复次数×每题最多3次`，2—3次包含原Adaptive、必要的legacy回退及来源参数修复。10题3轮最坏180次，正常无回退通常60次；不能沿用B的13次当作扩大集完整授权。操作者必须明确max-requests；默认总时长3600秒，可显式在7200秒内调整。每次60秒，所有失败和回退共同记账，时限包括源核验、准备和隔离检查；时间不足即停止，不自动增额或续跑。检查会说明最坏请求等待可能超过总时限。

所有重复使用同一冻结输入和同一候选，从同一原版快照构造两组，只允许原提示字符串追加内容不同。按重复轮次交替原版/候选先后顺序，完整记录试次顺序和请求；不中途挑表现最好的一轮，不把失败或未运行题剔除。编译、原五项固定legacy保护回归和OS探针继续执行。

只向规划Provider发送既有白名单Prompt/schema、当前题原句和原上下文，不发送Gold、分组、人工理由、文件族或保留集评分；C不会调用ADVISOR，不产生优化反馈包，不自动把保留结果传回B。

## 5. 独立比较

新增`adaptive-validation-compare`，只读重新核验源候选、冻结题库、人工分组、所有调用、执行顺序、预算、源码及原始模型结构，重放两组真实规划，拒绝相信缓存分数或候选自报模式。

逐组、逐集合报告全部预定试次的Precision/Recall/F1、逐题正确次数/总次数、预测变化、Token和延迟；额外报告schema通过但intent未识别的比例。SEARCH01这次路线正确但intent为FILE_SEARCH，不能因此声称意图契约完全解决。

决策顺序：明确安全违规、任何配对试次由对变错、或正常题意图契约出现新退步时标REGRESSION；条件不足、失败/回退/预检导致未完整比较时标INCONCLUSIVE；完整运行、开发集正确数增加、保留集不退步且候选保留集全对时才标VALIDATED，否则NO_GAIN。VALIDATED仅限本批首轮规划，不是生产发布许可或答案质量证明；稳定性和样本规模仍单独展示。

预期决策类型是本阶段额外人工标签。原工具范围检查及真实意图路线分类不更改；本阶段不通过修改裁判把候选已有错误改成正确。

## 7. 实现中的必要细化与验收结果

为方便人工，只需编辑独立`annotations-draft.json`，冻结时通过`--annotations`传入；大文件中的Catalog、真实输入和来源不需编辑。程序会重新核验真实来源，标签文件不能更改任务范围。原A两题的已确认路线保持不变。

带附件验收发现既有代理按原附件元数据核验，而真实Planning使用`graph._planning_attachments`从后端context合并元数据（缺少时为null），导致合法请求在模型调用前被拒绝。最小修正`improvement/executor.py`复用同一纯投影：仍固定原document_id和context，未经后端核验的附件文件名仍不外发；未修改真实规划代码、路由或旧评分。增加专项对抗测试验证前端元数据不能绕过。

所有失败试次记录明确阶段、脱敏异常类型及受控cause_code；未知异常正文不保存。规则回退中的不支持步骤保留为观察，不归因于未成功运行的候选；只有有效Adaptive配对才判业务/契约退步，真实候选安全违规单独拦截。

工程验收346项相关回归通过，普通回归按设计跳过9项OS用例；本阶段真实OS专项另行1项通过，完成六题、两轮、24次Fake规划请求、零建议器调用，并验证env/Gold/其他实验不可读。C快速专项29项包含在相关回归内，不累加。JUnit为`planning-stage-c-related.xml`和`planning-stage-c-os-acceptance.xml`。
