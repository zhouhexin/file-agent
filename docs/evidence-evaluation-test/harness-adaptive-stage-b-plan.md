# B阶段：让模型自主改进一类规划提示

日期：2026-11-12。状态：本方案在开发前冻结，现已按方案完成开发和Fake验收；真实模型由用户显式live。操作见[B测试步骤](harness-adaptive-stage-b-usage.md)。

## 1. 先用真实测试确定问题

已在改代码前独立重算`adaptive-baseline-v1`：两题都由Adaptive完成，无模型失败、无回退，正确1/2。R002要求根据通知回答正文问题，模型却生成自由文本intent“定位2024年教工党支部换届工作通知原文”。其user_goal保留了后续回答目标，但程序未获得受支持的正文任务意图。SEARCH01只要求列文件，当前正确。

这是已观察到的“业务目标与应用意图表达不一致”，不是网络错误，也不能仅凭首轮检索计划断言最终答案失败。本阶段评分仍限首轮路线，不改Gold或裁判，不把找到材料、生成答案算作已验收。

## 2. 只开放这一类策略

让建议模型依据机器反馈、实际模型决策和应用契约，自主写一段通用的Adaptive规划补充说明。不是选择人工预写的修复，也不由程序替它填入正确intent。

候选唯一允许改变`app/modules/agent/adaptive_planner.py`中`ADAPTIVE_PLANNER_SYSTEM_PROMPT`的字符串值：原提示逐字保留，只追加模型生成的说明。其余AST、函数、工具、后端校验、权限、确认要求、Gold、预算和评分器均不允许修改。候选只写实验副本，当前活动提示和线上设置不变。

补充说明最多3000字符，禁止样本ID、完整题干、UUID、路径、Shell或SQL片段，不能写逐题答案。通用说明是否有效必须靠复测；文本检查不代替后端安全约束。保留NO_CHANGE，以及证据不足、超出范围等理由；已知任务错误时不能声称所有题都正确。

## 3. 最小流程与新命令

新增`adaptive-cycle --baseline <A实验> --output <新目录>`，默认只检查。检查源A产物、独立分数、数据集、Catalog和源码身份，不建目录、不调用模型。显式`--live`后：

1. 从A原始记录重建反馈，不信缓存feedback或comparison。只给建议器开发集对错和原模型决策，不给Gold标签、Gold理由或参考答案。
2. 在当前同版原始源码快照上验证OS隔离，整个实验只有一个总预算。
3. 调用一次建议器，得到真实补充说明或有依据的NO_CHANGE。
4. 严格校验反馈引用、源码散列、候选协议与唯一字符串差异；保存真实补丁、原版/候选提示身份。
5. 从同一快照创建原版和候选，执行编译和已有五项固定legacy保护回归；不执行业务Tool。
6. 同题、同附件、同上下文、同Catalog、同模型和额度，在两组中运行真实planning节点；保存模型原始结构、后端校验、真实模式及回退。
7. 独立重放两组模型结构评分，得到IMPROVED、NO_GAIN、REGRESSION、INCONCLUSIVE或NOT_RUN。保留候选，绝不自动应用线上。

新增`adaptive-compare --experiment <B实验>`只读核验并重算，不发模型请求、不改实验记录。一轮只生成一个候选，不自动重试建议器；更大题库及固定候选多轮验证留给C。

最坏请求数为`1 + 2 × 题数 × 重复次数 × 3`，现有两题一轮为13次（通常建议1次、两组各2次，共5次）。建议器默认8000输出Token，规划默认3000；每次60秒，总时长1800秒；失败、回退、中断请求均记账，用量未知不能记为0。总时长含源核对、快照及隔离检查，不自动增额、不自动续跑。

## 4. 独立比较如何避免自报成功

先从可信程序和提案重建候选字符串及源码，逐文件验证两组只差这一个提示字符串。由于候选不能修改任何执行代码，比较器可用原版纯规划和记录的模型返回重放，仅在模型请求处代入已验证候选提示，逐次核对真实请求散列、模式、最终计划和校验轨迹。不得相信缓存分数、候选自报模式或被修改的提示。

只有两组都完整使用Adaptive、无失败/回退、无安全违规且无逐题退步，候选正确数严格增加，才判IMPROVED。回退后答对、未执行、接口失败不能证明策略改善；正常题退步判REGRESSION。两组相同不等于没有错误。

原A实验不改写。新增Harness模块会改变执行器整体散列，因此为已验收的A-v1执行器登记明确兼容身份`1ddc155c057fc27fe36349b51d5994d1cbf9e43229a305d395cf5f9cf43a2a2e`；仅接受该已知版本或当前版本，且仍要求原快照每个源码文件与当前源码相同、原始记录完整、原决策可独立重放。不是忽略任意旧版本身份；真实规划代码或评分逻辑变化时必须重新建立A基线。

## 5. 文件及接入位置

新增`improvement/adaptive_policy.py`：提案协议、反馈、受限补丁、隔离对照与独立比较。新增`test_adaptive_policy.py`和操作文档。

不修改线上Adaptive提示、用户env或数据库，不移除legacy源码补丁限制，不开放任意文件修改，不引入多智能体或新服务。

## 6. 验收

Fake模型验证真实候选说明进入候选规划请求、原版提示不变、同一输入对照、IMPROVED/NO_GAIN/REGRESSION/INCONCLUSIVE/NO_CHANGE、反馈引用与解释校验、无Gold外发、未知用量、失败/回退、来源篡改、预算、中断及默认零调用。篡改候选源码、提示、调用、模式或缓存不能蒙混过关。

macOS真实隔离验证候选补丁副本可运行，worker仍无法读取上级env、密钥、Gold或其他实验。原A、legacy自主补丁、路由和日志回归通过后交付命令。工程Fake改善不代表真实模型已改善，最终效果待用户live。

## 8. B反馈补全改进（修改代码前冻结）

用户已运行`adaptive-policy-v1`，独立重算为NO_GAIN：原版、候选各正确1/2，均无回退、接口失败或安全违规。建议器把问题猜成检索条件偏离，生成的补充说明强调首轮只表达文件发现目标，未解决自由文本intent不能映射正文任务的问题。本次只补齐反馈和建议器解释规则，不改路由、Gold、评分或线上规划提示。

新增`improvement/planning_feedback.py`，从已经独立核验的原始记录重建三组机器事实：

- **最终任务目标**：原始用户请求及模型`user_goal`原文，标明后者只是模型声明，不自动当成人工正确答案。程序不靠关键词或Gold给目标贴语义标签。
- **当前工具动作**：实际被接受计划的首个工具及其职责，例如hybrid-search表示发现文件；明确只有计划、尚未执行检索或回答，当前动作不能替代整项任务目标。
- **意图契约**：分别记录模型原intent、后端最终intent、JSON结构校验结果、应用支持的意图映射和实际路由。对已接受的hybrid-search计划，intent无法映射受支持的正文/找文件目标时，记录`UNRECOGNIZED_TASK_INTENT_FOR_DISCOVERY`这一确定性观察。它不是JSON结构非法，也不独立证明最终目标语义错误、检索失败或最终答案失败。

新反馈使用`adaptive-policy-feedback-v2`，每条增加`task_diagnostic`及其来源、确定性和未验证事项，完整内容写新实验私有feedback.json；不外发Gold标签、Gold理由或参考答案，不进入普通日志。受支持意图与现有离线路由映射保持一致，不新增一套线上判定规则。

建议器提示明确区分“最终要做什么”和“首步做什么”：正文回答可以先发现文件；schema通过不等于intent能被应用理解；发现步骤本身不代表最终目标只能是文件清单。已观察到的契约问题优先作为分析依据，尚未执行的检索或回答效果只能是假设。具体候选说明仍由模型生成，保留合理NO_CHANGE，不预写修复、不强制出补丁。

新实验使用`adaptive-policy-experiment-v2`并绑定反馈版本。旧B-v1的原始反馈、建议Prompt和提案上下文按v1重建；只为已核验的B-v1执行器身份`e25373b92fc653045866e653c3d6a9813b344c65eba04440d3fd88d7034130a7`保留只读比较兼容，仍核验完整性、原快照、真实请求和原计划；未知版本或新旧反馈混用拒绝。旧NO_GAIN记录不能被新版反馈重写。

命令保持不变，默认检查新增反馈版本和契约问题计数，继续零调用、不建目录；新输出用`adaptive-policy-v2`。用户追加live后建议器读取新版反馈并提出一个新候选，再执行同模式原版/候选对照。预算仍为两题最多13次、1800秒，不自动续跑、加额或上线；开发使用Fake和真实OS隔离，不发起收费请求。

验收覆盖：自由intent+结构通过、受支持正文intent+发现步骤、正常找文件、无首步、非发现Tool及缺失字段；证明不根据Gold推断目标、不强行用首工具改写最终目标；新反馈和Prompt确实送入建议器、合理NO_CHANGE、反馈篡改拒绝、旧v1精确只读重算、默认零调用与隔离边界。同步操作文档与README/runbook。
