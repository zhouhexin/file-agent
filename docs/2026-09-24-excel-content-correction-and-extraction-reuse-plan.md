# 已发布 Excel 内容修正与提取结果复用方案

日期：2026-09-24

状态：待实施；本文件是方案，不表示已修复服务器 Excel。
范围：专用职称材料 Skill、新 Excel 完整文件回传链路、结构化数据集与同名工作副本。保留旧的结构化数据集追加/导出功能。

## 1. 现状与问题边界

只读核对了此前提供的人工填报样表、对应 PDF、目前服务器的同名 Excel、该文件的历史版本、数据集记录、已有来源提取记录，以及专用 Skill 的列来源映射。服务器文件确实存在，且已有一行发布数据；本轮主要是**单元格内容选择与表达错误**，不能再按“文件没有生成”处理。

以当前数据行与人工样表作诊断对照：L 列人工样表有 2022、2024 年度优秀信息，当前为空；O 列当前学生信息明显少于样表；J、R、S、T、U、V、Y 等列有不同程度的范围、文字或勾选条件差异；E、K、M、P、Q、X 等列则出现“样表留空而当前写值”的情况。当前行也没有应按**整列标题条件**判定并放在数据格末尾的 `√`。这些是待核验的差异，不等于可以直接照抄人工样表：样表只提供预期结构与检查线索，最终事实仍必须来自上传的 PDF 和有效审批证据；样表留空也不能自动推断来源事实必须留空。

现有 PDF 的 WorkBuddy 提取结果已持久化，25 页文本可用；另有复用提取运行记录。当前已存来源元素中没有可直接定位的印章 bbox，因此“某年优秀”这类文字事实虽可复用，L 列是否满足盖章审批仍需核对末页方形印章，不能凭页内出现“人事管理科”等 OCR 字样推断已盖章。其余涉及审批的列同理按证据缺口决定是否只做定向图像核验。

现有完整文件回传工具的本地写入器仅在空白数据格写值，服务端校验也禁止改动已有非空格；发布过程按新增记录/追加行处理。因此，直接重跑现有 `checkout → apply → publish` 会被拒绝或造成重复人员行。已发布行修正必须与新增行追加分开设计。

## 2. 目标和不变量

1. 修正当前目标工作表中**已写入的那一行**，不新增第二个人员行；保留其他行、公式、样式、合并、图表及非目标工作表。
2. 对 A–AA 每列给出“保留/改写/清空/无法判定”的决定、来源页或单元、审批范围和理由；B–I 身份列继续按专用 Skill 的身份字段规则处理。人工样表仅用于发现差异，不能当作 PDF 证据。
3. 来源事实与审批结论分别存储和校验：J、K、M、O、P 等允许按 Skill 规定写入注明状态的无章来源事实；L、N 及 Q–Y 中需要审批的内容不能以未盖章文字冒充通过。签字不能替代印章，印章须能绑定具体范围。序号不是填写前提，按现行 Skill 的整栏、勾选、跨页和末项规则定位。
4. `√` 只在该列标题的完整条件已满足、且该单元格写入范围整体符合要求时，在**该数据格完整文字末尾出现一次**。不在每个小项、标题、来源引文或不达标字段后添加。
5. 工作副本实际 basename、文件列表名称与下载名称保持一致；每次修正产生新的 `DocumentVersion`、数据集修订及审计记录，不生成第二份用户可见 Excel，也不覆盖上传原件。
6. 原则上不重跑整本 Excel 解析或整份 PDF OCR。复用条件由内容哈希、版本、提取器版本、页覆盖率和证据完整性共同决定；缺少印章定位时只复核相关页/区域。

## 3. 修正流程

### 3.1 确定唯一目标与冻结基线

通过当前 Excel 的稳定 Document ID、WorkingCopy ID、数据集 ID 和已发布记录 ID 确定目标，不单靠文件名。冻结当前 DocumentVersion、数据集 revision、文件 SHA-256、工作表名、目标行号及关键身份字段。若同名文件多于一份、行号无法唯一绑定、用户同时上传新 Excel 或版本已变化，停止并要求重新选择/checkout；不得猜测或写到另一份文件。

服务端仅读当前工作表的表头/布局指纹、目标数据行和相关公式区域；模板结构已有缓存时先比对指纹，不再把 Excel 交给 WorkBuddy 全表重提取。保留现有 Excel 每个非目标部件的哈希作为发布校验基线。

### 3.2 基于已存来源形成逐列差异草稿

以已保存的 `DocumentPage`、`DocumentElement`、`StructuredExtractionRun`、字段候选、source-unit/evidence 引用和专用 Skill 列来源图为输入，按“差异列优先”重算候选值。对仍一致的列不重新提取，只核对版本与规则。每列输出：当前值、建议值、操作类型、事实证据、审批证据、勾选判定和缺口状态。对人工样表中不同的 E/K/M/P/Q/X 等列，必须先判断是合法来源事实、误投列还是超出批准范围，不能机械清空。

如果当前持久化结果有该页的文本但缺少印章图像证据，仅对对应 PDF 页或印章 ROI 进行一次受控 WorkBuddy 视觉复核，并将页码、bbox、印章文字/形状、适用范围及来源版本关联保存。L 列优先检查最后一页的方形印章与优秀年度；O 列优先检查已映射的学生名单页及其续页，避免从全文重新检索。目标页证据依然不足时，该列保持不通过/待核，不得猜出 `√` 或伪造审批。只有来源版本哈希变化、缓存页缺失/损坏或路由不足以找到目标页时，才升级到更大范围的提取。

### 3.3 新增受控“修正已发布行”路径

在现有追加工具之外，增加独立的 correction checkout/preview/publish 能力（具体 API/MCP 名称在实现时统一命名），只允许修改冻结目标行的白名单数据格。不能简单放宽现有 `WRITEBACK_EXISTING_CELL_CHANGED` 校验，否则旧追加入口将失去保护。

修正请求携带稳定目标 ID、基线版本/哈希、目标行绑定、逐格 before/after、字段证据与预期变化摘要。服务端对候选工作簿做**差异白名单**校验：非目标格、公式、样式、合并、其他表、Office 包其余部件不变；目标格原值必须与冻结 before 一致；修正的非空值必须通过现行字段、来源与审批校验。清空也需明确原因和审计记录，不能借 correction 删除任意内容。

发布继续复用现有受控候选版本、数据库/可见文件一致性协调器和恢复机制。一个修正任务幂等键对应唯一候选版本；相同摘要重试不重复出版本，摘要变化或并发版本冲突返回明确错误。成功后生成新 `DocumentVersion`、数据集 revision、对应导出/当前版本指针、ChangeSet/ToolInvocation；工作副本只保留原有同名可见文件，旧内容留在历史版本中。数据集查询需投影修订后的最新值，不得仍返回旧 `StructuredExtractionRun` 原字段；旧提取事实保留为不可变证据，另记更正事件/记录版本及 before/after。

由于修正会覆盖已发布非空格，第一次修复当前错误行应给用户展示逐列 diff 并取得针对该目标版本的确认，然后发布。该确认只针对**更正既有数据**；专用 Skill 对新数据的既有“直接写入、无需人为复核”规则保持不变。若将来要让既有行修正也自动执行，需单独定义明确授权、可覆盖范围和回滚边界，不能从“新行直接保存”推导。

## 4. 提取结果复用与耗时控制

分层缓存：Excel 模板层复用工作表/表头/字段布局与当前 DocumentVersion；PDF 内容层复用同一 `DocumentVersion + SHA-256 + 提取器配置` 的页文本/元素；字段层复用经验证的 source unit 与审批映射。缓存命中时不触发 WorkBuddy 全文读取。仅对值不一致、证据不完整或政策变更影响的列重判，并按列来源图请求相应页。印章 ROI 结果也按来源页哈希、区域和识别策略版本缓存，但不能跨文件或跨版本复用审批结论。

性能验收记录各层的 `cache_hit`、重新读取页数、ROI 调用数、字段重判数和总耗时，不记录完整个人材料正文。典型“同版本修正”应为 0 次全表重提取、0 次全文 OCR；只对确有印章证据缺口的页做定向核验。缓存无效时可以增量补提，不能为了节省时间牺牲证据完整性。

## 5. 实施顺序和验收

1. **只读基线报告**：按目标行生成 A–AA 差异与证据缺口清单，核对人工样表、已保存 PDF 提取与当前 Excel；不写文件。先确定每个差异是内容选择、列映射、审批、文字表达、`√` 判定还是历史样表示例差异。
2. **纠错候选与服务端路径**：实现稳定行绑定、逐格 diff、修正事件/数据集投影、独立 correction 工具和严格包级差异校验。旧追加路径、旧导出及普通文件导入不改语义。
3. **专用 Skill 细化**：明确按列来源图和缓存优先、L 末页方章、O 多页名单、来源事实与审批结论分离、整列末尾单个 `√`、当前行修正的用户确认要求；不把人工样表的具体答案硬编码进 Skill。
4. **自动测试**：用脱敏/合成样表覆盖空值改写、非空值更正、清空、长名单、跨页、无明确项号、印章不可定位、无章事实、整列满足/不满足、版本冲突、重复 publish、下载一致、旧版回溯、其他格与公式不变。验证同一人员行数不增加，数据集查询与 Excel 值一致，缓存命中不触发全文 OCR。
5. **真实验收**：先在隔离副本验证；部署 API、worker、MCP/Skill 与迁移并重连 WorkBuddy 后，对当前行展示逐列修正预览，获确认再发布。逐格对照 PDF 证据、人工样表提示及 Skill 条件；核对服务器同名文件、文件列表、下载 SHA-256、DocumentVersion/数据集 revision 与历史版本。未通过任一检查不得宣称已修好，也不得通过再次追加来“修复”。

## 6. 需保留的既有能力与风险提示

- 无新 Excel 时按文件名继续追加、新上传 Excel 优先成为新目标的规则不变；此次更正只作用于已绑定的既有行。
- 人工样表可能包含人工判断或不同填报口径；差异只是复核线索。尤其空白列、年度优秀、未盖章项目和 `√` 不能仅凭样表自动复制。
- 项目已有发布安全加固设计；实施时要先核对实际运行版本和数据库迁移状态，再复用发布协调器，不能假设仅因代码存在就已在当前服务生效。
- 初版方案阶段没有修改当前服务器文件；本文件后续实施进度以第 7 节为准。
