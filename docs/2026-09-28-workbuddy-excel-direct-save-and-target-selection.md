# WorkBuddy Excel 直写与目标选择修订

日期：2026-09-28。本文修订 `2026-09-20-workbuddy-excel-target-continuation-spec.md`
中“显式提取成表默认先人工确认”的旧策略；目标、证据、版本和文件安全规则保持有效。

## 目标选择是互斥的

1. 本轮有新上传的目标 Excel：以该文件注册独立新数据集，读取它的当前工作表、标题、字段和既有内容，
   从本轮其他来源提取并写入**这个新文件**。即使提示词同时提到历史 Excel，也不得追加到历史文件。
   `.xls` 提升为 `.xlsx` 后或新上传 `.xlsx` 与一个已发布的活动目标同名时，先完整发布新表，再将旧目标的
   工作副本及受管文件标记为 `ARCHIVED`；旧数据集、版本和导出保留供按稳定 ID 查询、下载及后续受控恢复。
   当前文件列表和按文件名匹配只展示新表，旧表的数据不合并到新表。不得自动改名或覆盖旧目标的历史版本。
   同名对象不是已发布累计目标、存在多个活动同名目标、旧目标有正在发布的任务或新表发布失败时，停止切换；
   发布失败时旧目标保持 `ACTIVE`。
   归档使用现有工作副本和受管文件状态字段，不新增数据库列；新表发布期间标记为 `PUBLISHING`、冻结
   旧目标续写，发布状态恢复后才将新表置为 `ACTIVE`、旧表置为 `ARCHIVED`，并写入归档 ChangeItem。
   旧目标保留稳定 ID 的历史导出下载入口。
2. 本轮没有新上传的目标 Excel，且用户通过完整文件名指定已有表：精确解析现有工作副本，读取其当前字段，
   向同一文件追加新行并创建新 DocumentVersion。找不到或匹配多个目标时，请用户选择，不猜测。
3. 本轮既无新上传目标表、也未指定已有文件：根据提示词创建新 Excel，文件名使用用户指定值或生成可读名称。

新上传目标用 `uploaded_task_id` / `uploaded_document_id` / `uploaded` 绑定；按文件名续写用现有
`dataset_id` 和当前版本绑定。服务端必须继续校验稳定 Document ID、WorkingCopy ID、数据集 ID、SHA、
版本 CAS、表头和布局。工作副本、文件列表及下载文件名一致，历史由 DocumentVersion 管理。

### 上传提取结果与归档版本的绑定

`document_extraction_submit` 的 run 固定在上传暂存版本。归档创建新的 Document/DocumentVersion 时，
服务端复制该 run 的页面和单元格证据，并在当前工作副本版本的 `extraction_policy_json` 记录原上传版本
与原 run ID。WorkBuddy 可继续提交原 run ID；目标 Excel 校验只在以下条件同时成立时映射到当前版本的
复制 run：当前版本属于本轮指定的工作副本、受管文件明确引用该上传版本、两版本 SHA-256 相同、原 run
属于上传版本且已完成、当前版本的来源记录与原 run ID 一致、复制页面逐一引用原页面。随后只用当前版本
复制件校验 SHEET 覆盖和表头。映射缺失或不一致仍返回 `TARGET_EXCEL_EXTRACTION_INVALID`，不得回退到
同名历史 `.xlsx` 数据集；`document_extraction_resume` 不重绑 run，它只恢复归档流程。

## 确认策略

- Excel 新建、续写和已发布行的定向更正默认 `DIRECT_SAVE`：真实读取、证据校验、预览指纹登记和
  服务端发布依次完成，不等待人工逐文件/逐列/逐格确认。`preview` 是技术校验步骤，不等于用户复核。
- 用户本轮明确要求“先预览/复核/确认后保存”才使用 `REVIEW_REQUIRED`；此时展示完整候选，用户确认
  同一指纹后发布。已经冻结的模式不得因耗时或失败自行切换。
- 发现重复上传时必须暂停并让用户选择“继续上传／使用已有文件／取消上传”；直写授权不替代查重决定。
- 仅本轮上传新 Excel 与唯一已发布累计目标同名时执行上述归档替换。工作表歧义、目标版本冲突及其他
  同名歧义仍是防止写错文件的安全阻断；无法确定唯一目标时仍要询问，不可自动选择。
- 单独要求提取内容、但不要求新建或追加 Excel 的普通任务，继续按原有显式提取确认规则处理。

## 验收

1. 新上传模板与旧表同时出现时，新模板产生不同的 dataset/document 绑定，旧表版本和行数不变。
2. 无新模板、按完整文件名续写时，字段来自现有表，Document ID 和 WorkingCopy ID 不变，版本递增。
3. 默认 Excel 任务和定向更正无需 confirm 即能发布；显式 `REVIEW_REQUIRED` 未确认时不能发布。
4. 重复上传仍会等待用户明确选择；同名与目标歧义不得自动选择或覆盖。
5. 同名新上传目标发布中旧表保持活动但冻结续写；发布失败时旧表仍活动；成功后旧表归档、按文件名只命中
   新表，旧表历史导出仍可通过稳定 ID 下载。同一次请求键重试不得再次创建目标或归档其他表。
6. 传入上传暂存版 run ID 与归档后工作副本版本 ID 时，`.xls` 转换任务能够完成并发布到本轮新表；其他
   文件的 run ID 仍被拒绝，同名旧表不参与这次写入。
