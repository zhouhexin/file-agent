# 教师按工号查询资助金额与余额功能方案

## 独立服务实施决定（2026-11-05）

本功能单独部署为 `standalone/teacher-funding-portal`，不注册到 FileAgent 的 FastAPI、MCP、前端或 Docker Compose。按最新要求，复用 FileAgent 现有 PostgreSQL 数据库及数据库账号，只新增 `teacher_funding_` 前缀的表，不复用 FileAgent 原有业务表或用户账号。应用、依赖、管理员账号、进程和端口保持独立，既能本机 Python 启动，也能使用独立 Compose。

工号—姓名对应关系保存到现有 PostgreSQL 的 `teacher_funding_staff` 表，管理员在网页表格里新增、编辑和停用，不需要长期保存名单 Excel。余额表仍通过 FileAgent 现有只读 API 自动同步，查询服务只读写自己的前缀表，不直接读取或修改 FileAgent 原有业务表。启动时立即检查，以后默认每 60 秒按完整文件名获取新发布版本；失败时保留上一个有效快照并重试。

## 1. 目标

增加一个教师自助查询入口。教师注册并登录后，只能查看自己名下的资助信息：教师姓名、总科研成果资助金额、其他资助金额、总资助金额、总支出和当前余额。

教师工号与姓名的对应关系以用户提供的正式名单为准。系统不根据姓名相似度猜测身份，也不允许用户自行修改名单中的姓名。

本文件记录设计与当前实现边界。首版代码位于独立目录 `standalone/teacher-funding-portal`，启动和数据导入方式见该目录的 `README.md`。

## 2. 注册方式与身份边界

按当前确定的简化方式，教师直接使用工号注册，并自行设置登录密码。注册时系统检查工号是否在有效名单中，以及该工号是否已经注册；已注册时提示“该工号已注册”，不创建第二个账号。无需注册码，也不单独设置用户名，工号就是登录账号。

需要知道这个简化方式的边界：工号—姓名名单能确认工号对应的教师姓名，但不能证明注册者本人身份。知道他人工号的人可能先注册并查看对应资助信息。首版按需求采用工号注册，同时通过每工号只能注册一次、限制连续尝试次数、记录注册和登录审计来降低滥用；如果后续需要确认一定是本人，再接校园统一身份认证或其他校内核验方式。

## 3. 用户怎么使用

1. 教师打开注册页面，填写工号并设置密码。
2. 系统检查工号是否在当前有效名单中。名单中不存在时提示联系管理员核对名单。
3. 如果工号已经注册，页面提示“该工号已注册”，引导用户登录或联系管理员处理账号问题。
4. 如果工号尚未注册，系统创建账号，并将账号与名单中的教师记录绑定；页面显示对应姓名供用户核对。
5. 教师使用工号和密码登录。
6. 登录后进入“我的资助信息”页面。页面根据账号已绑定的工号找到名单中的姓名，再读取该教师的最新资助数据。
7. 教师只查看当前绑定教师的信息，不需要再次输入姓名，也不能在页面上切换成其他教师。

## 4. 名单如何进入系统

管理员登录后，在“教师工号—姓名表”里直接维护数据：

- 新增：填写工号和姓名，保存到本服务数据库；不自动创建教师账号或密码。
- 修改：在表格点击“编辑”修改姓名，工号作为固定标识；不会修改 FileAgent 中的教师名称或资助业务数据。
- 停用或重新启用：在编辑时切换状态，停用后不能注册、登录或查询。
- 表格显示工号、姓名、启停状态和是否注册，支持分页查看；只有管理员可以访问。
- 工号按文本保存，`001234` 的前导零不会丢失；空白工号、重复工号或与管理员账号冲突的工号不能新增。
- 修改姓名或启停状态时使原有登录失效，并记录修改前后内容、操作人和时间。已注册账号及历史记录保留。

教师注册和查询始终读取这张数据库表，不依赖名单 Excel 文件是否存在。名单保存后即可使用。

如需一次录入较多人，可选择上传工号—姓名 Excel。这个可选批量入口仍检查：

- 必须能识别“教师工号”和“姓名”两列；列标题允许通过管理页面明确指定。
- 工号和姓名都不能为空；工号按文本处理，保留前导零。
- 同一工号不能对应多个不同姓名；重复工号、空行和无效行会列出来供管理员处理。
- 不能静默覆盖当前名单。管理员确认导入后，系统保存名单版本、文件摘要、导入时间和导入人。
- 新名单生效后，旧名单版本保留审计记录。离职或不再允许查询的教师可以停用，停用后不能新注册，也不能继续查看。

网页表格保存或可选批量导入后，有效工号即可注册。管理员不为教师设置默认密码。

## 5. 查询哪些金额

查询页建议显示以下金额，避免“资助总额”口径不清：

| 页面名称 | 含义 |
|---|---|
| 总科研成果资助金额 | 余额表中的科研成果资助金额 |
| 其他资助金额 | 院优青、专委、其他资助金额合计 |
| 总资助金额 | 总科研成果资助金额 + 其他资助金额 |
| 总支出 | 已确认使用登记金额的合计 |
| 当前余额 | 总资助金额 - 总支出 |

教师可以展开查看自己名下的逐笔使用登记明细。字段与现有个人明细页保持一致：序号、使用登记原文、日期、确认使用金额、核对说明。待核对记录需要醒目标记，且不计入已确认总支出；如果存在待核对记录，余额区域显示“余额待核对”。没有登记记录时显示“暂无使用登记”。

如果现有数据中有待核对的使用记录，系统不能把它当作已确认支出，也不能显示一个看似准确的余额。页面应显示“余额待核对”，并说明存在待核对记录。缺少资助总额或支出信息时，对应金额显示“暂无可用数据”，不显示为 0 元。

## 6. 金额从哪里读取

查询以最近一次成功同步的正式“教师成果资助使用登记余额表” XLSX 快照为准。后台通过 FileAgent 只读 API 获取余额表，教师查询读取 PostgreSQL 前缀表中的快照和本人逐笔明细。

FileAgent 发布新版本后，后台在下一次检查时自动同步；同步完成后教师刷新页面即可看到新数字。页面显示本服务快照更新时间。查询服务对 FileAgent 只读，不会修改其 Excel、资助记录或余额。

当前余额表以教师姓名保存资助记录，而登录绑定使用工号。系统用“已验证工号对应的名单姓名”做精确匹配：

- 恰好匹配一位教师：显示该教师数据。
- 找不到该姓名：显示“暂未找到资助记录”，不改名单或业务数据。
- 余额表里出现多个同名教师：停止展示金额并提示管理员处理，不能随便选一条。
- 名单和余额表的姓名不一致：不做模糊匹配，提示管理员核对名单或余额表。

## 7. 账号与身份绑定规则

- 普通账号只绑定一个有效教师工号；工号本身作为唯一登录账号。
- 一个教师工号只能绑定一个账号，避免多人共享或重复认领。
- 用户不能自行更改已绑定工号、教师姓名或账号角色。
- 已注册工号不能重复注册。账号登录后可以在“账号安全”页面修改密码，修改时需要填写当前密码和两次一致的新密码。
- 忘记密码时，不能通过重新注册抢占已绑定工号；由管理员核验后重置密码，或以后接入学校统一身份认证后的自助恢复。
- 工号绑定错误时，由管理员核验后解除旧绑定并重新绑定；系统记录操作人、时间和变更前后信息。
- 管理员停用教师名单项时，该账号不能再查看资助数据；是否同时禁止登录其他 File Agent 功能，按账号是否还用于其他业务决定。建议本功能先只关闭资助查询权限，不影响已有账号的其他权限。

## 8. 页面大致样子

登录后的“我的资助信息”页只显示当前账号绑定教师的数据：

```text
姓名：张老师
工号：系统显示部分掩码，例如 *******1234

总科研成果资助金额：  xx,xxx.xx 元
其他资助金额：        x,xxx.xx 元
总资助金额：          xx,xxx.xx 元
总支出：              x,xxx.xx 元
当前余额：            xx,xxx.xx 元

数据更新时间：YYYY-MM-DD HH:mm
```

页面不提供“输入其他教师姓名/工号查询”的入口，也不显示其他教师列表、其他教师明细或完整工作簿下载链接。教师可以查看本人逐笔登记原文、日期、金额和核对说明；接口必须在服务端按当前登录账号绑定的工号和名单姓名过滤，不能依赖前端隐藏其他人的数据。

## 9. 程序需要增加什么

### 后端

- 增加数据库工号—姓名表的管理员查询、新增和修改入口；可选保留名单 Excel 批量导入及版本记录。
- 增加教师工号注册入口：仅接受名单内、尚未注册的工号；重复注册给出明确提示。
- 沿用现有密码哈希、登录和 JWT；新增修改密码入口，要求验证当前密码并校验新密码。
- 增加“查询我的资助信息”只读接口。接口从登录用户身份取得绑定工号，不接受客户端传入任意教师工号。
- 查询时同时返回该教师的汇总金额和逐笔登记明细，只返回必要字段和更新时间；不返回整份余额表、其他教师数据、内部文件路径或下载令牌。
- 明细只包含序号、使用登记原文、日期、确认使用金额及核对说明；该查询入口只读，不允许通过它修改、删除或新增登记。
- 对未绑定、名单已停用、无匹配记录、姓名冲突、余额待核对等情况返回清楚的状态。
- 记录注册、登录、绑定变更、密码修改/重置、管理员停用和资助信息查询等审计事件；日志不记录密码或其他教师金额。

### 数据库

预计需要新增数据结构保存：

1. 教师名单及名单版本：工号、姓名、是否有效、名单版本、来源文件摘要、导入人和导入时间。
2. 账号—教师绑定：用户 ID、教师名单项 ID、绑定时间、状态；工号和账号都要防止重复绑定。
3. 必要的操作审计：名单导入、注册、绑定修改、密码修改/重置和资助信息查询记录。

本服务使用 FileAgent 现有 PostgreSQL 的连接账号，首次启动创建自己的 `teacher_funding_` 前缀表，不新建数据库或数据库账号，不修改 FileAgent 原有表。名单和教师查询账号保存在新表中。旧 SQLite 文件仅作为已导入数据的迁移来源，正常服务不再使用它。工号按文本存储以保留前导零。

### 前端

- 添加注册页面的工号、密码和确认密码输入项；已注册时给出明确提示。
- 添加登录后的“我的资助信息”页面。
- 在资助金额下方添加可展开的“使用登记明细”，展示本人逐笔记录和核对状态。
- 添加登录后的修改密码页面。
- 添加管理员工号—姓名表格，支持新增、编辑、启停、分页及注册情况查看；Excel 批量导入放在可选展开区域。
- 所有状态使用中文说明；金额保留两位小数并显示“元”。

## 10. 首版建议范围

第一版建议只完成：

1. 管理员在数据库表格里维护工号—姓名对应关系，无需名单 Excel。
2. 教师使用工号注册、设置密码并登录。
3. 教师查看自己对应的资助总额、总支出和余额。
4. 教师登录后修改密码。
5. 管理员在此独立服务中更新名单并查看自动同步状态，停用名单项、处理错误绑定和密码重置。

首版不提供教师之间互查、个人明细导出或自行修改资助数据。这样可以先解决查询需求，同时把数据访问范围限制在“本人”。

1. 先确认工号名单模板和当前正式余额表的唯一数据来源。
2. 完成名单导入、工号唯一性及重复数据检查。
3. 完成工号注册、账号唯一绑定、登录和修改密码接口。
4. 完成只读查询接口、教师查询页面及管理员名单管理页面。
5. 用测试账号分别验证有效工号注册、未知工号注册拦截、已注册工号重复注册提示、修改密码、跨教师访问拦截、无资助记录、同名冲突、待核对余额和名单停用等情况。
6. 独立部署本服务并初始化管理员账号；配置 FileAgent 地址、访问令牌和余额表完整文件名，由管理员在工号—姓名表中录入教师，并确认首次同步成功，再开放教师注册。

## 12. 验收标准

- 名单中的工号能准确显示对应姓名；前导零不会丢失。
- 不在名单中的工号不能注册。
- 同一个工号不能被两个账号绑定；同一账号不能绑定多个教师。
- 已注册工号再次注册时明确提示已存在，不覆盖旧账号或密码。
- 登录用户能使用当前密码修改密码；错误的当前密码不能修改成功。
- 登录用户只能查询自己绑定的教师信息。即使手工改请求参数，也不能读取其他教师金额。
- 查询返回的金额与当前正式余额表一致，待核对时不伪造余额。
- 逐笔明细与本人当前正式余额表个人页一致；修改请求参数也不能读取其他教师的明细。
- FileAgent 发布新版本后，查询服务在配置的检查周期内发起同步；同步成功后教师刷新页面可读到金额和明细的新数据。
- 查询接口不修改任何业务数据，也不返回完整工作簿或其他教师信息。
- 管理员名单导入、绑定修正和密码重置都有可追溯记录。

## 13. 自动同步实施细节

1. 使用服务端配置的 FileAgent 地址及访问令牌，只调用完整文件名定位、工作副本元数据和下载三个 GET 接口，不创建 FileAgent 任务或新版本。
2. 文件名解析沿用 FileAgent 的正式发布检查。同名多份、发布未完成或目标无效时停止本次同步，不任取一份。
3. 以来源地址、数据集 ID、工作副本 ID 和版本 ID 共同标识来源版本。版本未变化时不下载、不重复创建快照。
4. 下载时校验文件 SHA-256，下载前后核对来源版本，防止发布过程中混读。读取金额和明细成功后，在 PostgreSQL 单个事务中保存并切换快照；写入失败会回滚。
5. 管理员页显示最近检查时间和同步成功/失败状态。网络、凭证、格式或发布问题都不会删除旧快照，后台按周期重试。访问令牌不写入数据库、不回传浏览器、不放入日志。
6. 开启自动同步时不允许手动余额表覆盖；关闭同步配置后才使用离线手动导入。工号名单仍由本服务独立维护，FileAgent 不访问本服务账号或数据库。
7. 配置与部署步骤见 `standalone/teacher-funding-portal/README.md`。FileAgent 无需修改代码或数据库；查询服务需要更新镜像并配置同步参数。默认每 60 秒检查并非实时推送，实际同步耗时还受网络、文件大小和发布状态影响。

## 14. 整体检查与修正（2026-11-05）

- 页面退出登录时清空管理员区域、金额和明细；忽略退出前尚未完成的旧请求。浏览器登录信息改用会话存储，业务响应禁止缓存。
- 注册和改密增加重复密码输入；改密、管理员重置密码、名单停用或教师对应姓名变更会使旧登录失效。注册码仍不启用，继续按已确认的工号注册方案执行。
- 限流按工号和请求来源共同计数，避免校园共用出口 IP 时多位教师共用一个注册额度；计数更新使用原子 SQL。
- Excel 使用每张表一次顺序读取，避免只读工作簿反复定位单元格造成耗时。读取固定第一张名单页、保留工号前导零、拒绝重复标题或无效工号。
- 非法金额、超过两位小数的金额、不能直接读取的金额公式均不能产生可信余额；待核对余额在后端返回空值。明细页损坏时停止导入，避免直接跳过导致明细消失。
- 自动同步遇到临时数据库故障后继续检查；教师可看到同步失败时使用的是旧快照。

本轮验证：21 项 Python/API/同步回归测试通过；页面退出和请求竞态检查通过；JavaScript 语法和 Compose 配置解析通过。所有功能测试使用临时数据和模拟 FileAgent 响应，没有对真实业务数据执行操作。容器镜像构建和真实 FileAgent 联调仍需在部署环境进行。
