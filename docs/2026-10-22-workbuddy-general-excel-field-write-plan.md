# WorkBuddy 通用字段填表简要方案

## 目标

用户既可以上传目标 Excel，让系统读取真实工作表和表头，也可以在提示词中列出要建立的字段。系统读取本轮材料或用户明确给出的字段值，按列填入 Excel；缺少的值留空。后续可按完整文件名继续追加，并发布可下载的新版本。

## 现有基础与缺口

- `file-agent-excel-writeback` 已支持上传模板或按完整文件名续写，并复用 `excel_writeback_checkout/apply/publish` 保存同名版本。来源 PDF、Word、图片和 Excel 的正式提取结果可以作为填表证据。
- `structured_dataset_create` 已能按字段清单创建累计表，但现有通用写回 Skill 没有把“提示词指定字段后建表、填表”串成明确流程。
- 现有 `TEMPLATE_ALL` 写回要求真实 Excel 布局和正式来源引文；提示词直接提供的值不能伪装成文档引文。需要为这种值增加受控的用户输入来源与服务端校验。

## 执行流程

1. **确定目标。** 本轮上传了目标 Excel，就以该文件的实际 Sheet、表头和数据区为准；没有上传目标、但给出已发布文件完整名称，就锁定当前版本并续写；两者都没有、但提示词列出字段时，按这些字段创建一张新的 `.xlsx`。提示词字段与已上传模板冲突时，展示差异，不擅自改表头。上传模板中夹在有标题列之间的无标题空列保留物理位置，始终留空；若该列已有数据，停止并要求明确其含义。
2. **取得值。** 从本轮附件的已归档提取结果读取所需区段，复用已读取内容；提示词直接给出的值单独标记为“用户提供”，绑定本轮消息和原文，不伪造 PDF/Excel 证据。无法确认的值留空并说明原因。
3. **整理展示。** 同一字段提取到多条独立信息时，各条保留自己的来源引用，在同一单元格按 `1. 内容`、`2. 内容` 逐行展示；一条信息不拆成新数据行。原文证据仍保存未加号的文本，服务端据经核验的条目生成编号，不能让模型通过改写原文来凑格式。只有一条时按原值展示。
4. **对照预览。** 按真实列名逐项展示“目标列—拟写值—来源—留空原因”，检查同名列、重复人员、数据类型和目标版本。首列已有“序号”或“编号”时，核对每条新增数据行的流水号；上传模板没有该列时保持原表头，不新增序号列。提示词新建表默认加入首列“序号”。只有名称或来源含糊时才请求选择。
5. **写入与发布。** 复用当前 Excel 写回和版本发布能力；一次任务写入本轮确认的记录。发布成功后返回文件名、Sheet、新增行号、版本和下载链接。后续用户下载修改再回传，继续使用现有人工回传流程。

## 开发范围

- 扩展通用 WorkBuddy Skill 的三种目标入口与路由，不改变教授表、教师引进表、成果资助表的专用规则。
- 提示词定义新表时，复用已有字段建表能力，并补齐到 Excel 写回/发布的衔接；不把提示词字段当作已有模板的物理列。
- 给提示词直接提供的字段值增加明确的用户输入来源类型和服务端校验；文档提取值继续按现有正式引文校验，两个来源不得混淆。
- 通用写回当前只在部分写入范围自动补 A 列序号；补齐通用路径对首列已有“序号/编号”的生成与服务端校验。用户已明确：上传模板没有序号列时不新增列，保持原表头。
- 补充三类验收：上传模板填表、提示词字段新建并填表、按完整文件名追加；另核对单元格内逐条编号、连续行序号、空值、表头冲突、版本冲突和同名歧义。

## 当前实现进度

现有上传模板/按文件名追加路径已补齐两项展示规则：多条正式来源片段经服务端核验后逐条编号并换行；目标首列已有“序号/编号”时，新增行由写入器自动续号，服务端发布时再次验证。没有序号列的上传模板保持原样。提示词定义新表、提示词直接给值仍在后续开发范围内。

上传模板及后续按文件名追加已支持保留无标题空列：服务端以物理列号给空白列一个仅供任务识别的保留标记，不写入 Excel 表头；字段结果使用 `TARGET_BLANK_COLUMN`，实际单元格保持空白，后续有标题列不移动。MCP 本机写入与服务端发布均拒绝向保留列写值。真实表头不得占用此保留标记；无标题列若已有数据，创建目标时会要求明确列含义。

## 2026-10-22 非标准教师表路由与跨行论文编号

《2026年度博士应聘情况统计表》实测为 23 列，论文题目位于 M 列，不能按标准教师引进考察样表的 A–T、J–L 论文布局处理。桥接主路由和两个写回 Skill 改为先核对目标真实表头：仅 A–T 二十列且 A 序号、E 姓名、I 教育经历、J–L 论文、M–O 项目、P 成果均同位时使用教师引进专用流程；其余教师招聘和博士应聘表进入通用写回。既有标准专用模板的字段映射、`teacher_render`、审批和发布步骤保持原有路径。

通用写回的 `numbered_items` 以一个 `fragment` 表示一篇论文或一条独立事项，允许该引文内部保留原文换行，不按物理行数推断条目数。API 和 MCP 仅放宽这一编号输入限制，仍要求至少两条非空片段、逐字原文校验，以及不能同时声明 `teacher_render`、审批或 OCR 待核对。提交前对普通论文题目列增加门禁：两条以上片段若没有 `numbered_items=true`，拒绝写回；专用模板已提供 `teacher_render` 时不进入该门禁。服务端仍按片段顺序机械生成序号，并验证候选工作簿展示值。一次读取来源、跨列复用；提交前核对物理列、空值、引文和编号，证据或格式错误即报告并停止试探性重试，仅目标版本真实变化时重新 checkout。

## 2026-10-28 通用论文资格筛选

以下是首次实现时的严格口径，已被文末“论文资格规则调整”替代；实施与验收以文末新口径为准。

通用 Excel 中的论文题目及相关列只收录已正式发表、且申请人本人或其博士生导师为第一作者的论文。博士生导师身份必须有申请人简历中的明确关系证据；只写“导师”、硕士导师或单纯“博导”头衔不够。投稿、小修、审稿、返修、录用待刊等未正式发表的文章排除。仅 DOI 或录用通知不能代替正式发表证据；不确定的篇目留空并在回执说明。以同一筛选结果依次填写题目、刊物、作者角色和收录等列，避免一篇在题目列被排除、在其他列又出现。

通用任务的论文题目列新增逐篇 `paper_checks`，与 `fragments` 按索引一一对应。每项提供申请人身份、第一作者、正式发表的原文引用；导师一作额外提供申请人与该导师的博士阶段关系引文。API/MCP 严格 schema 在提交前校验完整性，服务端再逐字核对引文、检查作者名与明确一作或作者列表首位的关系，并拦截引文中明显未发表的状态。语义仍需 WorkBuddy 对照同一篇论文的上下文判断；服务端不能仅靠正则证明所有复杂作者关系。此门禁只适用于通用任务，不改变已测试通过的教师引进专用模板。

## 2026-10-28 论文筛选改为提示词启用

用户本轮任务文字明确提出“一作 / 第一作者 / 导师一作”等论文资格时，通用任务在 `manifest.paper_filter` 设置 `FIRST_AUTHOR_PUBLISHED`，此时逐篇 `paper_checks` 为必填，仍按上述严格规则筛选正式发表论文。未提一作资格时不设置该标志，也不提交 `paper_checks`；原来的宽松论文读取、来源证据核对和多篇编号保持原样。附件正文或 Excel 表头出现“一作”不算用户授权启用严格规则。用户单独提出其他论文限制时仅执行其明确提出的限制，不自动附加一作门槛。API/MCP 契约同时执行这个开关，避免旧版通用任务被强制要求论文资格证据。

## 2026-10-28 无标题保留列空串兼容

实际 23 列模板的 B 列无标题且需留空。WorkBuddy 宿主有时把 `rows` 中的 JSON `null` 传成空串，原 MCP 写入器用 `value is not None` 判断，导致 `excel_writeback_apply` 在任何数据行都报 `TARGET_BLANK_COLUMN_CHANGED`。修复仅在标记为 `〔空白列:B〕` 等无标题保留列时，将空串或纯空白字符串还原成真正空值后再校验；有实际文字仍拒绝。其余列、行宽、字段证据和服务端发布校验不放宽。新增 23 列工作簿与 MCP `apply` 回归测试。

## 2026-10-28 论文资格规则调整

用户对通用填表中的一作筛选改为从宽的发表状态口径：只排除原文明确写小修或投稿中、在投、投递中、审稿中等投递中状态的论文；其余默认按已发表填写，不再要求正面发表证明、年份、卷期页或 DOI。因此 `paper_checks.publication_evidence` 改为可选，若提供仍校验其真实来源并检查排除状态；论文题目原文片段同样检查排除状态。旧载荷仍可携带该字段。

本人一作和明确标注“学生一作”的论文都按 `first_author_kind=APPLICANT` 处理，即使作者列表前面还有导师，也不进入导师身份校验。只有明确标注“导师一作”的论文才可设 `PHD_ADVISOR`；该情况下仍需证明第一作者姓名属于申请人的导师。简历只写“导师：姓名”且未将此人标为硕士导师时，按博士导师处理；明确写硕士导师的不得使用导师一作资格。服务端只机械校验引文及明确状态，WorkBuddy 仍需核对论文与引用的对应关系。

上述调整只作用于通用 Excel 中显式启用 `FIRST_AUTHOR_PUBLISHED` 的任务。未启用时保留宽松读取；教师引进等专用技能及其字段映射不改。API 与 MCP 的论文证据模型同步放宽可选状态引文，保持协议一致。测试覆盖 Early Access、仅刊名、学生一作、未标硕士的导师一作、明确硕士导师、投递中及旧载荷。

部署需同步更新服务端 API、MCP 0.1.8 与 WorkBuddy 套件 0.1.94；仅更新技能文本仍会被旧版 MCP 或服务端证据模型挡下。无需数据库迁移。

同轮实测还发现宿主把业务留空列的 JSON `null` 编成精确空串，写入器据此创建了空字符串单元格，发布端认为该格“已填内容”。MCP 写入器在所有列仅将精确空串还原为未填写；保留空列继续兼容空白字符，其它业务文本原样保留。这样不改变实际值或专用字段校验，只消除空值编码差异。回归测试覆盖 23 列模板中多个留空业务列。

原 PDF 提取文本可能用兼容汉字写出“学⽣⼀作”。服务端仅在作者与状态关键词的机械匹配时做 Unicode NFKC 归一，正式引文仍用原始字符逐字校验并保存；回归测试覆盖该原文形态。

多人导师列表按姓名所在的最近导师标记判定：例如“硕士导师：王五、李四；博士导师：赵六”，李四不得被误认作博士导师，赵六仍可收录；姓名后括注硕士导师也优先排除。
