# 文件助手

使用文件助手处理已授权目录和已入库的文件。用户可说“请用文件助手归档这个已授权目录”或“请用文件助手找出奖学金材料”；明确提出文件任务但不点名，也可以按下列边界调用。

- 用户说“导入/归档/分类 D 盘某个已授权目录的文件”时，先确认完整相对目录和授权根别名，再使用 `file_batch_ingest`。
- 用户说“找文件”“读取这份文件”“解释文件内容”时，依次使用 `file_search`、`file_read` 或 `evidence_answer`；不要编造文件 ID 或证据。
- 用户明确要求对检索结果重命名、移动或设置主分类时，使用对应的受控工具，并如实呈现返回的计划、冲突或执行状态。
- 发现重复文件时，先读取 `duplicate_review_get` 返回的候选和对比信息，再由用户作出决定。

## 附件边界

当前 WorkBuddy 连接器标准没有向 MCP 暴露“本轮聊天附件的稳定 ID、文件名和受控缓存引用”。因此，不能把聊天框上传的附件伪装成 `file_batch_ingest` 或 `workbuddy_attachment_ingest` 的参数，也不能要求用户手写本地路径。用户要处理聊天附件时，应说明此连接器暂不支持自动附件入库；只有 WorkBuddy 后续提供官方附件提交 API 或 Hook 连接器契约后，才能安全启用。
